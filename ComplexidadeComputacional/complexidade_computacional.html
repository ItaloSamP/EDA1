O que é complexidade computacional?

analogia do dia a dia

Imagine que você precisa encontrar um livro em uma biblioteca. Se você olhar prateleira por prateleira (busca linear), pode levar até N passos. Se a biblioteca organiza os livros em ordem alfabética (busca binária), você encontra em log₂(N) passos. A complexidade computacional mede exatamente isso: quantos passos um algoritmo precisa conforme a entrada cresce.

A complexidade computacional estuda quão rápido um algoritmo executa em função do tamanho da entrada (n). Não se trata do tempo em segundos (que depende do hardware), mas sim do número de operações elementares que o algoritmo realiza.

📌 Tempo de execução: número de operações elementares como função do tamanho da entrada n.

📌 Espaço de memória: quantidade de memória adicional necessária para executar o algoritmo.

Por que isso importa?

✔ Escolher o algoritmo certo pode fazer a diferença entre milissegundos e dias de processamento

✔ Permite comparar algoritmos independentemente de hardware ou linguagem

✔ É fundamental para projetar soluções escaláveis em problemas do mundo real

Análise assintótica — o comportamento para entradas grandes

A análise assintótica responde: "o que acontece com o tempo de execução quando n tende ao infinito?" Para valores pequenos de n, qualquer algoritmo é rápido. O que importa é como ele se comporta à medida que a entrada cresce.

Crescimento das funções típicas (n = tamanho da entrada): n | log n | n | n log n | n² | 2ⁿ ───────────────────────────────────────────────────────── 1 | 0 | 1 | 0 | 1 | 2 10 | 3 | 10 | 33 | 100 | 1.024 100 | 7 | 100 | 664 | 10.000 | 1,3e30 1.000 | 10 | 1.000 | 9.966 | 10⁶ | — inviável 10⁶ | 20 | 10⁶ | 2×10⁷ | 10¹² | — inviável ★ Para n = 1.000: n (1.000 ops) → µs n log n (10.000) → ms n² (1.000.000) → segundos 2ⁿ (imensurável)→ bilhões de anos

A análise assintótica ignora constantes e termos de menor ordem. 3n² + 5n + 100 é tratado como O(n²) — para n grande, o termo n² domina completamente.

Constantes importam na prática, mas a análise assintótica foca na taxa de crescimento. Um algoritmo O(n²) com constante pequena pode ser mais rápido que um O(n log n) com constante enorme para n pequeno — mas eventualmente o O(n log n) vence.
// 03

Notação Big O (O) — limite superior

A notação Big O descreve o pior caso (ou limite superior) de um algoritmo. Ela responde: "no máximo, quantos passos este algoritmo executa?"

analogia

Você está procurando uma pessoa em uma lista telefônica. No pior caso, a pessoa é a última da lista — você vai olhar todas as N entradas. A complexidade é O(n).

Definição formal

Dizemos que f(n) = O(g(n)) se existem constantes positivas c e n₀ tais que, para todo n ≥ n₀, vale 0 ≤ f(n) ≤ c·g(n).

Em outras palavras: a partir de um certo ponto n₀, f(n) nunca ultrapassa c·g(n).

f(n) = O(g(n)) ▲ │ c·g(n) │ ↗ │ ↗ f(n) │ ↗ ↗ │ ↗ ↗ │ ↗ ↗ │ ↗ ↗ └──────────────────────────▶ n n₀

Exemplos

f(n) = 3n + 2
/* 3n + 2 ≤ 4n para n ≥ 2         */
/* f(n) = O(n), c = 4, n₀ = 2     */
f(n) = n² + 10n
/* n² + 10n ≤ 2n² para n ≥ 10      */
/* f(n) = O(n²), c = 2, n₀ = 10   */
// 04

Notação Big Ω (Ω) — limite inferior

A notação Big Ω descreve o melhor caso (ou limite inferior) de um algoritmo. Ela responde: "no mínimo, quantos passos este algoritmo precisa executar?"

Definição formal

Dizemos que f(n) = Ω(g(n)) se existem constantes positivas c e n₀ tais que, para todo n ≥ n₀, vale 0 ≤ c·g(n) ≤ f(n).

f(n) = Ω(g(n)) ▲ │ f(n) │ ↗ │ ↗ c·g(n) │ ↗ ↗ │ ↗ ↗ │ ↗ ↗ │ ↗ ↗ └──────────────────────────▶ n n₀

Exemplo prático

Busca linear em um vetor: no melhor caso, o elemento está na primeira posição — Ω(1). No pior caso, está na última — O(n).

Big O e Big Ω podem ser diferentes para o mesmo algoritmo. É por isso que existe uma terceira notação.

// 05

Notação Big Θ (Θ) — limite justo

A notação Big Θ descreve o comportamento quando o limite superior e inferior coincidem — ou seja, a função cresce exatamente na mesma taxa para todos os casos.

Definição formal

Dizemos que f(n) = Θ(g(n)) se f(n) = O(g(n)) e f(n) = Ω(g(n)) simultaneamente. Existem constantes c₁, c₂, n₀ tais que c₁·g(n) ≤ f(n) ≤ c₂·g(n) para todo n ≥ n₀.

f(n) = Θ(g(n)) ▲ │ c₂·g(n) │ ↗ │ ↗ f(n) │ ↗ ↗ │ ↗ ↗ │ ↗ ↗ │↗ c₁·g(n) └──────────────────────────▶ n n₀
Θ(n) — acesso a vetor
/* Percorrer vetor de n elementos  */
for (int i = 0; i < n; i++)
    printf("%d\n", vet[i]);
/* Sempre faz exatamente n iterações
   → Θ(n)                            */
O(n²) mas Ω(1)
/* Busca em vetor desordenado      */
for (int i = 0; i < n; i++)
    if (vet[i] == alvo) break;
/* Melhor caso: Ω(1) (1º elemento)
   Pior caso:   O(n) (último)
   NÃO é Θ(n) — depende do caso!   */
Use Θ quando o algoritmo sempre executa o mesmo número de operações independentemente da entrada. Use O quando o pior caso é o que importa (é o mais comum na prática).
// 06

Hierarquia das complexidades mais comuns

As complexidades são ordenadas da mais eficiente para a menos eficiente:

O(1) ← constante (acesso a vetor: vet[i]) │ O(log n) ← logarítmica (busca binária) │ O(n) ← linear (busca sequencial) │ O(n log n) ← linearítmica (mergesort, quicksort médio) │ O(n²) ← quadrática (bubble sort, inserção direta) │ O(n³) ← cúbica (multiplicação de matrizes ingênua) │ O(2ⁿ) ← exponencial (Fibonacci ingênuo, subset sum) │ O(n!) ← fatorial (caixeiro viajante força bruta) ───────────────────────────────────────── Eficientes (polinomiais) ← O(1) a O(n^k) Ineficientes (exponenciais) ← O(2ⁿ) e O(n!)

Algoritmos polinomiais (O(1), O(log n), O(n), O(n log n), O(n²), etc.) são considerados eficientes ou tratáveis. Algoritmos exponenciais (O(2ⁿ), O(n!)) são intratáveis para valores grandes de n.

Cuidado: O(n²) pode ser aceitável para n pequeno (n ≤ 10³), mas inviável para n grande (n = 10⁶). Conhecer a complexidade ajuda a decidir se o algoritmo escala para o tamanho do problema.
// 07

Análise de algoritmos — exemplos práticos

Operações elementares

Para calcular a complexidade, contamos operações elementares: atribuições, comparações, operações aritméticas, acesso a vetor. Cada uma conta como O(1).

exemplo 1 — soma de elementos (O(n) → Θ(n))
int soma(int vet[], int n) {
    int total = 0;                 /* O(1) */
    for (int i = 0; i < n; i++)   /* n vezes: */
        total += vet[i];          /* O(1) cada */
    return total;                 /* O(1) */
}
/* Total: 1 + n*1 + 1 = n + 2 = O(n) = Θ(n) */
exemplo 2 — laços aninhados (O(n²))
void bubbleSort(int vet[], int n) {
    for (int i = 0; i < n - 1; i++) {      /* n-1 vezes */
        for (int j = 0; j < n - i - 1; j++) { /* ≈ n/2 médio */
            if (vet[j] > vet[j+1]) {
                int tmp = vet[j];
                vet[j] = vet[j+1];
                vet[j+1] = tmp;
            }
        }
    }
}
/* Soma: (n-1) * (n/2) ≈ n²/2 = O(n²) */
exemplo 3 — busca binária (O(log n))
int buscaBinaria(int vet[], int n, int alvo) {
    int esq = 0, dir = n - 1;
    while (esq <= dir) {                  /* a cada iteração: */
        int meio = (esq + dir) / 2;      /* O(1) */
        if (vet[meio] == alvo)
            return meio;                   /* O(1) */
        if (vet[meio] < alvo)
            esq = meio + 1;                /* descarta metade */
        else
            dir = meio - 1;                /* descarta metade */
    }
    return -1;
}
/* A cada iteração, o espaço de busca é dividido por 2.
   Número de iterações: log₂(n). Logo O(log n). */
exemplo 4 — Fibonacci ingênuo (O(2ⁿ))
int fib(int n) {
    if (n <= 1) return n;            /* caso base */
    return fib(n-1) + fib(n-2);   /* 2 chamadas recursivas */
}
/* Árvore de recursão: dobra a cada nível.
   T(n) = T(n-1) + T(n-2) + O(1)
   T(n) = O(2ⁿ)  — exponencial!

   Versão iterativa: O(n) — diferença brutal. */

Regras práticas para calcular complexidade

1

Laço simples de 1 a n

Um for de 0 a n-1 → O(n).

2

Laços aninhados

For dentro de for → multiplique: externo (n) × interno (n) = O(n²). Se o interno depende do externo, calcule a soma (ex: n + (n-1) + ... + 1 = n(n+1)/2 = O(n²)).

3

Divisão ao meio

Se o problema é dividido pela metade a cada passo → O(log n). Ex: busca binária, árvores balanceadas.

4

Divide and conquer

Divide em 2 metades (log n níveis) e faz O(n) trabalho por nível → O(n log n). Ex: mergesort, quicksort.

5

Recursão com múltiplas chamadas

Se uma chamada gera 2 ou mais subchamadas, a complexidade tende a ser exponencial O(2ⁿ) se não houver memoização.

Classes de complexidade — P, NP, NP-Completo

analogia

P são problemas fáceis de resolver (ex: ordenar uma lista). NP são problemas cuja solução é fácil de verificar, mas não necessariamente fácil de encontrar (ex: descobrir a senha de um cadeado — difícil de achar, mas se alguém te der a senha, você verifica em segundos). NP-Completo são os problemas mais difíceis dentro de NP.

Classe P (Polinomial)

Problemas que podem ser resolvidos em tempo polinomial O(n^k) por uma máquina determinística. São considerados "tratáveis" ou "eficientes".

Exemplos: ordenação, busca em vetor, caminho mínimo em grafo, árvore geradora mínima.

Classe NP (Nondeterministic Polynomial)

Problemas cuja solução pode ser verificada em tempo polinomial. Ou seja: se alguém te der uma resposta candidata, você confere se ela está correta rapidamente.

Exemplos: problema da mochila, SAT (satisfabilidade booleana), caixeiro viajante (versão decisão).

Todo problema P está em NP (se é fácil resolver, também é fácil verificar). A grande questão em aberto da Ciência da Computação: P = NP? — isto é, todo problema cuja solução é fácil de verificar também é fácil de resolver?

NP-Completo — os problemas mais difíceis de NP

Um problema X é NP-Completo se:

1. X está em NP (a solução é verificável em tempo polinomial)

2. X é NP-difícil: todo problema em NP pode ser reduzido a X em tempo polinomial

A consequência prática: se alguém encontrar um algoritmo polinomial para um problema NP-Completo, então todos os problemas em NP teriam solução polinomial (P = NP). Por isso, acredita-se que problemas NP-Completos não têm solução polinomial.

Relação entre as classes: ┌──────────────────────────────┐ │ NP │ │ ┌──────────────────────┐ │ │ │ P (polinomiais) │ │ │ │ ordenação, busca, │ │ │ │ caminho mínimo, etc │ │ │ └──────────────────────┘ │ │ ┌──────────────────────┐ │ │ │ NP-Completo │ │ │ │ SAT, mochila, │ │ │ │ caixeiro viajante │ │ │ └──────────────────────┘ │ └──────────────────────────────┘ Se P = NP: os dois círculos internos se fundem. (A maioria dos cientistas acredita que P ≠ NP.)

Exemplos de problemas NP-Completos clássicos

ProblemaDescrição
SATDada uma fórmula booleana, existe uma atribuição de variáveis que a torna verdadeira?
Problema da MochilaDado um conjunto de itens com peso e valor, existe um subconjunto com peso ≤ capacidade e valor ≥ alvo?
Caixeiro Viajante (decisão)Existe um roteiro que visita todas as cidades com distância total ≤ K?
CliqueDado um grafo, existe um subgrafo completo de tamanho K?
Coloração de GrafosDado um grafo, é possível colorir os vértices com K cores sem que adjacentes compartilhem a mesma cor?
Para problemas NP-Completos, não se busca solução ótima exata para entradas grandes. Usam-se heurísticas, algoritmos aproximados ou programação dinâmica para casos especiais.

Exercícios de fixação

Quiz rápido

1. Qual a complexidade de um laço que percorre um vetor de n elementos uma única vez?

✔ Correto! Um único for de 0 a n-1 executa n iterações → O(n).
✘ Um laço simples de n iterações é O(n). Relembre: cada iteração é O(1), e são n iterações.

2. O que significa dizer que um algoritmo é O(n²)?

✔ Exato! Big O é um limite superior assintótico: para n grande, f(n) ≤ c·n².
✘ Big O é limite superior, não valor exato. 3n² + 5n + 100 também é O(n²) — ignoramos constantes e termos menores.

3. Qual a complexidade da busca binária em um vetor ordenado de n elementos?

✔ Correto! A cada iteração, o espaço de busca é dividido por 2 → log₂(n) iterações.
✘ A busca binária descarta metade do vetor a cada passo. log₂(1.000) ≈ 10, log₂(10⁶) ≈ 20. É O(log n).

4. Qual a diferença entre as classes P e NP?

✔ Correto! P = polinomial para resolver. NP = polinomial para verificar. Sabe-se que P ⊆ NP, mas P = NP? é a grande questão em aberto.
✘ P = fácil de resolver (ordenar). NP = fácil de verificar (mochila). Todo P está em NP, mas a recíproca é o problema do milênio.

5. Qual a complexidade de for(i=0; i<n; i++) for(j=0; j<n; j++) soma++;?

✔ Correto! Laço externo executa n vezes, interno n vezes cada → n × n = n² iterações.
✘ São dois laços aninhados independentes: externo n, interno n → n × n = n² = O(n²).

6. Um problema é dito NP-Completo quando:

✔ Correto! NP-Completo = em NP + NP-difícil (todo NP se reduz a ele). Se qualquer NP-Completo tiver solução polinomial, então P = NP.
✘ NP-Completo exige duas propriedades: (1) estar em NP, (2) ser NP-difícil — todo problema de NP se reduz a ele.

Desafios para programar

Desafio 1 — Contar operações
Implemente os algoritmos de bubble sort, busca binária e Fibonacci ingênuo. Para cada um, adicione um contador de operações e execute com n = 10, 100, 1000. Os resultados batem com a complexidade teórica?

Desafio 2 — Comparar crescimento
Escreva um programa que gere uma tabela comparando n, log n, n log n, n², n³ e 2ⁿ para n = 1 até 20. Observe como 2ⁿ explode rapidamente. Qual o maior n para o qual 2ⁿ é viável?

Desafio 3 — Redução polinomial
Pesquise como o problema SAT pode ser reduzido ao problema da mochila (knapsack). (A redução não precisa ser implementada — apenas compreenda a lógica conceitual.)

Desafio 4 — Qual a complexidade?
Dado o código abaixo, determine a complexidade assintótica. Justifique.
for (i = 0; i < n; i++)
  for (j = i + 1; j < n; j++)
    printf("%d %d\n", i, j);
