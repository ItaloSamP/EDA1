// 01

O que complexidade mede de verdade

Complexidade computacional mede como o tempo de execução cresce em função do tamanho da entrada. Não mede segundos — mede crescimento. Um algoritmo O(n²) não é "lento"; ele é "para uma entrada 10x maior, fica 100x mais lento".

O tamanho da entrada (n): depende do problema. Para um vetor: n é o número de elementos. Para uma string: n é o comprimento. Para um grafo: pode ser o número de vértices e/ou arestas. A complexidade é sempre expressa em função de n.

Operação dominante: em vez de contar cada instrução de máquina, identifica-se a operação que cresce mais rápido e domina o custo total. Em uma busca, a comparação de elementos. Em ordenação, as trocas ou comparações.

Constantes são ignoradas no Big-O

Se um algoritmo faz 5n comparações, ainda é O(n). Se faz 3n² + 7n + 42, ainda é O(n²). O Big-O descreve o comportamento assintótico — o que acontece quando n cresce muito. Constantes ficam irrelevantes. Apenas o termo de maior ordem importa.

// 02

Notações: O, Ω e Θ

O (Big-O) — limite superior: f(n) é O(g(n)) se f cresce no máximo tão rápido quanto g para n suficientemente grande. É o "pior caso" da complexidade. "No máximo faz isso."

Exemplo: busca binária é O(log n) — no pior caso, faz log₂n iterações.

Ω (Omega) — limite inferior: f(n) é Ω(g(n)) se f cresce pelo menos tão rápido quanto g. É o melhor caso. "No mínimo faz isso."

Exemplo: busca binária é Ω(1) — no melhor caso, acerta na primeira comparação.

Θ (Theta) — limite exato: f(n) é Θ(g(n)) se f cresce exatamente tão rápido quanto g (por cima e por baixo). Isso significa O(g(n)) E Ω(g(n)) ao mesmo tempo.

Exemplo: Selection Sort é Θ(n²) — melhor e pior caso são ambos O(n²).

Na prova, quando usar qual notação

Se a questão perguntar "complexidade no pior caso" → use O. Se perguntar "complexidade" sem especificar → use O (padrão). Se perguntar "melhor caso" → use Ω ou diga O(1), O(n), etc. dependendo do algoritmo.

// 03

Como contar operações em código

O método: identifique o que acontece em cada instrução e some os custos. Para loops, multiplique o custo do corpo pelo número de iterações.

Regras básicas

  • Sequência de instruções: some os custos → O(f) + O(g) = O(max(f,g))
  • if/else: custo do if = max(custo do then, custo do else) no pior caso
  • Loop: custo do loop = número de iterações × custo do corpo
  • Loops aninhados: multiplique os custos de cada nível
  • Chamada de função: substitua pelo custo da função chamada

Analisando loops um por um

caso 1 — loop simples
for (int i = 0; i < n; i++) {   // executa n vezes
    operacao();                   // custo O(1)
}
// Total: n × O(1) = O(n)
caso 2 — loops aninhados dependentes
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {    // n iterações
        operacao();                   // O(1)
    }
}
// Total: n × n × O(1) = O(n²)
caso 3 — loop interno vai de 0 a i
for (int i = 0; i < n; i++) {
    for (int j = 0; j < i; j++) {    // i iterações (não n!)
        operacao();
    }
}
// i=0: 0 iters. i=1: 1. i=2: 2. ... i=n-1: n-1
// Total: 0+1+2+...+(n-1) = n(n-1)/2 = O(n²)
caso 4 — loop com divisão (logarítmico)
for (int i = 1; i <= n; i = i * 2) {   // i dobra a cada passo
    operacao();
}
// i=1,2,4,8,...,n → log₂(n) iterações = O(log n)
caso 5 — loop com n/2 iterações
for (int i = 0; i < n / 2; i++) {   // n/2 iterações
    operacao();
}
// n/2 = (1/2)n → O(n)   ← constante 1/2 é ignorada!
n/2 ainda é O(n)

Muita gente pensa que n/2 iterações resulta em O(n/2) ou O(n²/2). Não. A constante 1/2 é descartada: O(n/2) = O(n). Para virar O(log n), o índice precisa multiplicar ou dividir a cada iteração, não somar/subtrair.

Recursão e recorrências

Para funções recursivas, a complexidade é expressa por uma relação de recorrência T(n) e depois resolvida.

Recorrências importantes — memorize

T(n) = T(n-1) + O(1) → O(n)

Reduz o problema em 1 a cada chamada, faz O(1) extra. Exemplo: fatorial, impressão de lista encadeada.

int fat(int n) {
    if (n == 0) return 1;
    return n * fat(n - 1);   // T(n) = T(n-1) + O(1)
}

T(n) = T(n/2) + O(1) → O(log n)

Reduz o problema à metade a cada chamada, faz O(1) extra. Exemplo: busca binária recursiva.

// Busca binária: descarta metade a cada chamada
// T(n) = T(n/2) + O(1) → O(log n)

T(n) = 2T(n/2) + O(n) → O(n log n)

Faz 2 chamadas com metade do tamanho, mais O(n) de trabalho. Exemplo: Merge Sort.

T(n) = T(n-1) + O(n) → O(n²)

Reduz o problema em 1 mas faz O(n) extra a cada nível. Exemplo: Selection Sort recursivo, QuickSort pior caso.

T(n) = 2T(n-1) + O(1) → O(2ⁿ)

Duplica o número de chamadas a cada nível. Exemplo: Fibonacci recursivo ingênuo. MUITO lento.

Como verificar pela substituição

verificando T(n) = T(n-1) + 1 → O(n)
T(n) = T(n-1) + 1 = T(n-2) + 1 + 1 = T(n-2) + 2 = T(n-3) + 3 ... = T(n-k) + k Quando k = n: T(0) + n = 1 + n = O(n) ✓
verificando T(n) = T(n/2) + 1 → O(log n)
T(n) = T(n/2) + 1 = T(n/4) + 1 + 1 = T(n/4) + 2 = T(n/8) + 3 ... = T(n/2^k) + k Quando n/2^k = 1, ou seja k = log₂(n): T(1) + log₂n = O(log n) ✓
// 06

Casos: melhor, médio e pior

Melhor caso (best case): a entrada que resulta no menor número de operações. Exemplo: busca sequencial com o elemento na posição 0 → 1 comparação.

Pior caso (worst case): a entrada que resulta no maior número de operações. O que queremos limitar com Big-O. Exemplo: busca sequencial com elemento ausente → n comparações.

Caso médio (average case): o comportamento esperado para uma entrada aleatória. Geralmente requer análise probabilística. Em busca sequencial: em média, percorre n/2 elementos.

Quando o melhor caso parece bom mas o pior é ruim

O Insertion Sort tem melhor caso O(n) (vetor já ordenado) mas pior caso O(n²) (vetor invertido). Quando a questão perguntar a complexidade sem especificar, assuma pior caso. Se pedir especificamente melhor caso, responda O(n).

// 08

Pegadinhas da prova — complexidade

⚠ pegadinha #1 — n/2 não é O(n/2), é O(n)

Um loop que vai de 0 a n/2 tem n/2 iterações. Mas O(n/2) = O(n) porque constantes são ignoradas. Só vira O(log n) se o índice multiplicar ou dividir.

⚠ pegadinha #2 — loop interno de 0 a i é O(n²)
for (i=0; i<n; i++)
    for (j=0; j<i; j++)  // j vai de 0 até i-1
        op();
// Parece O(n × n/2) = O(n²/2)... e é O(n²). A /2 some.
⚠ pegadinha #3 — custo total é o maior, não a soma

Se um algoritmo faz uma parte O(n) e depois uma parte O(n²):

// Parte 1: O(n)
for (i=0; i<n; i++) op1();
// Parte 2: O(n²)
for (i=0; i<n; i++)
    for (j=0; j<n; j++) op2();
// Total: O(n) + O(n²) = O(n²)  ← o maior domina
⚠ pegadinha #4 — chamada de função dentro do loop multiplica
for (i=0; i<n; i++)       // n iterações
    buscaSeq(v, n, i);    // cada busca é O(n)
// Total: O(n) × O(n) = O(n²)  ← não O(n) + O(n)!
⚠ pegadinha #5 — O(log n) não é O(n/log n)

Algumas questões tentam confundir com "o algoritmo divide por 2 a cada passo, então é n/2 + n/4 + ... = n". Isso vale para algumas somas, mas o número de iterações de um loop que divide por 2 é log₂(n), não n.

⚠ pegadinha #6 — selection sort: todos os casos são O(n²)

O Selection Sort não tem melhor caso melhor que O(n²). Ele sempre percorre o vetor inteiro buscando o mínimo, independente de quão ordenado o vetor está. Isso é diferente do Insertion Sort que tem melhor caso O(n).

⚠ pegadinha #7 — merge sort pior caso é O(n log n), não O(n²)

O Merge Sort garante O(n log n) em todos os casos — melhor, médio e pior. Isso o diferencia do QuickSort que tem pior caso O(n²). Se a questão perguntar qual algoritmo garante O(n log n) no pior caso, é o Merge Sort.

// 09

Questões no estilo da prova

Analise e determine a complexidade

Q1. Qual a complexidade do trecho abaixo?

for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j += n)
        printf("%d %d\n", i, j);
✔ Loop externo: n iterações. Loop interno: j começa em 0 e incrementa n a cada passo. j=0 → j+=n → j=n → j<n? Falso. Loop interno executa apenas 1 vez! Total: n × 1 = O(n).
✘ O loop interno faz j+=n, não j++. Com j=0 e n>=1: j=0 (executa), j+=n→j=n, j<n falso. Apenas 1 iteração por loop externo. O(n) total.

Q2. Qual a recorrência e complexidade de:

int f(int n) {
    if (n <= 1) return n;
    return f(n-1) + f(n-1);
}
✔ f(n) chama f(n-1) DUAS vezes. T(n) = 2T(n-1) + O(1). Expandindo: 2T(n-1) = 2(2T(n-2)) = 4T(n-2) = ... = 2^k T(n-k). Quando k=n: 2^n T(0) = O(2^n). Exponencial!
✘ Duas chamadas a f(n-1): T(n)=2T(n-1)+O(1). Isso expande para O(2ⁿ). Duas chamadas = exponencial.

Q3. Um loop for com i = n; i >= 1; i /= 2 tem complexidade:

✔ i começa em n e divide por 2 a cada passo: n → n/2 → n/4 → ... → 1. Número de passos = log₂(n). Qualquer loop que multiplica ou divide o índice por constante é O(log n).
✘ i divide por 2 a cada passo → log₂(n) iterações → O(log n). Divisão/multiplicação do índice é sempre O(log n).

Q4. Qual a complexidade de busca linear em vetor já ordenado, buscando elemento que existe no final?

✔ A busca sequencial, mesmo em vetor ordenado, é O(n) no pior caso. Se o elemento está no final, percorre n-1 comparações antes de achá-lo. A ordenação só melhora quando o elemento NÃO existe (break antecipado) — mas o pior caso continua O(n).
✘ Busca sequencial ordenada: pior caso ainda é O(n). A ordenação melhora o caso de ausência (break antecipado), mas não o caso de presença no final.

Q5. O trecho abaixo tem qual complexidade?

for (int i = 0; i < n; i++) {
    for (int j = i; j < n; j++) {
        op();
    }
}
✔ i=0: loop interno vai de 0 a n-1 → n iters. i=1: j de 1 a n-1 → n-1 iters. ... i=n-1: j de n-1 a n-1 → 1 iter. Total: n+(n-1)+...+1 = n(n+1)/2 = O(n²).
✘ Somatório de n + (n-1) + ... + 1 = n(n+1)/2. Isso é O(n²), não O(n). O fato do j começar em i não muda a classe de complexidade.

Q6. O trecho abaixo processa a matrícula 232037937. Qual sua complexidade em função do valor de entrada m, e quantas vezes op() é chamada para m=232037937?

void f(int m) {
    while (m > 0) {
        op();
        m /= 10;
    }
}
✔ m /= 10 divide por 10 a cada passo: 232037937→23203793→2320379→232037→23203→2320→232→23→2→0 = 9 chamadas. Generalizado: se m tem d dígitos, executa d = ⌊log₁₀(m)⌋+1 vezes → O(log m). É análogo ao loop i*=2 que dá O(log n) — qualquer divisão por constante é logarítmica.
✘ m /= 10 reduz o problema multiplicativamente. Para m=232037937 (9 dígitos): 9 iterações. Complexidade: O(log m).

Q7. O Selection Sort aplicado ao vetor de 9 dígitos da matrícula 232037937 faz n(n-1)/2 comparações. Calcule o valor exato e classifique a complexidade.

✔ n(n-1)/2 = 9×8/2 = 36. O loop externo faz smallerIndex(ini=0): 8 comp, ini=1: 7 comp, ..., ini=7: 1 comp, ini=8: 0 comp. Total = 8+7+6+5+4+3+2+1+0 = 36. Complexidade: O(n²) — independente dos valores, sempre 36 comparações para n=9.
✘ n(n-1)/2 = 9×8/2 = 36 comparações. Não confunda com n² = 81 (seria se o loop interno fosse até n, não até i).

Q8. O trecho abaixo busca cada dígito da matrícula 232037937 usando busca binária. Se n é o tamanho do vetor e os dígitos têm 9 elementos, qual a complexidade total?

int digitos[] = {2,3,2,0,3,7,9,3,7};
for (int i = 0; i < 9; i++)
    buscaBinaria(v, n, digitos[i]);  // cada chamada: O(log n)
✔ Regra: chamada de função dentro de loop multiplica os custos. Loop externo: 9 iterações (constante aqui, mas O(n) se fosse variável). Busca binária: O(log n). Total: O(9 × log n) = O(log n) com 9 fixo. Mas se o problema fosse geral com n dígitos buscando num vetor de tamanho n: O(n × log n) = O(n log n). Esta é a complexidade do HeapSort e MergeSort.
✘ Chamada de função dentro de loop multiplica: 9 × O(log n) = O(9 log n). Como 9 é constante aqui: O(log n). Se fosse n dígitos: O(n log n).

Q9. Qual a diferença prática entre O(n²) e O(n log n) para n=9 (dígitos da matrícula 232037937) e para n=1.000.000?

✔ n=9: O(n²)≈81, O(n log n)≈9×3=27 — razão de 3×, pouco perceptível. n=1.000.000: O(n²)=10¹² (horas), O(n log n)≈20.000.000 (milissegundos). Big-O importa para entradas grandes — para n=9 qualquer algoritmo é "rápido". É por isso que o Selection Sort (O(n²)) é aceitável em listas pequenas como a matrícula.
✘ Para n=9: 81 vs ~27 operações — diferença pequena. Para n=1M: 10¹² vs 20M — diferença de 50.000×. Big-O importa em grande escala.

Q10. O trecho abaixo usa os dígitos da matrícula 232037937. Qual a complexidade — cuidado com a pegadinha no loop interno!

int v[] = {2,3,2,0,3,7,9,3,7};
for (int i = 0; i < 9; i++)
    for (int j = 0; j < 9; j += 9)
        printf("%d %d\n", v[i], v[j]);
✔ Loop interno: j começa em 0 e incrementa 9 a cada passo. j=0 (executa), j+=9 → j=9, j<9? Falso → para. Apenas 1 iteração por loop externo! Total: 9×1 = O(n). Dois loops aninhados não implicam automaticamente O(n²) — depende de como o índice avança. Com j+=n (passo = n), o interno é O(1).
✘ j+=9 com limite j<9: j=0 executa, j=9 não entra. 1 iteração interna por iteração externa. Total O(n), não O(n²).
