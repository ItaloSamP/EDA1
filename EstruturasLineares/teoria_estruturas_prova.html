// 01

O que a prova testa em estruturas lineares

As questões de estruturas lineares geralmente caem em três categorias:

  1. Trace de operações: dado código que insere/remove elementos de uma lista, qual o estado final? Qual a saída de um percorrimento?
  2. Ponteiros: dado código que manipula ponteiros de nós, o que acontece? Qual nó fica "órfão"? O que `*l` aponta?
  3. Complexidade: qual a complexidade de inserir no início/meio/fim de cada tipo de lista?
Cuidado especial com ponteiros

A prova adora questões onde um ponteiro deixa de ser atualizado na ordem certa, causando perda de referência. Sempre rastreie o estado de todos os ponteiros após cada linha de atribuição. Um ponteiro "perdido" é um nó que não pode mais ser acessado.

// 02

Lista sequencial — inserção e remoção com deslocamento

Armazena elementos em um vetor. O acesso é O(1) por índice, mas inserção e remoção no meio exigem deslocar elementos.

estrutura
#define MAX 100          // capacidade máxima fixa do vetor (constante)
typedef struct {              // define um novo tipo composto chamado Lista
    int v[MAX];               // vetor que guarda os elementos (sempre tem MAX posições)
    int n;       // número de elementos atualmente na lista (0 a MAX)
} Lista;                    // agora "Lista" pode ser usado como tipo

n é o número de elementos, não o tamanho do vetor. O vetor tem MAX posições, mas apenas as posições 0 a n-1 estão ocupadas. Inserir no final: coloca em v[n] e incrementa n. Remover do final: decrementa n.

Inserção na posição p — como o deslocamento funciona

inserção na posição p
int inserir(Lista *l, int x, int p) {   // l=ponteiro p/ lista, x=valor, p=posição
    if (l->n == MAX || p < 0 || p > l->n) return 0;   // cheia OU posição inválida → falha (retorna 0)
    for (int i = l->n; i > p; i--)    // começa no fim (i=n) e desce até p+1: desloca de trás p/ frente
        l->v[i] = l->v[i - 1];      // copia cada elemento uma casa p/ a direita, abrindo espaço
    l->v[p] = x;                    // coloca o novo valor no buraco aberto na posição p
    l->n++;                         // agora há um elemento a mais
    return 1;                    // sucesso
}

Por que deslocar de trás para frente (i começa em n, vai até p)? Se deslocasse de frente para trás, o elemento em p+1 seria sobrescrito pelo elemento em p antes de ser salvo. Deslocando de trás: salva o maior índice primeiro, liberando espaço para o próximo deslocamento.

inserir(l, 25, 2) em [10, 20, 30, 40], n=4
Antes: [10, 20, 30, 40, ?, ?], n=4, inserindo 25 na posição 2 i=4: v[4] = v[3] = 40 → [10, 20, 30, 40, 40, ?] i=3: v[3] = v[2] = 30 → [10, 20, 30, 30, 40, ?] i=2: i > p(2)? Não, para. Espera! i > p é condição do loop. i=2, p=2: 2 > 2? Falso → para. v[2] = 25 → [10, 20, 25, 30, 40, ?] n++ → n=5 Após: [10, 20, 25, 30, 40], n=5 ✓

Remoção na posição p

remoção na posição p
int remover(Lista *l, int p) {        // remove o elemento que está na posição p
    if (p < 0 || p >= l->n) return 0;   // posição inválida (não existe) → falha
    for (int i = p; i < l->n - 1; i++)   // começa em p e vai até o penúltimo: desloca de frente p/ trás
        l->v[i] = l->v[i + 1];      // puxa cada elemento uma casa p/ a esquerda, cobrindo o removido
    l->n--;                         // agora há um elemento a menos
    return 1;                    // sucesso
}

Remoção: deslocamento de frente para trás. Para remover posição p: copia v[p+1] para v[p], v[p+2] para v[p+1], etc. O loop vai de p até n-2 (não n-1, pois i+1 chegaria a n-1, o último elemento válido).

remover(l, 1) em [10, 20, 30, 40], n=4
Removendo posição 1 (valor 20): i=1: v[1] = v[2] = 30 → [10, 30, 30, 40] i=2: v[2] = v[3] = 40 → [10, 30, 40, 40] i=3: i < n-1 = 3? Não → para n-- → n=3 Resultado: [10, 30, 40], n=3 ✓
// 03

Lista simplesmente encadeada — ponteiros linha a linha

Nós alocados dinamicamente, cada um com um campo info (dado) e um campo prox (ponteiro para o próximo nó). A lista é referenciada por um ponteiro para o primeiro nó (inicio). O último nó tem prox = NULL.

estrutura do nó
typedef struct no {        // "struct no" precisa de nome p/ poder se referenciar
    int          info;        // o dado guardado no nó
    struct no *prox;        // ponteiro p/ o próximo nó (NULL se for o último)
} No;                       // apelido curto: "No" em vez de "struct no"
Representação visual: inicio → [10|→] → [20|→] → [30|→] → [40|NULL] Cada nó: [info | prox] O último nó sempre tem prox = NULL.

Inserção no início — trace de ponteiros

inserirInicio
void inserirInicio(No **l, int valor) {   // **l: ponteiro p/ o ponteiro "inicio" (permite alterá-lo)
    No *novo = (No*) malloc(sizeof(No));   // reserva memória p/ 1 nó; (No*) converte o tipo
    novo->info = valor;  // grava o dado no nó recém-criado
    novo->prox = *l;    // novo aponta para o primeiro atual (*l = inicio)
    *l = novo;           // atualiza o início para o novo (escreve na variável da main)
}
inserirInicio(&inicio, 5) — lista: [10]→[20]→NULL
Estado inicial: inicio → [10|→] → [20|NULL] 1. novo = malloc(...) → cria nó [?|?] 2. novo->info = 5 → nó fica [5|?] 3. novo->prox = *l → *l é inicio, que aponta para [10|...] novo fica [5|→[10|→[20|NULL]]] 4. *l = novo → inicio agora aponta para o novo nó Estado final: inicio → [5|→] → [10|→] → [20|NULL] ✓ ORDEM IMPORTA: se fizéssemos '*l = novo' ANTES de 'novo->prox = *l', perderíamos a referência para a lista antiga!

Inserção no final

inserirFim — percorre até o último nó
void inserirFim(No **l, int valor) {   // insere no final da lista
    No *novo = (No*) malloc(sizeof(No));   // cria o novo nó
    novo->info = valor;         // grava o dado
    novo->prox = NULL;          // será o último, então aponta p/ NULL
    if (*l == NULL) {         // lista vazia: não há para onde caminhar
        *l = novo;              // o novo nó vira o próprio início
        return;                 // encerra a função aqui
    }
    No *atu = *l;               // "atu" (atual) começa no primeiro nó
    while (atu->prox != NULL)  // enquanto houver próximo, ainda não é o último
        atu = atu->prox;        // avança um nó por vez até chegar no último
    atu->prox = novo;           // conecta o último (atu) ao novo nó
}

Complexidade da inserção no final: O(n) porque precisa percorrer toda a lista para encontrar o último nó. Inserção no início é O(1).

Remoção — lógica do ponteiro anterior

remover por valor
int remover(No **l, int valor) {   // remove o primeiro nó cujo info == valor
    No *ant = NULL, *atu = *l;   // ant=nó anterior (ainda nenhum), atu=nó atual (começa no início)
    while (atu != NULL && atu->info != valor) {   // anda enquanto não chegou ao fim E não achou o valor
        ant = atu;              // guarda o nó atual como "anterior" antes de avançar
        atu = atu->prox;        // avança para o próximo nó
    }
    if (atu == NULL) return 0;    // chegou ao fim sem achar → não encontrado

    if (ant == NULL)              // ant nunca mudou → o alvo é o primeiro nó
        *l = atu->prox;            // novo início passa a ser o segundo nó
    else                           // alvo está no meio ou no fim
        ant->prox = atu->prox;     // o anterior "pula" o alvo, ligando direto ao seguinte
    free(atu);                  // libera a memória do nó removido (evita vazamento)
    return 1;                    // sucesso
}
remover(&inicio, 20) — lista: [10]→[20]→[30]→NULL
ant=NULL, atu=inicio=[10|→20] Iteração 1: atu->info = 10 == 20? Não. ant = atu = [10|→] atu = atu->prox = [20|→] Iteração 2: atu->info = 20 == 20? Sim. Para o while. ant != NULL (ant aponta para [10|→]) → ant->prox = atu->prox = [30|NULL] → [10|→] agora aponta para [30|NULL] free(atu) → libera [20|→] Resultado: [10|→] → [30|NULL] ✓
remover(&inicio, 10) — removendo o PRIMEIRO — [10]→[20]→NULL
ant=NULL, atu=inicio=[10|→] Iteração 1: atu->info = 10 == 10? Sim. Para imediatamente. ant == NULL? SIM → estamos removendo o primeiro nó! *l = atu->prox = [20|NULL] → inicio agora aponta para [20|NULL] free(atu) → libera [10|→] Resultado: inicio → [20|NULL] ✓

Percorrimento — leitura da lista

percorrer e imprimir
void percorrer(No *l) {        // recebe cópia do ponteiro (basta ler, não altera a lista)
    while (l != NULL) {       // repete enquanto não passou do último nó
        printf("%d ", l->info);   // imprime o dado do nó atual
        l = l->prox;            // avança para o próximo (mexe só na cópia local)
    }
}

Para imprimir [10]→[20]→[30]→NULL: saída é 10 20 30. O percorrimento usa uma variável local l — não modifica o ponteiro original da lista.

// 04

Lista duplamente encadeada — dois ponteiros

Cada nó tem dois ponteiros: ant (para o nó anterior) e prox (para o próximo). Permite percorrer nos dois sentidos e remover um nó sem precisar do nó anterior.

estrutura do nó duplamente encadeado
typedef struct no {        // nó com DUAS ligações
    int          info;        // o dado guardado
    struct no *ant;   // anterior (NULL se for o primeiro)
    struct no *prox;  // próximo (NULL se for o último)
} No;                       // apelido "No"
Representação visual: NULL ← [ant|10|prox] ↔ [ant|20|prox] ↔ [ant|30|prox] → NULL ↑ inicio O primeiro nó: ant = NULL O último nó: prox = NULL

Inserção no início com dupla ligação

inserirInicio com dois ponteiros
void inserirInicio(No **l, int valor) {   // insere no começo da lista dupla
    No *novo = (No*) malloc(sizeof(No));   // cria o nó
    novo->info = valor;       // grava o dado
    novo->ant  = NULL;       // novo é o primeiro, não tem anterior
    novo->prox = *l;          // seu próximo é o antigo primeiro nó
    if (*l != NULL)         // se a lista não estava vazia...
        (*l)->ant = novo;     // CRÍTICO: o antigo primeiro agora aponta "ant" p/ o novo
    *l = novo;                // atualiza o início p/ o novo nó
}
Atualizar (*l)->ant é obrigatório

Na lista duplamente encadeada, inserir um novo nó no início exige atualizar o ponteiro ant do antigo primeiro nó para apontar para o novo. Se esquecer, a lista terá um ponteiro ant errado no segundo nó — aponta para NULL em vez do novo primeiro.

Remoção com dupla ligação

remover por valor — lista duplamente encadeada
int remover(No **l, int valor) {   // remove por valor na lista dupla (não precisa de "ant" separado)
    No *atu = *l;               // começa no primeiro nó
    while (atu != NULL && atu->info != valor)   // procura o nó com o valor
        atu = atu->prox;        // avança
    if (atu == NULL) return 0;   // não encontrado

    if (atu->ant != NULL)        // tem nó antes → não é o primeiro
        atu->ant->prox = atu->prox;   // o anterior pula o atual (liga ao seguinte)
    else
        *l = atu->prox;            // era o primeiro → novo início é o seguinte

    if (atu->prox != NULL)        // tem nó depois → não é o último
        atu->prox->ant = atu->ant;   // o seguinte aponta "ant" de volta p/ o anterior

    free(atu);                  // libera a memória do nó removido
    return 1;                    // sucesso
}

Por que dois ifs de remoção? Precisamos atualizar dois ponteiros:

  1. O nó anterior ao removido deve ter seu prox pulando o nó removido
  2. O nó posterior ao removido deve ter seu ant pulando o nó removido
  3. Mas se o nó a ser removido for o primeiro (ant == NULL), atualizamos o início da lista em vez do nó anterior
  4. E se for o último (prox == NULL), não há nó posterior para atualizar
// 05

Lista circular — sem NULL, com do-while

O último nó aponta para o primeiro, formando um ciclo. Não existe NULL nos ponteiros de uma lista circular não vazia. Isso muda como percorremos e como detectamos o fim.

Lista circular simplesmente encadeada: inicio → [10|→] → [20|→] → [30|→] ─┐ ↑_________________________│ O último nó (30) aponta de volta para o primeiro (10).

Percorrimento — use do-while, não while

percorrer lista circular
void percorrer(No *inicio) {     // percorre lista circular
    if (inicio == NULL) return;   // lista vazia: nada a fazer
    No *atu = inicio;           // começa no primeiro nó
    do {                        // do-while: executa o corpo ANTES de testar (visita ao menos 1)
        printf("%d ", atu->info);   // imprime o dado atual
        atu = atu->prox;        // avança um nó
    } while (atu != inicio);      // repete até dar a volta completa e voltar ao início
}

Por que do-while e não while? Com while (atu != inicio), a condição seria checada antes da primeira iteração. Como atu começa em inicio, a condição seria falsa de imediato e o loop não executaria — visitaríamos zero elementos. O do-while garante que o primeiro elemento seja processado antes de checar a condição de parada.

Lista circular com 1 elemento

Um único nó numa lista circular aponta para si mesmo: nó->prox = nó. O percorrimento do-while: visita o nó (info), atu = nó->prox = nó, atu == inicio? Sim → para. Correto — visita exatamente 1 elemento.

// 06

Ponteiro para ponteiro — **l na prova

Funções que modificam o início da lista precisam receber um ponteiro para ponteiro (No **l). Isso é uma das fontes de confusão mais comuns na prova.

Por que **l e não *l?

  • Se a função recebe No *l e faz l = novo, modifica apenas a cópia local. O ponteiro original não é alterado.
  • Se recebe No **l e faz *l = novo, modifica o ponteiro original através de indireção dupla.
diferença — passagem por valor vs. por referência
// ERRADO — não modifica o inicio original
void inserirErrado(No *l, int valor) {   // recebe só uma CÓPIA do ponteiro inicio
    No *novo = ...;     // cria o nó (malloc omitido por brevidade)
    novo->prox = l;      // novo aponta p/ o antigo primeiro
    l = novo;            // muda só a cópia local; a variável da main continua igual!
}

// CORRETO — modifica o inicio original via **
void inserirCorreto(No **l, int valor) {   // recebe o ENDEREÇO do ponteiro inicio
    No *novo = ...;     // cria o nó
    novo->prox = *l;     // *l = o inicio real; novo aponta p/ o antigo primeiro
    *l = novo;           // escreve no inicio real da main através do ponteiro
}
entendendo **l
No *inicio = [10|→[20|NULL]] ← variável na main inserirCorreto(&inicio, 5): l = &inicio ← l é o endereço de inicio *l = inicio ← *l é o valor de inicio (o nó [10|→]) novo->prox = *l ← novo aponta para [10|→] *l = novo ← inicio (na main) agora aponta para novo Na main após a chamada: inicio → [5|→] → [10|→] → [20|NULL] ✓
// 07

Pegadinhas da prova — estruturas lineares

⚠ pegadinha #1 — perder ponteiro ao inserir

Ao inserir um nó, se você fizer *l = novo antes de novo->prox = *l, você sobrescreve o ponteiro para a lista antes de salvá-lo. A lista é perdida.

// ERRADO:
*l = novo;          // inicio agora aponta para novo
novo->prox = *l;    // novo->prox = novo (aponta para si mesmo!)

// CORRETO:
novo->prox = *l;    // salva o inicio primeiro
*l = novo;          // agora atualiza o inicio
⚠ pegadinha #2 — lista circular: while vs do-while

Se o código usar while (atu != inicio) numa lista circular, o loop não executa nenhuma iteração porque atu começa igual a inicio. Use do-while ou use uma variável de controle.

⚠ pegadinha #3 — lista sequencial: limite de inserção é MAX, não MAX+1

A condição de lista cheia é n == MAX. Com MAX=100, a lista pode ter no máximo 100 elementos (índices 0 a 99). Se n=100, não cabe mais nenhum.

// inserir falha se:
if (l->n == MAX) return 0;  // n==MAX significa que está cheia
⚠ pegadinha #4 — deslocamento de inserção começa no fim, não no início

Para inserir na posição p, o loop começa em i = n e vai até i > p, decrementando. Se começasse em p e fosse até n, sobrescreveria dados antes de copiá-los.

⚠ pegadinha #5 — lista duplamente encadeada: esquecer de atualizar ->ant

Na inserção de um nó, precisa atualizar o ant do nó seguinte. Na remoção, precisa atualizar o ant do nó posterior ao removido. Se só atualizar prox, os ponteiros ant ficam inconsistentes.

⚠ pegadinha #6 — percorrer lista encadeada modifica o ponteiro local, não o original
void percorrer(No *l) {
    while (l != NULL) {
        printf("%d ", l->info);
        l = l->prox;    // modifica a cópia local, não a original
    }
}
// O ponteiro original passado para percorrer() não foi modificado.
⚠ pegadinha #7 — remover nó que não existe não corrompe a lista

Se atu == NULL ao final do while de busca, a função retorna 0 sem modificar nada. A lista permanece intacta. Isso é um retorno de erro, não uma corrupção.

⚠ pegadinha #8 — inserção válida na posição n (após o último)

Numa lista de n elementos, inserir na posição n é válido — equivale a inserir no final. A condição de validade é p >= 0 && p <= l->n. A posição p = n não é erro!

// Lista com n=3: posições válidas de inserção = 0, 1, 2, 3

Questões no estilo da prova

Analise o código e responda

Q1. A lista sequencial tem n=3, MAX=5, v=[10,20,30,?,?]. Após inserir(l, 99, 1), qual o estado?

✔ Inserir na posição 1: loop i de n=3 até i>p=1. i=3: v[3]=v[2]=30. i=2: v[2]=v[1]=20. i=1: 1>1 falso, para. v[1]=99. n=4. Estado: [10,99,20,30,?].
✘ Inserção na posição 1: desloca v[2]→v[3] e v[1]→v[2]. Então v[1]=99. Resultado: [10,99,20,30,?], n=4.

Q2. Qual a saída de percorrer(inicio) após as operações abaixo?

No *inicio = NULL;
inserirInicio(&inicio, 30);
inserirInicio(&inicio, 20);
inserirInicio(&inicio, 10);
// percorrer imprime do início ao fim
✔ Inserção no início inverte a ordem: após inserir 30 → [30]. Depois 20 → [20,30]. Depois 10 → [10,20,30]. Percorrimento: 10 20 30.
✘ inserirInicio sempre insere na frente. Ordem de inserção: 30, 20, 10. Cada inserção empurra o anterior para trás: [30] → [20,30] → [10,20,30]. Saída: 10 20 30.

Q3. Na lista circular com 1 elemento, o prox do nó aponta para:

✔ Na lista circular, o único elemento aponta para si mesmo (é tanto o primeiro quanto o último). prox = o próprio nó. O percorrimento do-while: visita o nó, atu = atu->prox = o próprio nó, atu == inicio? Sim → para.
✘ Na lista circular, não existe NULL. Com 1 elemento, o nó aponta para si mesmo: prox = nó.

Q4. Por que a função inserirInicio recebe No **l e não No *l?

✔ Com No *l, qualquer atribuição a l modifica apenas a cópia local na função. Com No **l, a atribuição a *l modifica o ponteiro original. Inserção no início precisa mudar o que "inicio" aponta — requer **l.
✘ Parâmetros em C são cópias. Com No *l, fazer l=novo não afeta o ponteiro original. Com No **l e *l=novo, o ponteiro original é modificado através de dupla indireção.

Q5. Qual a complexidade de inserir no início da lista simplesmente encadeada e da lista sequencial, respectivamente?

✔ Lista encadeada: inserir no início é O(1) — aloca nó, ajusta 2 ponteiros, pronto. Lista sequencial: inserir no início exige deslocar todos os n elementos para a direita → O(n).
✘ Encadeada: inserção no início O(1) (sem deslocamento). Sequencial: inserção no início O(n) (desloca tudo).

Q6. Lista sequencial com v=[2,3,2,0,3] (5 primeiros dígitos da matrícula 232037937), n=5. Após remover(l, 2) (remover posição 2), qual o estado?

✔ Remover posição 2 (valor 2): loop i de p=2 até i<n-1=4. i=2: v[2]=v[3]=0→[2,3,0,0,3]. i=3: v[3]=v[4]=3→[2,3,0,3,3]. i=4: 4<4? Falso, para. n--→n=4. Porção válida: v[0..3]=[2,3,0,3]. O valor em v[4] (=3) ainda existe na memória mas está fora do alcance (n=4).
✘ Remoção desloca de frente para trás: v[2]←v[3]=0, v[3]←v[4]=3. Array com posição válida n=4: [2,3,0,3].

Q7. inserirInicio é chamada 3 vezes com os 3 primeiros dígitos da matrícula 232037937 (2, 3 e 2, nessa ordem). Qual a saída de percorrer(inicio)?

No *inicio = NULL;
inserirInicio(&inicio, 2);
inserirInicio(&inicio, 3);
inserirInicio(&inicio, 2);
✔ Inserir 2: [2|NULL]. Inserir 3: [3|→2|NULL]. Inserir 2: [2|→3|→2|NULL]. percorrer imprime da esquerda: 2 3 2. Coincidência: a string "2 3 2" é a mesma que a ordem de inserção (2, 3, 2), pois a última inserção (2) foi para o início. Não confunda com a regra geral de inversão — aqui o primeiro e terceiro valores são iguais.
✘ Cada inserirInicio empurra o atual para trás: após inserir 2→[2], depois 3→[3,2], depois 2→[2,3,2]. percorrer: 2 3 2.

Q8. Numa lista simplesmente encadeada, você recebe um ponteiro direto para um nó do meio (sem o anterior). Qual a complexidade de removê-lo?

✔ Para remover um nó da lista simplesmente encadeada, precisa fazer ant->prox = atu->prox. Mas para isso precisa de ant — o nó anterior. Sem ele, é necessário percorrer desde *l até encontrar o nó cujo prox == atu. Isso é O(n). A lista simplesmente encadeada não tem ponteiro ant, ao contrário da duplamente encadeada.
✘ Mesmo com ponteiro para o nó, remoção em lista simples exige o nó anterior (para ant->prox = atu->prox). Encontrar o anterior custa O(n).

Q9. Na lista duplamente encadeada, você recebe um ponteiro direto para um nó do meio. Qual a complexidade de removê-lo? Por que difere da lista simplesmente encadeada?

✔ Na lista duplamente encadeada, o próprio nó tem atu->ant (anterior) e atu->prox (próximo). Para remover: atu->ant->prox = atu->prox e atu->prox->ant = atu->ant. Ambas as operações são O(1) — sem percorrimento. Esta é a principal vantagem da lista dupla sobre a simples: remoção O(1) com ponteiro direto para o nó.
✘ Lista dupla: atu->ant já aponta para o anterior. Remoção = 2 atribuições de ponteiro = O(1). Não precisa percorrer.

Q10. Uma lista circular tem 3 nós com valores [2, 3, 2] (3 primeiros dígitos da matrícula 232037937). O código de percorrimento usa while (atu != inicio) em vez de do-while. Quantos elementos são visitados?

No *atu = inicio;
while (atu != inicio) {   // ← while, não do-while
    printf("%d ", atu->info);
    atu = atu->prox;
}
✔ atu começa igual a inicio. A condição while (atu != inicio) é verificada ANTES da primeira iteração: atu==inicio → falso → loop não executa → 0 elementos visitados. O do-while resolve isso: executa o corpo primeiro, depois verifica a condição. Esta é a pegadinha #2 desta apostila: lista circular + while sem do = visita zero elementos.
✘ atu = inicio na linha 1. while(atu != inicio) → while(false) → loop não executa. 0 elementos. Use do-while para listas circulares.
