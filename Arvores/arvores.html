Árvore binária — conceitos e propriedades

analogia do dia a dia

Uma árvore binária é como uma árvore genealógica onde cada pessoa tem no máximo 2 filhos: um filho "esquerdo" e um filho "direito". A raiz é o ancestral comum. Cada pessoa sem filhos é uma "folha" da árvore.

Uma árvore binária é uma estrutura hierárquica definida recursivamente: é vazia OU um nó raiz com duas subárvores binárias (esquerda e direita). Cada nó tem um campo de dado e dois ponteiros para os filhos.

estrutura do nó — C
typedef struct no {
    int          info;       // dado armazenado no nó
    struct no *esq;        // ponteiro para o filho esquerdo
    struct no *dir;        // ponteiro para o filho direito
} No;

Propriedades fundamentais

PropriedadeFórmula / Valor
Nº máximo de nós no nível k2k (raiz: nível 0)
Nº máximo de nós total (altura h)2h+1 − 1
Altura mínima com n nós⌊log2 n⌋ (balanceada)
Altura máxima com n nósn − 1 (degenerada)
Nº de folhas em árvore cheia2h
[8] ← raiz (nível 0) / \ [3] [10] ← nível 1 / \ \ [1] [6] [14] ← nível 2 / \ / [4] [7] [13] ← nível 3 Nós: 9 · Altura: 3 · Folhas: {1,4,7,13} (4 folhas)

Termos importantes:

  • Nó folha: nó sem filhos (esq == NULL && dir == NULL)
  • Árvore cheia: todo nó tem 0 ou 2 filhos (nenhum filho único)
  • Árvore completa: todos os níveis exceto o último estão preenchidos
  • Árvore degenerada: cada nó tem no máximo 1 filho → vira lista encadeada
  • Árvore balanceada: altura O(log n)
Árvore degenerada = pior caso. Uma BST degenerada tem altura O(n) e todas as operações viram O(n) — igual a uma lista encadeada. Isso acontece inserindo elementos em ordem crescente (ou decrescente).
// 02

Árvore binária de busca — BST

Uma BST (Binary Search Tree) impõe a propriedade de ordem: para todo nó X, todos os valores na subárvore esquerda são menores que X e todos na subárvore direita são maiores que X. Não há duplicatas (valores iguais não são inseridos).

[8] / \ [3] [10] / \ \ [1] [6] [14] Propriedade BST verificada: - Esquerda de 8: {1,3,6} — todos < 8 ✓ - Direita de 8: {10,14} — todos > 8 ✓ - Esquerda de 3: {1} — 1 < 3 ✓ - Direita de 3: {6} — 6 > 3 ✓

Busca em BST

busca recursiva — O(log n) balanceada, O(n) degenerada
No* buscar(No *raiz, int x) {
    if (raiz == NULL) return NULL;        // não encontrou (base)
    if (raiz->info == x) return raiz;        // encontrou!
    if (x < raiz->info)
        return buscar(raiz->esq, x);     // vai p/ esquerda (menores)
    else
        return buscar(raiz->dir, x);     // vai p/ direita (maiores)
}

Inserção em BST

inserção recursiva — O(log n) balanceada, O(n) degenerada
No* inserir(No *raiz, int x) {
    if (raiz == NULL) {              // chegou na posição correta
        No *novo = (No*) malloc(sizeof(No));
        novo->info = x;
        novo->esq = novo->dir = NULL;
        return novo;
    }
    if (x < raiz->info)
        raiz->esq = inserir(raiz->esq, x);
    else if (x > raiz->info)
        raiz->dir = inserir(raiz->dir, x);
    // se x == raiz->info: não insere (sem duplicatas)
    return raiz;
}
Inserção sempre cria nó folha. O novo nó é sempre inserido como folha — nunca no meio da árvore. A recursão desce até encontrar NULL e aloca lá.
// 03

Remoção em BST — os 3 casos

A remoção é a operação mais complexa da BST. Existem 3 casos distintos, dependendo do número de filhos do nó a ser removido.

remoção em BST — implementação completa
No* remover(No *raiz, int x) {
    if (raiz == NULL) return NULL;         // valor não encontrado

    if (x < raiz->info)
        raiz->esq = remover(raiz->esq, x);
    else if (x > raiz->info)
        raiz->dir = remover(raiz->dir, x);
    else {                               // ENCONTROU o nó a remover

        // CASO 1: nó folha (0 filhos)
        if (raiz->esq == NULL && raiz->dir == NULL) {
            free(raiz);
            return NULL;
        }

        // CASO 2: um filho só (esquerdo OU direito)
        if (raiz->esq == NULL) {         // só tem filho direito
            No *tmp = raiz->dir;
            free(raiz);
            return tmp;                 // filho sobe no lugar
        }
        if (raiz->dir == NULL) {         // só tem filho esquerdo
            No *tmp = raiz->esq;
            free(raiz);
            return tmp;                 // filho sobe no lugar
        }

        // CASO 3: dois filhos — usa SUCESSOR (menor da direita)
        No *suc = raiz->dir;
        while (suc->esq != NULL)
            suc = suc->esq;               // vai até o menor da subárvore direita
        raiz->info = suc->info;            // copia o valor do sucessor
        raiz->dir = remover(raiz->dir, suc->info); // remove sucessor (caso 1 ou 2)
    }
    return raiz;
}
Removendo 3 da BST: Removendo 10 da BST: [8] [8] / \ / \ [3] [10] → [4] [14] / \ \ / \ / [1] [6] [14] [1] [6] [13] / \ / / \ [4] [7] [13] [4] [7] Caso 3: 2 filhos Caso 2: 1 filho Sucessor de 3 = 4 10 só tem filho direito Copia 4, remove 4 (caso 1) Sobe [14] no lugar
CasoFilhosAçãoComplexidade
Caso 10 (folha)free(raiz), retorna NULLO(log n)
Caso 21 filhofree(raiz), retorna o filhoO(log n)
Caso 32 filhosSubstitui pelo sucessor, remove sucessorO(log n)

Sucessor = menor da subárvore direita. O sucessor de um nó X é o menor valor MAIOR que X. Basta ir uma vez para a direita e depois descer sempre à esquerda até NULL. O sucessor sempre tem no máximo 1 filho (o direito) — portanto sua remoção é sempre caso 1 ou 2.

// 04

Percorrimentos em árvores — pré, em e pós-ordem

Três tipos de percorrimento DFS (depth-first search). A diferença está na ordem de visita da raiz em relação aos filhos.

pré-ordem (RED): Raiz → Esquerda → Direita
void preOrdem(No *raiz) {
    if (raiz == NULL) return;
    printf("%d ", raiz->info);        // visita raiz PRIMEIRO
    preOrdem(raiz->esq);
    preOrdem(raiz->dir);
}
em-ordem (ERD): Esquerda → Raiz → Direita
void emOrdem(No *raiz) {
    if (raiz == NULL) return;
    emOrdem(raiz->esq);
    printf("%d ", raiz->info);        // visita raiz NO MEIO
    emOrdem(raiz->dir);
}
pós-ordem (EDR): Esquerda → Direita → Raiz
void posOrdem(No *raiz) {
    if (raiz == NULL) return;
    posOrdem(raiz->esq);
    posOrdem(raiz->dir);
    printf("%d ", raiz->info);        // visita raiz POR ÚLTIMO
}
Árvore de exemplo: [8] / \ [3] [10] / \ \ [1] [6] [14] / \ / [4] [7] [13] Pré-ordem (RED): 8 3 1 6 4 7 10 14 13 Em-ordem (ERD): 1 3 4 6 7 8 10 13 14 ← ordem crescente! Pós-ordem (EDR): 1 4 7 6 3 13 14 10 8
PercorrimentoAbrev.Resultado em BSTUso típico
Pré-ordemREDRaiz primeiroCopiar árvore, expressão prefixa
Em-ordemERDOrdem crescente!Listar elementos ordenados
Pós-ordemEDRRaiz por últimoDeletar árvore (libera folhas primeiro), expressão posfixa

Em-ordem em BST = elementos em ordem crescente. Esta é uma propriedade exclusiva da BST. Se o percorrimento em-ordem não produzir valores crescentes, a árvore NÃO é uma BST válida.

Complexidade dos percorrimentos: O(n). Todo percorrimento visita cada nó exatamente uma vez. A recursão usa a pilha de chamadas como estrutura auxiliar implícita.
// 05

Lista encadeada sem descritor

A lista é referenciada diretamente pelo ponteiro para o primeiro nó. Lista vazia = NULL. Funções que alteram o primeiro nó precisam de **l.

estrutura e inserção no início
typedef struct no {
    int          info;
    struct no *prox;
} No;

void inserirInicio(No **l, int valor) {
    No *novo = (No*) malloc(sizeof(No));
    novo->info = valor;
    novo->prox = *l;                  // novo aponta p/ antigo primeiro
    *l = novo;                        // início atualizado
}

Vantagens

Tamanho dinâmico, inserção/remoção no início O(1), sem desperdício de memória, sem deslocamento.

Desvantagens

Acesso sequencial O(n), inserção no fim O(n) (precisa percorrer toda a lista), remoção no fim O(n).

remoção por valor — com ponteiro anterior
int remover(No **l, int valor) {
    No *ant = NULL, *atu = *l;
    while (atu != NULL && atu->info != valor) {
        ant = atu;
        atu = atu->prox;
    }
    if (atu == NULL) return 0;          // não encontrado
    if (ant == NULL) // removendo o primeiro
        *l = atu->prox;
    else              // removendo do meio ou fim
        ant->prox = atu->prox;
    free(atu);
    return 1;
}
// 06

Lista encadeada com descritor

O descritor é uma struct que encapsula metadados da lista: ponteiro para o primeiro nó, ponteiro para o último e opcionalmente o tamanho.

estrutura com descritor
typedef struct no {
    int          info;
    struct no *prox;
} No;

typedef struct {
    No  *inicio;       // ponteiro p/ primeiro nó
    No  *fim;          // ponteiro p/ último nó (chave p/ O(1) no fim)
    int   tam;          // quantidade de nós (opcional mas útil)
} Descritor;
inserção no fim — O(1) com descritor
void inserirFim(Descritor *d, int valor) {
    No *novo = (No*) malloc(sizeof(No));
    novo->info = valor;
    novo->prox = NULL;

    if (d->inicio == NULL) {           // lista vazia
        d->inicio = novo;
        d->fim = novo;
    } else {
        d->fim->prox = novo;           // conecta no último
        d->fim = novo;                 // atualiza ponteiro fim
    }
    d->tam++;
}

Vantagem chave do descritor: inserção no fim O(1). Sem descritor, inserir no fim exige percorrer toda a lista (O(n)). Com o ponteiro fim, a inserção é direta. O campo tam também evita percorrer para saber o tamanho.

Remover do fim ainda é O(n). Na lista simplesmente encadeada, mesmo com descritor, remover o último nó exige encontrar o penúltimo para ajustar fim — e isso custa O(n). Na lista duplamente encadeada com descritor, a remoção do fim é O(1).

Pilha — revisão

Estrutura LIFO (Last In, First Out). O último elemento inserido é o primeiro a ser removido. Implementada com lista encadeada (dinâmica) ou vetor (estática).

analogia do dia a dia

Uma pilha de pratos: você coloca pratos no topo (push) e retira do topo (pop). Não pode tirar um prato do meio sem derrubar a pilha.

pilha com lista encadeada
typedef struct no {
    int          info;
    struct no *prox;
} No;

No *topo = NULL;              // pilha vazia

// push — insere no topo (início da lista)
void push(No **topo, int x) {
    No *novo = (No*) malloc(sizeof(No));
    novo->info = x;
    novo->prox = *topo;
    *topo = novo;
}

// pop — remove do topo (início da lista)
int pop(No **topo) {
    if (*topo == NULL) return -1;   // pilha vazia
    No *tmp = *topo;
    int val = tmp->info;
    *topo = tmp->prox;
    free(tmp);
    return val;
}

// peek (topo) — consulta sem remover
int peek(No *topo) {
    if (topo == NULL) return -1;
    return topo->info;
}

Complexidade da pilha: Push O(1), Pop O(1), Peek O(1) — todas as operações no topo. Pilha implementada com vetor também é O(1), mas com limite de capacidade (MAX).

Toda função recursiva usa a pilha de chamadas. Cada chamada recursiva empilha um frame (parâmetros, endereço de retorno). Estourar a pilha = stack overflow = recursão muito profunda.
// 08

Fila — revisão

Estrutura FIFO (First In, First Out). O primeiro a entrar é o primeiro a sair. Implementada com lista encadeada + descritor ou vetor circular.

analogia do dia a dia

Fila de banco: quem chega primeiro é atendido primeiro. Novas pessoas entram no fim da fila (enqueue), o atendimento ocorre no início (dequeue).

fila com lista encadeada + descritor
typedef struct no {
    int          info;
    struct no *prox;
} No;

typedef struct {
    No *inicio;       // frente da fila (dequeue sai daqui)
    No *fim;          // final da fila (enqueue entra aqui)
} Fila;

// enqueue — insere no fim (igual inserirFim com descritor)
void enfileirar(Fila *f, int x) {
    No *novo = (No*) malloc(sizeof(No));
    novo->info = x;
    novo->prox = NULL;
    if (f->fim != NULL)
        f->fim->prox = novo;
    else
        f->inicio = novo;         // fila vazia: primeiro nó
    f->fim = novo;
}

// dequeue — remove do início (frente da fila)
int desenfileirar(Fila *f) {
    if (f->inicio == NULL) return -1;
    No *tmp = f->inicio;
    int val = tmp->info;
    f->inicio = tmp->prox;
    if (f->inicio == NULL)     // fila ficou vazia
        f->fim = NULL;
    free(tmp);
    return val;
}

Complexidade da fila: Enqueue O(1), Dequeue O(1), Peek O(1). A fila com vetor circular também é O(1) para todas as operações. O descritor com inicio e fim é essencial para garantir O(1) em ambas as pontas.

Operações na fila: inicio → [10|→] → [20|→] → [30|→] → NULL ↑ ↑ frente fim (último) enfileirar(40): inicio → [10|→] → [20|→] → [30|→] → [40|NULL] ↑ ↑ frente fim desenfileirar() → retorna 10: inicio → [20|→] → [30|→] → [40|NULL] ↑ ↑ frente fim

Resumo prático:

  • Dados ordenados + busca frequente → BST (O(log n) se balanceada)
  • Cuidado: inserção em ordem crescente → BST degenera → O(n)
  • Muitas inserções/remoções no fim → Lista com descritor (O(1))
  • Precisa de "desfazer", recursão, backtracking → Pilha
  • Processamento em ordem de chegada (FIFO) → Fila

Quiz rápido

Teste seus conhecimentos

1. Qual percorrimento em uma BST produz os elementos em ordem crescente?

✔ Em-ordem (ERD) visita esquerda → raiz → direita, produzindo a sequência ordenada em uma BST.
✘ Em-ordem (ERD) é o percorrimento que produz elementos em ordem crescente em uma BST.

2. Qual a complexidade de remover um nó folha em uma BST balanceada?

✔ O(log n): primeiro é preciso buscar o nó (O(log n) na árvore balanceada), depois a remoção é O(1).
✘ A busca pelo nó custa O(log n) na árvore balanceada. A remoção em si é O(1), mas o custo total é dominado pela busca: O(log n).

3. Qual a principal vantagem do descritor em uma lista encadeada?

✔ O descritor mantém ponteiro para o último nó (fim), permitindo inserção no final em O(1). Remoção do fim ainda é O(n) na lista simples.
✘ A grande vantagem é o ponteiro 'fim', que torna a inserção no final O(1).

4. O que acontece se inserirmos elementos em ordem crescente em uma BST sem balanceamento?

✔ A árvore vira uma lista encadeada (só filhos direitos). Altura = n-1, busca/inserção/remoção viram O(n).
✘ Inserir em ordem crescente produz uma árvore degenerada (todos os nós à direita), altura O(n).

5. Qual a complexidade de push e pop em uma pilha implementada com lista encadeada?

✔ Tanto push quanto pop operam no topo (início da lista), ambas são O(1).
✘ Ambas as operações são no início da lista: push insere no início, pop remove do início. Ambas O(1).
