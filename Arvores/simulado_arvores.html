typedef struct no {
    int          info;
    struct no *esq, *dir;    // árvore binária / BST
    struct no *prox;          // lista encadeada / pilha / fila
} No;

/* ── Descritor (lista encadeada com metadados) ────────────── */
typedef struct {
    No  *inicio;              // primeiro nó
    No  *fim;                 // último nó
    int   tam;                 // quantidade de nós
} Descritor;

/* ── BST ──────────────────────────────────────────────────── */
No* inserirBST(No *raiz, int x) {
    if (raiz == NULL) {
        No *novo = (No*) malloc(sizeof(No));
        novo->info = x;
        novo->esq = novo->dir = NULL;
        return novo;
    }
    if (x < raiz->info)
        raiz->esq = inserirBST(raiz->esq, x);
    else if (x > raiz->info)
        raiz->dir = inserirBST(raiz->dir, x);
    return raiz;
}

No* buscarBST(No *raiz, int x) {
    if (raiz == NULL || raiz->info == x) return raiz;
    if (x < raiz->info) return buscarBST(raiz->esq, x);
    return buscarBST(raiz->dir, x);
}

/* ── Lista encadeada sem descritor ────────────────────────── */
void insInicio(No **l, int v) {
    No *n = (No*) malloc(sizeof(No));
    n->info = v; n->prox = *l; *l = n;
}

int tamanho(No *l) {
    int c = 0;
    while (l) { c++; l = l->prox; }
    return c;
}

/* ── Pilha (LIFO) ─────────────────────────────────────────── */
void push(No **topo, int v) { insInicio(topo, v); }
int pop(No **topo) {
    if (!*topo) return -1;
    No *t = *topo; int v = t->info;
    *topo = t->prox; free(t);
    return v;
}

/* ── Fila (FIFO) com descritor ────────────────────────────── */
void enq(Descritor *f, int v) {
    No *n = (No*) malloc(sizeof(No));
    n->info = v; n->prox = NULL;
    if (f->fim) f->fim->prox = n;
    else f->inicio = n;
    f->fim = n; f->tam++;
}
int deq(Descritor *f) {
    if (!f->inicio) return -1;
    No *t = f->inicio; int v = t->info;
    f->inicio = t->prox;
    if (!f->inicio) f->fim = NULL;
    free(t); f->tam--;
    return v;
}
// BLOCO 1 — Árvore Binária de Busca
Questão 1 — BST · Inserção

Q1. Ao inserir os valores 8, 3, 10, 1, 6, 14 nessa ordem em uma BST inicialmente vazia, o percorrimento em-ordem produz 1 3 6 8 10 14.

✔ Correto! Em-ordem em uma BST sempre produz os elementos em ordem crescente, independentemente da ordem de inserção. A árvore resultante é balanceada: [8 [3 [1] [6]] [10 Ø [14]]]. Em-ordem: 1 3 6 8 10 14 ✓
✘ A afirmação é Verdadeira. Em-ordem em BST = ordem crescente. Não importa a ordem de inserção — se a propriedade BST for mantida, em-ordem sempre será crescente.
Questão 2 — BST · Degeneração

Q2. Inserir valores em ordem decrescente (9, 7, 3, 2, 0) em uma BST cria uma árvore degenerada com altura 4 e todas as operações O(n).

✔ Correto! Inserir em ordem decrescente gera apenas filhos à esquerda: [9 [7 [3 [2 [0]]]]]. Altura = 4 (raiz nível 0). É uma lista encadeada — busca/inserção/remoção O(n).
✘ A afirmação é Verdadeira. Ordem decrescente → todos filhos esquerdos → degenerada. Altura = n-1 = 4. Operações O(n).
Questão 3 — BST · Remoção (caso 3)

Q3. Ao remover a raiz (valor 8) da BST [8 [3 [1] [6]] [10 Ø [14]]], o sucessor é o nó 10 e ele assume o valor da raiz.

✔ Correto! O sucessor de 8 é o menor da subárvore direita: vai p/ direita (10), depois desce toda a esquerda. Como 10 não tem filho esquerdo, ele mesmo é o sucessor. Copia 10 p/ raiz e remove 10. 
Sucessor de 8:
1. Vai p/ direita: 10
2. Desce esquerda de 10: NULL → sucessor = 10
3. Copia 10 p/ raiz: raiz->info = 10
4. Remove 10 (caso 2: sobe 14)

Resultado: [10 [3 [1] [6]] [14]] ✓
✘ A afirmação é Verdadeira. O sucessor de 8 é 10 (vai p/ direita, depois toda esquerda — como 10 não tem esquerda, ele mesmo é o sucessor). Copia 10 p/ raiz e remove 10.
Questão 4 — BST · Complexidade

Q4. A busca em uma BST sempre tem complexidade O(log n), independentemente da ordem de inserção.

✔ Correto, é Falso! BST balanceada: O(log n). BST degenerada (inserção em ordem): O(n). A complexidade depende da altura, que no pior caso é O(n).
✘ A afirmação é Falsa. BST degenerada tem altura O(n) e busca O(n). O(log n) só é garantido em árvores balanceadas (AVL, rubro-negra).
Questão 5 — BST · Propriedade

Q5. Uma árvore binária onde o percorrimento em-ordem produz 2 5 3 8 não é uma BST válida.

✔ Correto! Em-ordem em uma BST sempre produz valores em ordem crescente. A sequência 2, 5, 3, 8 não é crescente (5 > 3), portanto a árvore não respeita a propriedade BST.
✘ A afirmação é Verdadeira. Se em-ordem não é crescente, a árvore NÃO é BST. 2, 5, 3, 8 tem 5 > 3 → violação da ordem.
// BLOCO 2 — Percorrimentos
Questão 6 — Pré-ordem

Q6. O percorrimento pré-ordem (RED) da BST [8 [3 [1] [6]] [10 Ø [14]]] produz 8 3 1 6 10 14.

✔ Correto! Pré-ordem (RED): visita raiz, depois esquerda, depois direita. 
8 → esq: 3 → esq: 1 → volta → dir: 6 → volta → dir: 10 → dir: 14
Resultado: 8 3 1 6 10 14 ✓
✘ A afirmação é Verdadeira. Pré-ordem: Raiz(8), Esq(3→1→6), Dir(10→14) = 8 3 1 6 10 14.
Questão 7 — Pós-ordem

Q7. O percorrimento pós-ordem (EDR) da BST [8 [3 [1] [6]] [10 Ø [14]]] produz 1 6 3 14 10 8.

✔ Correto! Pós-ordem (EDR): visita esquerda, depois direita, depois raiz. 
Esq(3): 1 → 6 → 3
Dir(10): 14 → 10
Raiz: 8
Resultado: 1 6 3 14 10 8 ✓
✘ A afirmação é Verdadeira. Pós-ordem: folhas primeiro (1,6,14), depois pais (3,10), raiz (8) por último.
Questão 8 — Pós-ordem = deletar árvore

Q8. Para deletar todos os nós de uma árvore binária sem deixar dangling pointers (ponteiros pendentes), o percorrimento ideal é o pós-ordem, pois as folhas são liberadas antes dos pais.

✔ Correto! Pós-ordem visita os filhos antes do pai. Se fizesse pré-ordem, liberaria a raiz primeiro e perderia a referência aos filhos. Pós-ordem: libera folhas → pais → raiz, sem perder referências.
✘ A afirmação é Verdadeira. Pós-ordem (EDR) garante que filhos sejam visitados antes dos pais — essencial para deletar sem perder ponteiros.
Questão 9 — Em-ordem em árvore não-BST

Q9. Toda árvore binária (não necessariamente BST) possui percorrimento em-ordem. O resultado sempre será uma sequência ordenada.

✔ Correto, é Falso! Toda árvore binária tem em-ordem, mas o resultado só é ordenado se for uma BST. Ex: árvore binária comum [8 [10] [3]] tem em-ordem 10, 8, 3 — não é ordenada.
✘ A afirmação é Falsa. O percorrimento em-ordem existe em qualquer árvore binária, mas a sequência será ordenada APENAS se a árvore for BST.
Questão 10 — Complexidade dos percorrimentos

Q10. Os percorrimentos pré-ordem, em-ordem e pós-ordem visitam cada nó exatamente uma vez, portanto todos têm complexidade O(n).

✔ Correto! Todos os três percorrimentos DFS visitam cada nó exatamente uma vez — O(n). A recursão usa a pilha de chamadas, que consome O(h) de memória extra.
✘ A afirmação é Verdadeira. Cada nó é visitado uma única vez em qualquer percorrimento DFS. Complexidade O(n).
// BLOCO 3 — Lista Encadeada (com e sem descritor)
Questão 11 — Inserção fim sem descritor

Q11. Em uma lista simplesmente encadeada sem descritor, a inserção no final tem complexidade O(n) porque é necessário percorrer toda a lista até o último nó.

✔ Correto! Sem descritor, a lista é referenciada apenas pelo ponteiro inicio. Para inserir no fim, é preciso percorrer nó a nó (while atu->prox != NULL) até o último — O(n).
✘ A afirmação é Verdadeira. Sem ponteiro para o último nó, a inserção no fim percorre toda a lista — O(n).
Questão 12 — Inserção fim com descritor

Q12. Com o descritor (struct com inicio e fim), a inserção no final da lista simplesmente encadeada passa a ser O(1).

✔ Correto! O descritor mantém fim apontando para o último nó. Inserir no fim: d->fim->prox = novo; d->fim = novo; — O(1).
✘ A afirmação é Verdadeira. O descritor armazena o ponteiro para o último nó, tornando a inserção no fim O(1).
Questão 13 — Remoção fim com descritor

Q13. Em uma lista simplesmente encadeada com descritor, a remoção do último nó também é O(1) porque o descritor tem o ponteiro fim.

✔ Correto, é Falso! A remoção do fim continua O(n) na lista simplesmente encadeada mesmo com descritor. É preciso percorrer desde o início para encontrar o penúltimo nó e ajustar seu prox e o ponteiro fim do descritor. Só a lista duplamente encadeada tem remoção do fim O(1).
✘ A afirmação é Falsa. Na lista simples, o ponteiro fim não tem ant. Para achar o penúltimo, percorre do início — O(n).
Questão 14 — Tamanho com vs sem descritor

Q14. Calcular o tamanho de uma lista simplesmente encadeada com descritor (campo tam) é O(1), enquanto sem descritor é O(n).

✔ Correto! Com descritor: return d->tam; — O(1). Sem descritor: percorre contando — O(n).
✘ A afirmação é Verdadeira. O campo tam no descritor armazena a contagem, tornando a consulta O(1).
Questão 15 — Ponteiro duplo

Q15. Funções que modificam o primeiro nó de uma lista sem descritor precisam receber No **l (ponteiro para ponteiro). Já com descritor, a função pode receber apenas Descritor *d (ponteiro para descritor).

✔ Correto! Sem descritor: No *inicio é uma variável local — para alterá-la, a função precisa de No **l. Com descritor: d->inicio é acessado via ponteiro Descritor *d — altera diretamente no struct.
✘ A afirmação é Verdadeira. Sem descritor: dupla indireção (**l). Com descritor: indireção simples (*d) acessa membros via ->.
// BLOCO 4 — Pilha e Fila
Questão 16 — Pilha LIFO

Q16. Na pilha implementada com lista encadeada (ponteiro topo), a sequência de operações push(2), push(3), push(2), pop(), pop(), push(0) resulta no topo igual a 2.

✔ Correto, é Falso! 
push(2) → topo=[2]
push(3) → topo=[3,2]
push(2) → topo=[2,3,2]
pop()   → topo=[3,2]    (removeu 2)
pop()   → topo=[2]      (removeu 3)
push(0) → topo=[0,2]
Topo = 0, não 2!
✘ A afirmação é Falsa. Trace: [2] → [3,2] → [2,3,2] → pop: [3,2] → pop: [2] → push 0: [0,2]. Topo = 0.
Questão 17 — Pilha O(1)

Q17. Tanto push quanto pop em uma pilha implementada com lista encadeada são O(1) porque ambas operam no início da lista.

✔ Correto! Push insere no início (topo), pop remove do início. Ambas são operações de lista encadeada no início — O(1).
✘ A afirmação é Verdadeira. O topo da pilha é o início da lista. Inserir/remover no início é O(1).
Questão 18 — Fila FIFO

Q18. Na fila implementada com descritor (inicio e fim), a sequência enq(2), enq(3), deq(), enq(0), enq(3), deq(), deq() resulta na frente da fila igual a 3.

✔ Correto! 
enq(2) → fila=[2]         frente=2, fim=2
enq(3) → fila=[2,3]       frente=2, fim=3
deq()  → fila=[3]         retorna 2
enq(0) → fila=[3,0]       frente=3, fim=0
enq(3) → fila=[3,0,3]     frente=3, fim=3
deq()  → fila=[0,3]       retorna 3
deq()  → fila=[3]         retorna 0
Frente = 3 ✓
✘ A afirmação é Verdadeira. Trace: [2]→[2,3]→deq:[3]→enq 0:[3,0]→enq 3:[3,0,3]→deq:[0,3]→deq:[3]. Frente=3.
Questão 19 — Fila sem descritor

Q19. Uma fila implementada com lista encadeada mas sem descritor (apenas ponteiro inicio) teria enqueue O(n), pois seria necessário percorrer até o fim para inserir.

✔ Correto! Sem descritor, a fila só tem referência ao início. Para enfileirar (inserir no fim), é preciso percorrer toda a lista até o último nó — O(n). O dequeue (remover do início) continua O(1).
✘ A afirmação é Verdadeira. Enfileirar = inserir no fim. Sem ponteiro fim, percorre toda a lista — O(n).
Questão 20 — Pilha vs Fila

Q20. Uma fila pode ser simulada usando duas pilhas. A operação de enfileirar (enqueue) empilha na pilha 1, e desenfileirar (dequeue) desempilha da pilha 2 (transferindo da pilha 1 se a pilha 2 estiver vazia).

✔ Correto! Este é um algoritmo clássico. Enqueue: push na pilha 1 — O(1). Dequeue: se pilha 2 vazia, transfere todos da pilha 1 para pilha 2 (invertendo a ordem), depois pop da pilha 2 — O(1) amortizado.
✘ A afirmação é Verdadeira. Simular fila com duas pilhas é um problema clássico de EDA. Enqueue O(1), dequeue O(1) amortizado.
