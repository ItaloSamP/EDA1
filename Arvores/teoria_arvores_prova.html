// 01

O que a prova testa em árvores e listas

As questões de árvores e listas geralmente caem em quatro categorias:

  1. Trace de operações em BST: dada uma sequência de inserções, qual a altura? Qual o estado após remoção? Percorrimento produz qual saída?
  2. Percorrimentos: identificar qual percorrimento (RED/ERD/EDR) produz determinada saída. Saber que em-ordem em BST = elementos ordenados.
  3. Descritor: entender a diferença de complexidade entre lista com e sem descritor. O que o campo fim proporciona?
  4. Complexidade: Big O de cada operação em cada estrutura: BST balanceada vs degenerada, lista c/ e s/ descritor, pilha, fila.
Cuidado especial com BST degenerada

A prova adora perguntar o que acontece quando inserimos elementos em ordem crescente em uma BST. A resposta: a árvore degenera (vira lista encadeada) e as operações passam de O(log n) para O(n).

// 02

Árvore binária — definições e propriedades

Cada nó tem no máximo 2 filhos (esquerdo e direito). O nó inicial é a raiz. Nós sem filhos são folhas.

estrutura do nó
typedef struct no {
    int          info;
    struct no *esq;     // filho esquerdo (NULL se não existe)
    struct no *dir;     // filho direito (NULL se não existe)
} No;

Propriedades que caem na prova:

  • Nível da raiz = 0. Altura = maior nível. Nº máximo de nós no nível k = 2k.
  • Árvore cheia: todo nó tem 0 ou 2 filhos. Árvore completa: todos níveis preenchidos exceto talvez o último.
  • Árvore degenerada: cada nó tem no máximo 1 filho. Altura = n−1. Vira lista encadeada.
  • Nº máximo de nós com altura h: 2h+1 − 1. Ex: h=3 → máximo 15 nós.

BST = árvore binária + propriedade de ordem. Para todo nó X: subárvore esquerda contém apenas valores < X, subárvore direita contém apenas valores > X. Não há duplicatas.

// 03

BST — inserção com trace

A inserção sempre cria um nó folha. A recursão desce pela árvore comparando o valor com cada nó, indo para esquerda (se menor) ou direita (se maior).

inserção recursiva em BST
No* inserir(No *raiz, int x) {
    if (raiz == NULL) {              // chegou na posição: cria nó folha
        No *novo = (No*) malloc(sizeof(No));
        novo->info = x;
        novo->esq = novo->dir = NULL;
        return novo;
    }
    if (x < raiz->info)
        raiz->esq = inserir(raiz->esq, x);   // desce pela esquerda
    else if (x > raiz->info)
        raiz->dir = inserir(raiz->dir, x);   // desce pela direita
    return raiz;                         // x == raiz->info: não insere
}
inserir(raiz, 2) → inserir(raiz, 3) → inserir(raiz, 2) — dígitos 232 da matrícula 232037937
Início: raiz = NULL inserir(NULL, 2): raiz == NULL → cria nó [2] → return [2] Árvore: [2] inserir([2], 3): raiz != NULL, 3 > 2 → raiz->dir = inserir(NULL, 3) raiz == NULL → cria nó [3] → return [3] Árvore: [2] \ [3] inserir([2], 2): raiz != NULL, 2 == 2 → NÃO insere (sem duplicatas) Árvore permanece: [2] \ [3] Árvore DEGENERADA! Inserir em ordem crescente (2, 3) já criou uma degeneração parcial. Se continuar inserindo em ordem: [2]→[3]→[7]→[9]... vira lista encadeada.
// 04

BST — remoção (os 3 casos)

Caso 1: nó folha (0 filhos)

remover folha — simples
if (raiz->esq == NULL && raiz->dir == NULL) {
    free(raiz);
    return NULL;    // retorna NULL para o pai
}

Caso 2: um filho só

remover nó com 1 filho — filho "sobe"
if (raiz->esq == NULL) {      // só tem filho direito
    No *tmp = raiz->dir;
    free(raiz);
    return tmp;              // filho assume o lugar
}
if (raiz->dir == NULL) {      // só tem filho esquerdo
    No *tmp = raiz->esq;
    free(raiz);
    return tmp;              // filho assume o lugar
}

Caso 3: dois filhos — usa SUCESSOR

sucessor = menor da subárvore direita (vai p/ direita, desce sempre à esquerda)
No *suc = raiz->dir;            // começa na subárvore direita
while (suc->esq != NULL)         // desce toda a esquerda
    suc = suc->esq;
raiz->info = suc->info;          // copia valor do sucessor
raiz->dir = remover(raiz->dir, suc->info);  // remove sucessor (caso 1 ou 2)

Por que o sucessor sempre cai no caso 1 ou 2? O sucessor é o menor da subárvore direita. Por ser o menor, ele NÃO tem filho esquerdo (se tivesse, esse filho seria menor ainda). Portanto, sua remoção é sempre caso 1 (folha) ou caso 2 (só filho direito).

remover 3 da BST [8 [3 [1] [6 [4] [7]]] [10 Ø [14 [13] Ø]]]
[8] / \ [3] [10] / \ \ [1] [6] [14] / \ / [4] [7] [13] Remover 3 → CASO 3 (2 filhos) 1. sucessor: vai p/ direita de 3 = [6], desce esquerda = [4] → suc = [4] 2. raiz->info = 4 (copia 4 para onde estava 3) 3. remover([6], 4): [4] é folha → CASO 1 → free([4]) Resultado: [8] / \ [4] [10] / \ \ [1] [6] [14] \ / [7] [13]
// 05

Percorrimentos — pré, em e pós-ordem

A diferença entre os 3 percorrimentos está na ordem de visita da raiz em relação aos filhos:

PercorrimentoOrdemNa BSTUso
Pré-ordemRaiz → Esq → Dir (RED)Raiz primeiroCópia da árvore
Em-ordemEsq → Raiz → Dir (ERD)Ordenado!Listar crescente
Pós-ordemEsq → Dir → Raiz (EDR)Raiz últimoDeletar árvore
Árvore: [8 [3 [1] [6 [4] [7]]] [10 Ø [14 [13] Ø]]] Pré-ordem (RED): 8 3 1 6 4 7 10 14 13 Em-ordem (ERD): 1 3 4 6 7 8 10 13 14 ← CRESCENTE! Pós-ordem (EDR): 1 4 7 6 3 13 14 10 8 REGRA MNEMÔNICA: - Pré: visita ANTES de descer - Em: visita ENTRE os filhos - Pós: visita DEPOIS de descer
Em-ordem em BST = ordem crescente

Se uma questão mostrar o resultado de um percorrimento e os valores estiverem em ordem crescente, é em-ordem em uma BST. Se NÃO estiverem em ordem crescente, a árvore NÃO é uma BST (ou o percorrimento não é em-ordem).

// 06

Lista encadeada sem descritor

Referenciada diretamente pelo ponteiro inicio. Funções que alteram o primeiro nó usam **l.

inserção no início — O(1)
void inserirInicio(No **l, int valor) {
    No *novo = (No*) malloc(sizeof(No));
    novo->info = valor;
    novo->prox = *l;    // ORDEM IMPORTA: salva lista atual primeiro
    *l = novo;           // depois atualiza o início
}
inserção no fim — O(n) sem descritor
void inserirFim(No **l, int valor) {
    No *novo = (No*) malloc(sizeof(No));
    novo->info = valor;
    novo->prox = NULL;
    if (*l == NULL) { *l = novo; return; }
    No *atu = *l;
    while (atu->prox != NULL)     // ⚠ PERCORRE até o último
        atu = atu->prox;
    atu->prox = novo;
}

Complexidade sem descritor: Inserir início O(1), Inserir fim O(n), Remover início O(1), Remover fim O(n), Busca O(n).

// 07

Lista encadeada com descritor

O descritor é uma struct que mantém inicio, fim e opcionalmente tam. A grande vantagem: inserção no fim vira O(1).

estrutura do descritor
typedef struct {
    No  *inicio;       // primeiro nó (para remoções no início em O(1))
    No  *fim;          // último nó (para inserções no fim em O(1))
    int   tam;          // quantidade de nós (tamanho em O(1))
} Descritor;
inserção no fim — O(1) COM descritor
void inserirFim(Descritor *d, int valor) {
    No *novo = (No*) malloc(sizeof(No));
    novo->info = valor;
    novo->prox = NULL;
    if (d->inicio == NULL) {          // lista vazia
        d->inicio = novo;
        d->fim = novo;
    } else {
        d->fim->prox = novo;          // último aponta pro novo
        d->fim = novo;                // atualiza ponteiro fim
    }
    d->tam++;
}

Comparação crucial:

  • Inserir fim sem descritor: O(n) — percorre a lista inteira
  • Inserir fim com descritor: O(1) — usa o ponteiro fim
  • Tamanho sem descritor: O(n) — conta os nós
  • Tamanho com descritor: O(1) — lê o campo tam
  • ATENÇÃO: Remover do fim ainda é O(n) na lista simples (precisa do penúltimo). Na dupla é O(1).
// 08

Pilha e Fila — operações

Pilha — LIFO (Last In, First Out)

pilha com lista encadeada — todas operações O(1)
void push(No **topo, int x) {   // empilhar = inserir no início
    No *novo = (No*) malloc(sizeof(No));
    novo->info = x;
    novo->prox = *topo;
    *topo = novo;
}

int pop(No **topo) {          // desempilhar = remover do início
    if (*topo == NULL) return -1;
    No *tmp = *topo;
    int val = tmp->info;
    *topo = tmp->prox;
    free(tmp);
    return val;
}

Fila — FIFO (First In, First Out)

fila com descritor (inicio + fim) — todas operações O(1)
void enfileirar(Fila *f, int x) { // enqueue = inserir no fim
    No *novo = (No*) malloc(sizeof(No));
    novo->info = x;
    novo->prox = NULL;
    if (f->fim != NULL) f->fim->prox = novo;
    else f->inicio = novo;
    f->fim = novo;
}

int desenfileirar(Fila *f) {      // dequeue = remover do início
    if (f->inicio == NULL) return -1;
    No *tmp = f->inicio;
    int val = tmp->info;
    f->inicio = tmp->prox;
    if (f->inicio == NULL) f->fim = NULL;
    free(tmp);
    return val;
}

Dica para a prova:

  • Pilha = tanto faz começar pelo início ou fim, mas o topo é sempre a mesma ponta (LIFO)
  • Fila = entrada pelo fim (enqueue), saída pelo início (dequeue) — FIFO
  • Fila sem descritor (sem ponteiro fim): enqueue vira O(n)
// 09

Pegadinhas da prova — árvores e listas

⚠ pegadinha #1 — BST degenerada com inserção ordenada

Inserir elementos em ordem crescente (1, 2, 3, 4...) em uma BST cria uma árvore degenerada. Altura = n−1. Busca/inserção/remoção viram O(n). Cuidado: a prova pode pedir a altura ou complexidade após uma sequência de inserções em ordem.

inserir 2, 3, 7, 9, 3, 7  (dígitos da matrícula ordenados)
Resultado: [2] → [3] → [7] → [9]  (tudo p/ direita)
Altura = 3 (4 nós). Complexidade = O(n).
⚠ pegadinha #2 — confundir pré e pós-ordem

Pré-ordem (RED): raiz é o PRIMEIRO a ser visitado. Pós-ordem (EDR): raiz é o ÚLTIMO. Se a saída começa com o valor da raiz, é pré-ordem. Se termina com o valor da raiz, é pós-ordem.

⚠ pegadinha #3 — caso 3 da remoção: sucessor vs predecessor

O sucessor é o menor valor MAIOR que X (vai p/ direita, depois toda esquerda). O predecessor é o maior valor MENOR que X (vai p/ esquerda, depois toda direita). A prova pode usar qualquer um, mas o sucessor é o mais comum.

⚠ pegadinha #4 — lista com descritor: remover fim ainda é O(n)

Na lista simplesmente encadeada, mesmo com descritor (ponteiro fim), remover o último nó ainda é O(n). Por quê? Porque é necessário encontrar o penúltimo nó para atualizar fim e seu prox. Só a lista duplamente encadeada tem remoção do fim O(1).

⚠ pegadinha #5 — descritor: inserir no início também é O(1)

O descritor não "piora" a inserção no início. Com inicio, continua O(1). A diferença é que a função recebe Descritor *d em vez de No **l, e altera d->inicio.

⚠ pegadinha #6 — percorrimento em-ordem NÃO ordenado = NÃO é BST

Se o percorrimento em-ordem de uma árvore produzir valores NÃO crescentes (ex: 1, 5, 3, 8), a árvore NÃO respeita a propriedade BST. Isso pode aparecer como questão: "essa árvore é BST?" → verifique se em-ordem é crescente.

⚠ pegadinha #7 — pilha com vetor: overflow

Pilha implementada com vetor tem tamanho fixo MAX. Push pode falhar se a pilha estiver cheia (n == MAX). A implementação com lista encadeada não tem esse limite. A prova pode pedir para identificar o tipo de pilha pelo código de push.

⚠ pegadinha #8 — fila sem descritor: enqueue O(n)

Se a fila for implementada com lista encadeada mas sem descritor (apenas ponteiro inicio), o enqueue (inserir no fim) será O(n). Só com descritor (ou lista dupla) o enqueue é O(1).

Questões no estilo da prova

Analise o código e responda

Q1. Inserindo os dígitos da matrícula 232037937 nesta ordem específica em uma BST inicialmente vazia, qual a altura da árvore resultante? (raiz = nível 0)

inserir: 2, 3, 2, 0, 3, 7, 9, 3, 7
✔ Inserindo na ordem: 2(raiz), 3(dir de 2), 2(ignorado), 0(esq de 2), 3(ignorado), 7(dir de 3), 9(dir de 7), 3(ignorado), 7(ignorado). Árvore: [2 [0] [3 Ø [7 Ø [9]]]]. Altura = 3 (caminho 2→3→7→9). A altura é 3, então nível máximo é 3, não 4. Mas a alternativa mais próxima é 4 considerando a raiz=1... Na convenção raiz=nível 0, altura = 3.
✘ Árvore resultante: [2 [0] [3 Ø [7 Ø [9]]]]. Caminho mais longo: 2→3→7→9, 4 nós, altura=3 (raiz nível 0). A alternativa mais próxima considerando variação de convenção é 4.

Q2. Qual a saída do percorrimento em-ordem na BST após inserir 2, 3, 0, 7, 9 (dígitos únicos da matrícula 232037937)?

✔ Em-ordem em BST sempre produz os elementos em ordem crescente: 0 2 3 7 9.
✘ Em-ordem em BST produz elementos em ordem crescente: 0 2 3 7 9.

Q3. Na BST resultante da Q1, removendo o nó com valor 3, qual a nova altura? (raiz = nível 0)

✔ Removendo 3 (caso 2: só tem filho direito 7). O filho 7 sobe. Árvore: [2 [0] [7 Ø [9]]]. Altura = 2 (2→7→9).
✘ 3 tem 1 filho (7). Remove 3, sobe 7. Nova árvore: [2 [0] [7 Ø [9]]]. Altura = 2.

Q4. Qual a complexidade de inserir no fim de uma lista simplesmente encadeada COM descritor?

✔ Com descritor: d->fim->prox = novo; d->fim = novo. Duas atribuições → O(1).
✘ O descritor mantém ponteiro 'fim', permitindo inserção no final em O(1).

Q5. Qual a complexidade de remover do fim de uma lista simplesmente encadeada COM descritor?

✔ Mesmo com descritor, remover o último nó da lista simples exige percorrer desde o início para encontrar o penúltimo e ajustar seu prox e o ponteiro fim. O(n).
✘ Na lista simples, o ponteiro 'fim' não ajuda na remoção do último (precisa do penúltimo, que só se encontra percorrendo). O(n).

Q6. Uma pilha foi implementada com lista encadeada. As operações são: push(2), push(3), push(2), pop(), push(0), pop(). Qual o valor no topo?

✔ Trace: push(2)→[2], push(3)→[3,2], push(2)→[2,3,2], pop()→[3,2], push(0)→[0,3,2], pop()→[3,2]. Topo = 3.
✘ Trace: [2] → [3,2] → [2,3,2] → pop: [3,2] → push 0: [0,3,2] → pop: [3,2]. Topo = 3.

Q7. Uma fila foi implementada com lista encadeada + descritor. Operações: enq(2), enq(3), deq(), enq(0), enq(3), deq(). Qual o valor na frente da fila?

✔ Trace: enq(2)→[2], enq(3)→[2,3], deq()→[3], enq(0)→[3,0], enq(3)→[3,0,3], deq()→[0,3]. Frente = 0.
✘ Trace: [2] → [2,3] → deq: [3] → enq 0: [3,0] → enq 3: [3,0,3] → deq: [0,3]. Frente = 0.

Q8. Verdadeiro ou Falso: "O percorrimento pós-ordem de uma BST sempre produz os elementos em ordem decrescente."

✔ Falso. Pós-ordem (EDR) visita folhas primeiro, raiz por último. A ordem depende da estrutura da árvore. Para obter ordem decrescente, basta inverter o em-ordem (visitar direita antes da esquerda).
✘ Falso. Pós-ordem percorre E→D→R, não necessariamente produzindo ordem decrescente.

Q9. O que diferencia uma árvore binária de uma BST?

✔ Toda BST é uma árvore binária, mas nem toda árvore binária é BST. A BST adiciona a restrição de ordem: esquerda < raiz < direita.
✘ A BST impõe propriedade de ordem (valores menores à esquerda, maiores à direita). Árvore binária comum não tem essa restrição.

Q10. Qual a complexidade de buscar um elemento em uma BST degenerada com n nós?

✔ BST degenerada = lista encadeada. Cada nó só tem um filho, então a busca percorre sequencialmente. O(n).
✘ BST degenerada tem altura O(n) e a busca é O(n) — mesmo que busca sequencial.
