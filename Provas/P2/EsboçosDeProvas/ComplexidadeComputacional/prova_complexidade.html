// questão 01

Qual o valor retornado pela função Q1 ao invocá-la passando o número da sua matrícula como parâmetro de entrada?

int Q1(int m) {
    int c = 0;
    while (m > 0) {
        c++;
        m /= 10;
    }
    return c;
}
parâmetros
  • m = 232037937 (sua matrícula)
✔ CORRETO — resposta: 9 O que o código faz: m /= 10 corta o último dígito a cada volta. Logo, c conta QUANTOS DÍGITOS m tem. Trace: 232037937 → 23203793 → 2320379 → 232037 → 23203 → 2320 → 232 → 23 → 2 → 0 (para) São 9 divisões até zerar → c = 9. Padrão pra prova: while(m>0){ m/=10; } = "conta dígitos". Complexidade: O(log n) — o tamanho do problema cai pela metade (na base 10) a cada iteração.
✘ ERRADO — resposta certa: b) 9 m /= 10 remove o último dígito por iteração e c++ conta cada remoção. 232037937 tem 9 dígitos → 9 iterações → c=9. Não confunda: o loop NÃO soma dígitos nem retorna a matrícula — só conta quantas vezes dá pra dividir por 10. Decore: while(m>0){ c++; m/=10; } retorna nº de dígitos. Complexidade O(log n).
// questão 02

Qual o valor retornado pela função Q2 ao invocá-la passando a quantidade de dígitos da sua matrícula como parâmetro?

int Q2(int n) {
    int c = 0;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            c++;
    return c;
}
parâmetros
  • n = 9 (quantidade de dígitos de 232037937)
✔ CORRETO — resposta: 81 Loop duplo COMPLETO: para cada um dos n valores de i, o j roda n vezes inteiras (j sempre recomeça de 0). Total de incrementos = n × n = 9 × 9 = 81. Esse é o padrão O(n²) clássico. Diferencie do loop triangular (j = i+1), que dá n(n-1)/2 — cai na Q4.
✘ ERRADO — resposta certa: c) 81 j começa SEMPRE em 0 (não em i+1!). Então o loop interno executa n vezes completas para CADA i. Total = n × n = 9 × 9 = 81. 18 seria 2n (dois loops sequenciais). 36 seria n(n-1)/2 (loop triangular com j=i+1). 72 seria n(n-1). Olhe sempre ONDE o j começa — é isso que muda a contagem.

Qual o valor retornado pela função Q4 com n igual à quantidade de dígitos da sua matrícula?

int Q4(int n) {
    int c = 0;
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
            c++;
    return c;
}
parâmetros
  • n = 9
✔ CORRETO — resposta: 36 j começa em i+1 → loop TRIANGULAR. Contagem por i: i=0 → j de 1 a 8 → 8 voltas i=1 → 7 | i=2 → 6 | i=3 → 5 | i=4 → 4 i=5 → 3 | i=6 → 2 | i=7 → 1 | i=8 → 0 Soma: 8+7+6+5+4+3+2+1 = 36 = n(n-1)/2 = 9·8/2. Esse padrão é o nº de comparações do bubble/selection sort — guarda a fórmula n(n-1)/2. Continua O(n²).
✘ ERRADO — resposta certa: c) 36 A diferença está em j = i+1 (não j = 0!). O loop interno encolhe a cada i: i=0→8 voltas, i=1→7, ..., i=8→0. Soma = 8+7+...+1 = n(n-1)/2 = 9·8/2 = 36. 81 seria o loop completo (j=0). 45 é n(n+1)/2 (soma de 1 a 9 — cuidado, aqui é de 1 a 8!). Memorize: j=i+1 → n(n-1)/2 pares.

Qual o valor retornado pela função Q5 ao invocá-la passando os dois últimos dígitos da sua matrícula como parâmetro?

int Q5(int n) {
    if (n <= 1) return 1;
    return 1 + Q5(n / 2);
}
parâmetros
  • n = 37 (dois últimos dígitos de 232037937)
✔ CORRETO — resposta: 6 Recursão que divide por 2 (divisão INTEIRA) e soma 1 por chamada. Trace da pilha: Q5(37) = 1 + Q5(18) Q5(18) = 1 + Q5(9) Q5(9) = 1 + Q5(4) Q5(4) = 1 + Q5(2) Q5(2) = 1 + Q5(1) Q5(1) = 1 ← caso base Voltando: 1+1+1+1+1+1 = 6. É o "loop que divide por 2" em versão recursiva → O(log n), e o retorno ≈ ⌊log₂ n⌋ + 1.
✘ ERRADO — resposta certa: b) 6 Monte a pilha de chamadas com divisão INTEIRA (37/2=18, não 18.5): 37 → 18 → 9 → 4 → 2 → 1(base) São 5 chamadas recursivas + 1 do caso base = 6 níveis, cada um somando 1 → retorno 6. Erro comum: esquecer que o caso base TAMBÉM retorna 1, ou errar 9/2=4 (inteira!). Sempre escreva a pilha inteira.

// questão 07

Qual o valor retornado por Q7 com n = quantidade de dígitos da sua matrícula? E qual a complexidade da função?

int Q7(int n) {
    int c = 0;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            for (int k = 0; k < 10; k++)
                c++;
    return c;
}
parâmetros
  • n = 9
✔ CORRETO — resposta: 810, O(n²) Valor: n × n × 10 = 9 × 9 × 10 = 810. Complexidade: o loop de k vai até 10 — uma CONSTANTE, não depende de n. Constante multiplicativa é descartada no Big-O: O(10·n²) = O(n²). Pegadinha clássica: 3 fors aninhados ≠ O(n³) automático. Só vira n³ se TODOS os limites dependem de n.
✘ ERRADO — resposta certa: b) 810, O(n²) Valor: i roda 9×, j roda 9× por i, k roda 10× por j → 9 × 9 × 10 = 810. (729 seria 9³ — mas k vai até 10, não até n!) Complexidade: k ≤ 10 é constante → some no Big-O. O(n · n · 10) = O(n²). Regra: conte só os loops cujo limite DEPENDE de n. Loop com limite fixo é fator constante → descartado.
// questão 08

Qual o valor retornado por Q8 com n = quantidade de dígitos da sua matrícula? E a complexidade?

int Q8(int n) {
    int c = 0;
    for (int i = 0; i < n; i++)
        c++;
    for (int j = 0; j < 2 * n; j++)
        c++;
    return c;
}
parâmetros
  • n = 9
✔ CORRETO — resposta: 27, O(n) Os loops são SEQUENCIAIS (um depois do outro), não aninhados. Custos SOMAM, não multiplicam: 1º loop: n = 9 voltas 2º loop: 2n = 18 voltas Total: 9 + 18 = 27. Big-O: O(n + 2n) = O(3n) = O(n) — constante 3 descartada. Aninhado → multiplica. Sequencial → soma. Esse é O critério número 1 de análise de loops.
✘ ERRADO — resposta certa: b) 27, O(n) Repare na indentação/chaves: o 2º for NÃO está dentro do 1º. São dois loops em sequência: n + 2n = 9 + 18 = 27. Sequencial = SOMA (O(n)+O(n)=O(n)). Aninhado = MULTIPLICA (O(n)·O(n)=O(n²)). 81 seria se fossem aninhados 9×9. Sempre confira as chaves antes de classificar.

Qual o valor retornado por Q9 ao invocá-la com os dois últimos dígitos da sua matrícula?

int Q9(int n) {
    int c = 0;
    for (int i = 1; i < n; i *= 3)
        c++;
    return c;
}
parâmetros
  • n = 37
✔ CORRETO — resposta: 4 i TRIPLICA: assume 1, 3, 9, 27 — todos < 37 → 4 voltas. Próximo seria 81 ≥ 37 → para. Generalização: i *= k → O(log_k n) iterações. i *= 2 → log₂ | i *= 3 → log₃ | i *= 10 → log₁₀ (que é o mesmo padrão de contar dígitos da Q1!). No Big-O a base do log não importa: O(log₃ n) = O(log n).

// questão 10

Considere as complexidades das questões anteriores. Qual alternativa ordena corretamente do mais lento crescimento (melhor) para o mais rápido crescimento (pior)?

✔ CORRETO Hierarquia que TEM que estar decorada: O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) Ancore nos exemplos da prova: O(1) → acesso v[i] O(log n) → busca binária / loop que dobra (Q3, Q9) O(n) → busca linear / loop simples (Q8) O(n log n)→ merge sort O(n²) → bubble/selection/insertion, loop duplo (Q2, Q4) O(2ⁿ) → fibonacci recursivo ingênuo
✘ ERRADO — resposta certa: b) Ordem fixa (decore!): O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) Pontos onde mais se erra: • log n cresce MAIS DEVAGAR que n (log₂ de 1.000.000 ≈ 20!) • n log n fica ENTRE n e n² (não depois de n²) • O(1) é sempre o menor — constante não cresce. Teste mental com n=1024: log n=10, n=1024, n log n≈10.240, n²≈1.000.000. A ordem fica óbvia.
