// questão 01

Qual o valor retornado pela função Q1? A chave é nome[matricula % 10], ou seja, o caractere do seu nome na posição dada pelo último dígito da sua matrícula.

int Q1(char *s, char chave) {
    int p = 0;
    while (s[p] != '\0') {
        if (s[p] == chave) return p;
        p++;
    }
    return -1;
}
parâmetros
  • s = "italo alves sampaio de oliveira"
  • chave = s[232037937 % 10] = s[7]
✔ CORRETO — resposta: 3 Passo 1 — descobrir a chave: 232037937 % 10 = 7 → chave = nome[7]. i(0) t(1) a(2) l(3) o(4) ' '(5) a(6) l(7) → chave = 'l' Passo 2 — busca linear com return DENTRO do loop: retorna a PRIMEIRA ocorrência. 'l' aparece nas posições 3, 7 e 24. A primeira é a do "ita**l**o" → retorna 3. Pegadinha: a chave veio da posição 7, mas a resposta é onde 'l' aparece PRIMEIRO (posição 3), não 7!
✘ ERRADO — resposta certa: b) 3 Duas etapas separadas: 1) chave = nome[7] = 'l' (conte: i0 t1 a2 l3 o4 ␣5 a6 l7) 2) o return p está DENTRO do while → para na PRIMEIRA ocorrência de 'l', que é a posição 3 ("ita**l**o"). 7 confunde "posição de onde a chave veio" com "posição encontrada". 24 seria a ÚLTIMA ocorrência (isso é a Q2!). -1 só se a letra não existisse no nome.

Qual o valor retornado por Q2 passando seu nome completo e sua matrícula como parâmetros?

char letra(int P) {
    P = P % 26;
    return 'a' + P;
}

int Q2(char *nc, int matricula) {
    int p = 0, posic = -1;
    char chave = letra(matricula % 100);
    while (nc[p] != '\0') {
        if (chave == nc[p])
            posic = p;
        p++;
    }
    return posic;
}
parâmetros
  • nc = "italo alves sampaio de oliveira"
  • matricula = 232037937
✔ CORRETO — resposta: 24 Passo 1 — calcular a chave: matricula % 100 = 37 letra(37): 37 % 26 = 11 → 'a' + 11 = 'l' (a=0, b=1, ..., k=10, l=11) Passo 2 — entender o loop: NÃO há break/return dentro do while! posic é SOBRESCRITO a cada ocorrência → guarda a ÚLTIMA. Passo 3 — ocorrências de 'l': 3, 7 e 24. "...de o**l**iveira" → última = 24. Essa é a diferença Q1 vs Q2: return dentro do loop = primeira; atribuição sem break = última. Caiu na 24.1!
✘ ERRADO — resposta certa: c) 24 Chave: 232037937 % 100 = 37 → letra(37) → 37%26 = 11 → 'a'+11 = 'l' (conte no alfabeto: a0 b1 c2 d3 e4 f5 g6 h7 i8 j9 k10 l11). O detalhe que decide a questão: dentro do while NÃO tem break. posic = p executa TODA vez que acha 'l' → no final guarda a ÚLTIMA ocorrência. 'l' está em 3 ("italo"), 7 ("alves") e 24 ("oliveira"). Resposta: 24. (11 é o resultado de 37%26, não posição!)
// questão 03

Quantas comparações a função Q3 retorna ao buscar a letra 'p' (primeira letra de "sampaio" depois do m) no seu nome completo?

int Q3(char *s, char chave) {
    int p = 0, c = 0;
    while (s[p] != '\0') {
        c++;
        if (s[p] == chave) break;
        p++;
    }
    return c;
}
parâmetros
  • s = "italo alves sampaio de oliveira"
  • chave = 'p'
✔ CORRETO — resposta: 16 Posição do 'p': "italo alves sam**p**aio..." i0 t1 a2 l3 o4 ␣5 a6 l7 v8 e9 s10 ␣11 s12 a13 m14 p15 → 'p' está no índice 15. O contador c++ executa ANTES do if, inclusive na iteração que encontra. Para achar o índice 15, o loop visita os índices 0..15 → 16 iterações → c = 16. Regra: achou no índice k → comparações = k + 1 (índice começa em 0, contagem começa em 1).
✘ ERRADO — resposta certa: b) 16 'p' fica no índice 15 (conte: i0 t1 a2 l3 o4 ␣5 a6 l7 v8 e9 s10 ␣11 s12 a13 m14 p15). MAS a pergunta é o nº de COMPARAÇÕES, não o índice! c++ roda a cada iteração, incluindo a que dá match. Índices visitados: 0,1,2,...,15 → 16 visitas → c=16. Erro clássico de ±1: índice k ⇒ k+1 comparações. 31 seria varrer o nome inteiro (chave inexistente).

Qual o valor retornado por Q4 (número de iterações da busca binária)? O vetor é seu nome ordenado alfabeticamente com os espaços no início, e a chave é nome[matricula % 10] tirada do nome ordenado.

int Q4(char *nome, int tamanho, int matricula) {
    int inicio = 0, meio, fim = tamanho - 1, pcont = 0;
    char chave = nome[matricula % 10];
    while (inicio <= fim) {
        pcont++;
        meio = (inicio + fim) / 2;
        if (chave == nome[meio]) break;
        else if (chave < nome[meio]) fim = meio - 1;
        else inicio = meio + 1;
    }
    return pcont;
}
parâmetros
  • nome = "    aaaaadeeeiiiilllmoooprsstvv" (seu nome ordenado, 31 chars)
  • tamanho = 31
  • matricula = 232037937 → chave = nomeOrdenado[7]
✔ CORRETO — resposta: 2 Passo 1 — a chave: 232037937 % 10 = 7 → chave = nomeOrdenado[7] " aaaaadeee..." → ␣␣␣␣(0-3) a(4) a(5) a(6) a(7) → chave = 'a' Passo 2 — trace da busca binária (tamanho=31): it1: inicio=0 fim=30 → meio=15 → nome[15]='i' 'a' < 'i' → fim = 14 it2: inicio=0 fim=14 → meio=7 → nome[7]='a' 'a' == 'a' → BREAK! pcont = 2. A chave caiu exatamente num meio da 2ª iteração — coincidência boa de prova. Sempre faça o trace, não chute pelo "tamanho do vetor".
✘ ERRADO — resposta certa: b) 2 Trace obrigatório (escreva inicio/fim/meio!): chave: nomeOrdenado[7] = 'a' (ordenado = "␣␣␣␣aaaaadeeeiiiilllmoooprsstvv"; posições 0-3 são espaços, 4-8 são 'a') it1: inicio=0, fim=30 → meio=(0+30)/2=15 → 'i' 'a' < 'i' → busca à esquerda: fim=14 it2: inicio=0, fim=14 → meio=7 → nome[7]='a' = chave → break. pcont=2. 5 seria o PIOR caso (⌈log₂ 32⌉). A questão pede o caso REAL com a sua chave — tem que tracejar.
// questão 05

Busca binária no vetor com os dígitos da sua matrícula ordenados, procurando a chave 9. Qual posição é retornada e em quantas iterações?

int Q5(int v[], int n, int chave) {
    int inicio = 0, fim = n - 1, meio;
    while (inicio <= fim) {
        meio = (inicio + fim) / 2;
        if (v[meio] == chave) return meio;
        else if (chave < v[meio]) fim = meio - 1;
        else inicio = meio + 1;
    }
    return -1;
}
parâmetros
  • v = [0,2,2,3,3,3,7,7,9] (dígitos de 232037937 ordenados)
  • n = 9, chave = 9
✔ CORRETO — posição 8, 4 iterações v = [0,2,2,3,3,3,7,7,9] (índices 0..8) it1: inicio=0 fim=8 → meio=4 → v[4]=3 9 > 3 → inicio=5 it2: inicio=5 fim=8 → meio=6 → v[6]=7 9 > 7 → inicio=7 it3: inicio=7 fim=8 → meio=7 → v[7]=7 9 > 7 → inicio=8 it4: inicio=8 fim=8 → meio=8 → v[8]=9 ✔ → return 8 Buscar o MAIOR elemento força a binária a ir sempre pra direita — quase pior caso. Note it3: meio=(7+8)/2=7 (divisão inteira arredonda pra baixo!).
✘ ERRADO — resposta certa: c) posição 8, 4 iterações O 9 é o último elemento → a busca desce sempre pela direita. Trace completo: it1: meio=(0+8)/2=4, v[4]=3, 9>3 → inicio=5 it2: meio=(5+8)/2=6, v[6]=7, 9>7 → inicio=7 it3: meio=(7+8)/2=7, v[7]=7, 9>7 → inicio=8 it4: meio=(8+8)/2=8, v[8]=9 → achou! return 8 Atenção na it3: (7+8)/2 = 7 em divisão INTEIRA (não 7.5). É exatamente aí que se perde uma iteração na conta.
// questão 06

A função abaixo busca 'z' no seu nome completo e grava em *comp o número de comparações. O que ela retorna, e qual o valor final de comp?

int Q6(char *s, char chave, int *comp) {
    int p = 0;
    *comp = 0;
    while (s[p] != '\0') {
        (*comp)++;
        if (s[p] == chave) return p;
        p++;
    }
    return -1;
}
parâmetros
  • s = "italo alves sampaio de oliveira" (31 chars)
  • chave = 'z' (não existe no seu nome)
✔ CORRETO — retorna -1, comp = 31 'z' não aparece em "italo alves sampaio de oliveira" (tem v, mas não z!). O while varre TODAS as posições 0..30, incrementando comp em cada uma → comp = 31 (strlen do nome). Sai do loop quando s[31]='\0' e retorna -1 (código de "não encontrado"). Pior caso da busca linear = n comparações = O(n). O '\0' NÃO conta como comparação de chave — o teste s[p]!='\0' é a condição do loop, não o if da chave.
✘ ERRADO — resposta certa: b) retorna -1, comp = 31 Sem 'z' no nome → o if nunca dispara → o while roda até s[p]=='\0', visitando os 31 caracteres (índices 0..30). (*comp)++ executa 31 vezes → comp = 31. Depois do loop: return -1. 30 = esqueceu que o índice 30 ('a' final) também é comparado. 32 = contou o '\0' (a condição do while barra ANTES de incrementar). 0 = confundiu retorno com posição 0.

Qual o valor retornado por Q7 buscando o dígito 3 no vetor dos dígitos da sua matrícula (ordem natural)?

int Q7(int v[], int n, int chave) {
    int c = 0;
    for (int i = 0; i < n; i++)
        if (v[i] == chave)
            c++;
    return c;
}

✔ CORRETO — resposta: 3 Sem break, sem return dentro do loop, e c++ só quando acha → a função CONTA OCORRÊNCIAS. 2 3 2 0 3 7 9 3 7 ↑ ↑ ↑ → o dígito 3 aparece 3 vezes (i=1) (i=4) (i=7) Os 3 sabores de busca linear que a prova mistura: • return p no if → PRIMEIRA ocorrência • posic = p (sem break) → ÚLTIMA ocorrência • c++ (sem break) → CONTAGEM Identifique qual é ANTES de tracejar.
✘ ERRADO — resposta certa: c) 3 Olhe a estrutura: c++ dentro do if, sem break/return. Isso é CONTADOR de ocorrências, não posição! Matrícula 232037937 → [2,3,2,0,3,7,9,3,7] O dígito 3 está nos índices 1, 4 e 7 → 3 ocorrências. 1 seria o índice da primeira; 7 o da última. A função não retorna índice nenhum — retorna o CONTADOR c.
// questão 08

A busca binária recursiva abaixo procura a chave 2 nos dígitos ordenados da sua matrícula. Quantas chamadas da função acontecem (incluindo a primeira), e o que ela retorna?

int Q8(int v[], int inicio, int fim, int chave) {
    if (inicio > fim) return -1;
    int meio = (inicio + fim) / 2;
    if (v[meio] == chave) return meio;
    if (chave < v[meio])
        return Q8(v, inicio, meio - 1, chave);
    return Q8(v, meio + 1, fim, chave);
}
parâmetros
  • v = [0,2,2,3,3,3,7,7,9] · chamada: Q8(v, 0, 8, 2)
✔ CORRETO — 2 chamadas, retorna 1 v = [0,2,2,3,3,3,7,7,9] Chamada 1: Q8(v, 0, 8, 2) meio=(0+8)/2=4 → v[4]=3 2 < 3 → Q8(v, 0, 3, 2) Chamada 2: Q8(v, 0, 3, 2) meio=(0+3)/2=1 → v[1]=2 ✔ → return 1 Detalhes que decidem: (0+3)/2 = 1 (divisão inteira!) e o 2 aparece nos índices 1 E 2 — a binária encontra o do índice 1 porque foi o meio calculado. Ela NÃO garante achar a primeira ocorrência de duplicados!
✘ ERRADO — resposta certa: a) 2 chamadas, retorna 1 Trace: Chamada 1: inicio=0 fim=8 → meio=4 → v[4]=3; 2<3 → recursão à esquerda Q8(v,0,3,2) Chamada 2: inicio=0 fim=3 → meio=(0+3)/2=1 (inteira, não 1.5!) → v[1]=2 = chave → return 1 Dois pontos de erro: • (0+3)/2 = 1, não 2 — divisão inteira trunca. • v tem 2 nos índices 1 e 2; a binária retorna o que cair no meio (1), não necessariamente o primeiro.
// questão 09

No pior caso, quantas iterações a busca binária faz num vetor com 31 elementos (o tamanho do seu nome)? E a busca linear?

✔ CORRETO — binária: 5, linear: 31 Binária: a cada iteração o espaço de busca cai pela metade. Com n=31: 31 → 15 → 7 → 3 → 1 → 0 São 5 "cortes" até esgotar → no pior caso 5 iterações. Fórmula: ⌈log₂(n+1)⌉ = ⌈log₂ 32⌉ = 5. (2⁵ = 32 ≥ 31) Linear (pior caso = elemento ausente ou no fim): visita os 31 elementos → 31 comparações. 5 vs 31 — essa razão explode com n: pra n = 1.000.000, binária faz ~20, linear faz 1.000.000.
✘ ERRADO — resposta certa: b) binária: 5, linear: 31 Binária pior caso: quantas vezes 31 cai pela metade até virar 0? 31 → 15 → 7 → 3 → 1 → 0 = 5 cortes → 5 iterações. Atalho: menor k com 2^k ≥ n+1 → 2⁵=32 → k=5. Linear pior caso: varre tudo → 31. (16 seria o caso MÉDIO da linear ≈ n/2; 15 é n/2 da binária — não é assim que ela funciona.)
// questão 10

Sobre a condição necessária para usar busca binária, marque a alternativa correta:

✔ CORRETO A busca binária DEPENDE da ordenação: ao comparar chave < v[meio], ela DESCARTA metade do vetor assumindo que tudo à esquerda é menor e tudo à direita é maior. Vetor desordenado → o descarte joga fora a metade que continha a chave → pode retornar -1 com a chave presente. Por isso a prova sempre manda ordenar o nome ANTES (ex.: " aaaaadeee..."). Repetidos são permitidos (Q8 desta prova!) — só não há garantia de QUAL índice das repetições é retornado. Tamanho par/ímpar é irrelevante: divisão inteira resolve.
✘ ERRADO — resposta certa: b) Pré-requisito ÚNICO e obrigatório: vetor ORDENADO. O descarte de metade só é válido se a ordem garante "esquerda ≤ meio ≤ direita". Sem ordem, a chave pode estar na metade descartada → resultado imprevisível. Repetidos: permitidos (apenas não se sabe qual índice volta). Tamanho ímpar: ok, divisão inteira trunca. Memória contígua: vetores em C já são contíguos — isso não é a condição da binária.
