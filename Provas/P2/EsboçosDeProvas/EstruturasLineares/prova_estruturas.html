Prova — Estruturas Lineares

Lista sequencial, encadeada, dupla, circular, pilha e fila — todas operando sobre os dígitos da sua matrícula. Desenhe os ponteiros a cada linha.

Nome: italo alves sampaio de oliveira Matrícula: 232037937
// instruções — dados base
  • Dígitos da matrícula: [2,3,2,0,3,7,9,3,7]. As questões usam fatias deles (5 primeiros = [2,3,2,0,3], etc.).
  • As funções inserir, remover, inserirInicio, inserirFim e percorrer são as mesmas da teoria (teoria_estruturas_prova.html).
  • Listas encadeadas: DESENHE os nós como caixas [info|→] e atualize as setas a cada operação.
  • Pilha = LIFO (último entra, primeiro sai). Fila = FIFO (primeiro entra, primeiro sai).
// questão 01 — lista sequencial: inserção

A lista sequencial contém os 5 primeiros dígitos da sua matrícula: v=[2,3,2,0,3], n=5, MAX=10. Após inserir(&l, 9, 2) (inserir o dígito 9 — 7º da matrícula — na posição 2), qual o estado?

int inserir(Lista *l, int x, int p) {
    if (l->n == MAX || p < 0 || p > l->n) return 0;
    for (int i = l->n; i > p; i--)
        l->v[i] = l->v[i - 1];
    l->v[p] = x;
    l->n++;
    return 1;
}
✔ CORRETO — [2,3,9,2,0,3], n=6 Deslocamento de TRÁS pra FRENTE (i de n até p+1): [2,3,2,0,3,?] n=5, inserindo 9 na posição 2 i=5: v[5]=v[4]=3 → [2,3,2,0,3,3] i=4: v[4]=v[3]=0 → [2,3,2,0,0,3] i=3: v[3]=v[2]=2 → [2,3,2,2,0,3] i=2: 2>2? FALSO → para v[2]=9 → [2,3,9,2,0,3] n++ → 6 Posição 2 = TERCEIRA casa (índices começam em 0). Os elementos das posições 2,3,4 andaram uma casa pra direita; posições 0 e 1 ficaram paradas.
✘ ERRADO — resposta certa: b) [2,3,9,2,0,3], n=6 "Posição 2" é o ÍNDICE 2 — a terceira casa, não a segunda! O que estava em v[2..4] ([2,0,3]) anda uma casa pra direita, abrindo o buraco: [2,3,2,0,3] → desloca → [2,3,_,2,0,3] → v[2]=9 → [2,3,9,2,0,3], n=6. Trace do for (de trás pra frente): v[5]←v[4], v[4]←v[3], v[3]←v[2], para quando i==p. Se deslocasse de frente pra trás, sobrescreveria o 0 e o 3.
// questão 02 — lista sequencial: remoção

Na lista v=[2,3,2,0,3], n=5, executa-se remover(&l, 3) — remover a posição 3 (não o valor 3!). Qual o estado final?

int remover(Lista *l, int p) {
    if (p < 0 || p >= l->n) return 0;
    for (int i = p; i < l->n - 1; i++)
        l->v[i] = l->v[i + 1];
    l->n--;
    return 1;
}
✔ CORRETO — [2,3,2,3], n=4 PEGADINHA clássica: o parâmetro é a POSIÇÃO (índice), não o valor! v[3] = 0 → é o 0 que sai. Trace (desloca de frente pra trás, de p até n-2): i=3: v[3]=v[4]=3 → [2,3,2,3,3] i=4: 4 < 4? FALSO → para n-- → n=4 Parte válida: [2,3,2,3]. O v[4]=3 ainda existe na memória, mas está FORA da lista (n=4 ignora ele). Sempre leia o enunciado: remover posição ≠ remover valor.
✘ ERRADO — resposta certa: b) [2,3,2,3], n=4 O parâmetro 3 é POSIÇÃO (índice do vetor), não valor! v = [2,3,2,0,3] 0 1 2 3 4 ← v[3] = 0 → o 0 é removido. Deslocamento: v[3] ← v[4]=3, e n cai pra 4. Resultado: [2,3,2,3]. Remover por VALOR seria outra função (com busca antes). A prova alterna entre as duas pra pegar desatento — sublinhe no enunciado qual é o caso.
// questão 03 — encadeada: inserirInicio

Os 4 primeiros dígitos da sua matrícula (2, 3, 2, 0 — nessa ordem) são inseridos com inserirInicio. Qual a saída de percorrer(inicio)?

No *inicio = NULL;
inserirInicio(&inicio, 2);
inserirInicio(&inicio, 3);
inserirInicio(&inicio, 2);
inserirInicio(&inicio, 0);
percorrer(inicio);
✔ CORRETO — saída: 0 2 3 2 inserirInicio empurra a lista pra trás a cada chamada: insere 2 → [2] insere 3 → [3, 2] insere 2 → [2, 3, 2] insere 0 → [0, 2, 3, 2] percorrer imprime do início ao fim: 0 2 3 2. Regra: inserirInicio N vezes = ordem INVERTIDA da inserção. O último inserido (0) vira o primeiro. Cuidado com os dígitos repetidos (2 aparece 2x) — não "agrupam", cada um fica onde a inversão mandar.
✘ ERRADO — resposta certa: b) 0 2 3 2 Cada inserirInicio coloca o novo nó NA FRENTE: [2] → [3,2] → [2,3,2] → [0,2,3,2] A ordem de saída é a INVERSA da ordem de inserção: inseriu 2,3,2,0 → imprime 0,2,3,2. Não existe "agrupamento" de valores iguais — lista preserva posição, não ordena. Refaça desenhando a lista após CADA inserção.
// questão 04 — encadeada: misto início/fim

Agora misturando inserirFim (F) e inserirInicio (I) com os 4 primeiros dígitos. Qual a saída de percorrer(inicio)?

No *inicio = NULL;
inserirFim(&inicio, 2);      // F
inserirInicio(&inicio, 3);   // I
inserirFim(&inicio, 2);      // F
inserirInicio(&inicio, 0);   // I
percorrer(inicio);
✔ CORRETO — saída: 0 3 2 2 Trace operação por operação: F(2): lista vazia → [2] I(3): 3 entra na frente → [3, 2] F(2): 2 entra no fim → [3, 2, 2] I(0): 0 entra na frente → [0, 3, 2, 2] percorrer: 0 3 2 2. Quando mistura I e F, não dá pra usar a regra de "inverte tudo" — tem que simular UMA POR UMA. F põe no fim (caminha até o último), I põe na frente (O(1)).
✘ ERRADO — resposta certa: c) 0 3 2 2 Com I e F misturados, simule na ordem exata: F(2) → [2] (fim de lista vazia = único nó) I(3) → [3,2] (3 na frente) F(2) → [3,2,2] (2 no fim) I(0) → [0,3,2,2] (0 na frente) Erros comuns: aplicar "inversão total" (só vale se TODAS forem inserirInicio) ou esquecer que F em lista vazia também funciona (vira o primeiro nó).
// questão 05 — encadeada: remoção por valor

A lista contém os 5 primeiros dígitos na ordem natural: [2]→[3]→[2]→[0]→[3]→NULL. Após remover(&inicio, 3) (remover por valor), qual a saída de percorrer?

int remover(No **l, int valor) {
    No *ant = NULL, *atu = *l;
    while (atu != NULL && atu->info != valor) {
        ant = atu;
        atu = atu->prox;
    }
    if (atu == NULL) return 0;
    if (ant == NULL) *l = atu->prox;
    else ant->prox = atu->prox;
    free(atu);
    return 1;
}
✔ CORRETO — saída: 2 2 0 3 O while para na PRIMEIRA ocorrência (atu->info != valor falha) e a função retorna depois de UM free — não há loop de remoção múltipla. Trace: [2]→[3]→[2]→[0]→[3] it1: atu=[2], 2≠3 → ant=[2], atu=[3] it2: atu=[3], 3==3 → PARA ant=[2] (≠NULL) → ant->prox = atu->prox → o nó [2] inicial aponta direto pro [2] seguinte free([3]) Lista: [2]→[2]→[0]→[3] → saída 2 2 0 3. O SEGUNDO 3 (último nó) fica intacto!
✘ ERRADO — resposta certa: a) 2 2 0 3 Olhe a estrutura: a função tem UM return 1 após UM free — ela remove apenas a PRIMEIRA ocorrência e sai. Para remover todas, precisaria de outro loop. Busca: para no primeiro 3 (segundo nó). ant = nó [2] inicial → ant->prox pula o [3]: [2]→[2]→[0]→[3]. O 3 do final continua lá. Remover por valor ≠ remover posição (Q2!) ≠ remover todas — identifique qual é ANTES de tracejar.
// questão 06 — pilha (LIFO)

Os 5 primeiros dígitos da matrícula entram numa pilha (push 2, 3, 2, 0, 3). Depois executa-se a sequência abaixo. O que é impresso, e qual o topo final?

printf("%d ", pop(&p));
printf("%d ", pop(&p));
push(&p, 7);
printf("%d ", pop(&p));
estado inicial
  • pilha (fundo → topo): 2, 3, 2, 0, 3
✔ CORRETO — imprime 3 0 7, topo final = 2 Pilha é LIFO: pop tira do TOPO (último que entrou). Estado (fundo→topo): 2 3 2 0 3 pop → sai 3 (topo) → 2 3 2 0 pop → sai 0 → 2 3 2 push(7) → 2 3 2 7 pop → sai 7 → 2 3 2 topo final = 2. O 7 entrou e saiu IMEDIATAMENTE — quem entra por último sai primeiro. Os dígitos do fundo (2,3) nunca foram tocados.
✘ ERRADO — resposta certa: b) 3 0 7, topo = 2 LIFO: o pop SEMPRE tira o último que entrou (o topo), nunca o primeiro. Push 2,3,2,0,3 deixa o 3 no topo. pop→3, pop→0 (pilha: 2,3,2) push 7 (pilha: 2,3,2,7) pop→7 (o 7 acabou de entrar — sai primeiro!) Pilha final: 2,3,2 → topo = 2. "2 3 ..." seria FILA (FIFO). Não confunda: pilha tira de cima, fila tira da frente.
// questão 07 — fila (FIFO)

Agora os 4 primeiros dígitos entram numa fila (enqueue 2, 3, 2, 0). Executa-se a sequência abaixo. O que é impresso, e quem fica na frente da fila?

printf("%d ", dequeue(&f));
printf("%d ", dequeue(&f));
enqueue(&f, 7);
printf("%d ", dequeue(&f));
estado inicial
  • fila (frente → trás): 2, 3, 2, 0
✔ CORRETO — imprime 2 3 2, frente final = 0 Fila é FIFO: dequeue tira da FRENTE (primeiro que entrou). enqueue põe no FIM. Fila (frente→trás): 2 3 2 0 deq → sai 2 → 3 2 0 deq → sai 3 → 2 0 enq(7) entra ATRÁS → 2 0 7 deq → sai 2 → 0 7 Frente final = 0. O 7 NÃO sai — ele entrou por último, está no fim da fila. Compare com a Q6: na pilha o 7 saiu na hora. Essa dupla pilha/fila com mesma sequência é pegadinha recorrente.
✘ ERRADO — resposta certa: a) 2 3 2, frente = 0 FIFO: sai sempre o MAIS ANTIGO (a frente da fila), e quem chega (enqueue) entra no FIM. deq→2 (primeiro que entrou), deq→3, enq(7) vai pro fim [2,0,7], deq→2. Sobra [0,7], frente = 0. Se você pensou "0 2 7" ou "...7", aplicou lógica de PILHA. Fila: pense em fila de banco — o 7 que acabou de chegar espera atrás de todo mundo.
// questão 08 — lista circular

Lista circular com os 3 primeiros dígitos: [2]→[3]→[2]→(volta ao primeiro). O percorrimento abaixo começa em inicio->prox (não em inicio!). O que é impresso?

No *atu = inicio->prox;          // começa no SEGUNDO nó!
do {
    printf("%d ", atu->info);
    atu = atu->prox;
} while (atu != inicio->prox);   // para ao voltar ao ponto de partida
✔ CORRETO — saída: 3 2 2 O ponto de partida mudou: atu = inicio->prox = nó [3]. Numa circular, dá pra começar de QUALQUER nó e visitar todos — a condição de parada é "voltei ao ponto de partida". Nós: A[2] → B[3] → C[2] → A (circular) atu = B imprime 3, atu = C C ≠ B → continua: imprime 2, atu = A A ≠ B → continua: imprime 2, atu = B B == B → PARA Saída: 3 2 2 — os mesmos 3 elementos, começando do 2º. O do-while garante a 1ª impressão antes do teste.
✘ ERRADO — resposta certa: b) 3 2 2 Leia a primeira linha: atu = inicio->PROX → o percorrimento começa no SEGUNDO nó (valor 3), não no inicio! A condição de parada também compara com inicio->prox (o ponto de partida), então a volta é completa: B[3] → C[2] → A[2] → volta a B → para. Imprime 3 2 2 (3 elementos, ordem rotacionada). "nada" seria com WHILE simples começando igual ao alvo — aqui é DO-while, sempre roda ao menos 1 vez.
// questão 09 — ponteiro para ponteiro

A lista contém [3]→[7]→NULL (dois últimos dígitos pares de posição da matrícula). Chama-se inserirErrado(inicio, 9) e depois percorrer(inicio). O que é impresso?

void inserirErrado(No *l, int valor) {
    No *novo = (No*) malloc(sizeof(No));
    novo->info = valor;
    novo->prox = l;
    l = novo;            // ← modifica só a cópia local!
}

// na main:
inserirErrado(inicio, 9);
percorrer(inicio);
✔ CORRETO — saída: 3 7 A função recebe No *l — uma CÓPIA do ponteiro inicio. Dentro da função: novo->prox = l → o nó [9] aponta pra [3] ✓ l = novo → muda a CÓPIA local, não o inicio! Quando a função retorna, a cópia morre. O inicio da main continua apontando pra [3]→[7]. Consequências: 1) percorrer imprime 3 7 (lista intacta) 2) o nó [9] ficou alocado SEM ninguém apontando pra ele = MEMORY LEAK (nó órfão). Pra funcionar: No **l na assinatura, *l = novo no corpo, e &inicio na chamada. É A pegadinha de **l.
✘ ERRADO — resposta certa: b) 3 7 Parâmetros em C são passados POR VALOR — No *l é uma cópia do ponteiro. l = novo troca o valor da cópia; a variável inicio da main nem fica sabendo. Compila normalmente (atribuição válida), o 9 NÃO entra na lista (nem no início nem no fim), e o malloc do nó [9] vira vazamento de memória. Versão correta: void inserir(No **l, ...) com *l=novo e chamada inserir(&inicio, 9). Compare Q9 com a sua inserirInicio — a diferença é exatamente o **.
// questão 10 — lista duplamente encadeada

Lista dupla: NULL←[2]⇄[3]⇄[7]→NULL. Após remover(&inicio, 3) (remoção por valor, com atualização de ant e prox), qual o valor de inicio->prox->ant->info?

// após a busca, atu aponta para o nó [3]:
if (atu->ant != NULL)
    atu->ant->prox = atu->prox;
else
    *l = atu->prox;
if (atu->prox != NULL)
    atu->prox->ant = atu->ant;
free(atu);
✔ CORRETO — resposta: 2 Estado antes: NULL←[2]⇄[3]⇄[7]→NULL, atu = [3]. Linha 1: atu->ant = [2] ≠ NULL → [2]->prox = atu->prox = [7] (2 pula o 3) Linha 2: atu->prox = [7] ≠ NULL → [7]->ant = atu->ant = [2] (7 aponta de volta pro 2) free([3]) Estado final: NULL←[2]⇄[7]→NULL Decompondo a expressão: inicio = [2] inicio->prox = [7] inicio->prox->ant = [2] inicio->prox->ant->info = 2 ✓ Os DOIS lados foram religados — é o par de ifs que mantém a consistência da lista dupla.
✘ ERRADO — resposta certa: a) 2 A remoção na lista dupla atualiza DOIS ponteiros: • [2]->prox passa a apontar pra [7] (pula o 3) • [7]->ant passa a apontar pra [2] (linha atu->prox->ant = atu->ant) Se a 2ª atualização não existisse, aí sim [7]->ant apontaria pro nó liberado (ponteiro pendurado — bug da pegadinha #5 da teoria). Mas o código FAZ a atualização. Caminho: inicio=[2] → prox=[7] → ant=[2] → info=2. Resolva expressões encadeadas um -> por vez, da esquerda pra direita.
