// questão 01 — estilo exato da Q4 da prova 24.1

Qual o valor retornado por Q1 passando seu primeiro nome e a quantidade de letras dele?

int Q1(char *vet, int count) {
    int pcont = 0;
    char aux;
    for (int i = 0; i < count; i++)
        for (int j = i+1; j < count; j++)
            if (vet[i] < vet[j]) {
                aux = vet[i]; vet[i] = vet[j]; vet[j] = aux;
                pcont++;
            }
    return pcont;
}

  • vet = "italo" · count = 5
✔ CORRETO — resposta: 6 vet[i] < vet[j] + swap → ordena DECRESCENTE. Trace completo de "italo": i=0: j=1 'i'<'t'? SIM → troca → "tialo" (1) j=2 't'<'a'? não | j=3 't'<'l'? não | j=4 't'<'o'? não i=1: j=2 'i'<'a'? não j=3 'i'<'l'? SIM → troca → "tlaio" (2) j=4 'l'<'o'? SIM → troca → "toail" (3) i=2: j=3 'a'<'i'? SIM → troca → "toial" (4) j=4 'i'<'l'? SIM → troca → "tolai" (5) i=3: j=4 'a'<'i'? SIM → troca → "tolia" (6) pcont = 6. CUIDADO: depois de cada troca, vet[i] MUDA — as próximas comparações usam o valor novo!
✘ ERRADO — resposta certa: c) 6 Erro mais comum: esquecer que após a troca, vet[i] tem um valor NOVO, e as comparações seguintes do mesmo i usam esse valor novo. // questão 03

Ainda sobre o código da Q1: qual o tipo de ordenação e o sentido? (Terceira pergunta da Q4 da 24.1: "qual tipo de ordenação da função?")

✔ CORRETO Como identificar cada um na prova (assinaturas): TROCA/SELECTION: for i + for j=i+1 + if(v[i] ? v[j]) swap → compara a posição i com TODAS as seguintes. (selection sort otimizado só troca 1x por i, com min/max; este troca toda hora = "troca direta" / exchange sort) BUBBLE: if (v[j] > v[j+1]) — compara VIZINHOS adjacentes. INSERTION: chave = v[i]; while (j>=0 && v[j] > chave) → desloca e insere. Sentido: v[i] < v[j] + swap → DECRESCENTE. v[i] > v[j] + swap → crescente.
✘ ERRADO — resposta certa: b) Identifique pela ASSINATURA do código: • Bubble compara VIZINHOS: v[j] vs v[j+1]. Aqui não — compara v[i] com v[j] para todo j>i. • Insertion tem "chave" + while deslocando. Não tem. • Merge é recursivo com divisão. Não é. • O código compara a posição i com todas as posteriores e troca → ordenação por TROCA (selection variante). Sentido: v[i] < v[j] → traz os MAIORES pra frente → DECRESCENTE. Decore: o sinal da comparação dita o sentido.
// questão 04 — estilo exato da Q5 da prova 24.1

Qual o valor retornado por Q4 passando seu último nome ("oliveira") e tamanho = 8?

int Q4(char vetor[], int tamanho) {
    int trocas = 0, j, i;
    char chave;
    for (i = 1; i < tamanho; i++) {
        chave = vetor[i];
        j = i-1;
        while (j >= 0 && vetor[j] > chave) {
            vetor[j+1] = vetor[j];
            j--; trocas++;
        }
        vetor[j+1] = chave;
    }
    return trocas;
}

✔ CORRETO — resposta: 18 INSERTION SORT: trocas conta DESLOCAMENTOS (cada vetor[j+1]=vetor[j]). Trace de "oliveira": i=1 chave='l': 'o'>'l' desloca(1) → "loiveira" i=2 chave='i': 'o'(2),'l'(3) deslocam → "iloveira" i=3 chave='v': 'o'>'v'? não → 0 desloc. → "iloveira" i=4 chave='e': 'v','o','l','i' (4)=7 → "eilovira" i=5 chave='i': 'v','o','l' (3)=10 → "eiilovra" i=6 chave='r': 'v' (1)=11 → "eiilorva" i=7 chave='a': TODOS: v,r,o,l,i,i,e (7)=18→ "aeiilorv" Total: 1+2+0+4+3+1+7 = 18. O 'a' no final é o pior elemento possível: atravessa a string inteira (7 deslocamentos).
✘ ERRADO — resposta certa: c) 18 Conte os deslocamentos por iteração (i = 1 a 7): chave 'l'→1 | 'i'→2 | 'v'→0 | 'e'→4 | 'i'→3 | 'r'→1 | 'a'→7 (o 'a' final passa por cima de TUDO) 1+2+0+4+3+1+7 = 18. String final: "aeiilorv". Erros típicos: esquecer que 'v' não desloca nada (já está no lugar), ou subcontar o 'a' final — ele desloca as 7 letras anteriores. Faça o trace completo, i por i.

// questão 06

O bubble sort abaixo (com flag) recebe os dígitos da sua matrícula já ordenados: [0,2,2,3,3,3,7,7,9]. Quantas passadas (voltas do while) ele executa?

int Q6(int v[], int n) {
    int passes = 0, trocou = 1, aux;
    while (trocou) {
        trocou = 0;
        passes++;
        for (int i = 0; i < n-1; i++)
            if (v[i] > v[i+1]) {
                aux = v[i]; v[i] = v[i+1]; v[i+1] = aux;
                trocou = 1;
            }
    }
    return passes;
}
parâmetros
  • v = [0,2,2,3,3,3,7,7,9] (já ordenado!) · n = 9
✔ CORRETO — resposta: 1 O while só roda enquanto trocou==1. Na 1ª passada: v já está ordenado → nenhum v[i] > v[i+1] → nenhuma troca → trocou permanece 0 → while encerra. passes = 1. O algoritmo PRECISA dessa passada para DESCOBRIR que está ordenado — não existe "0 passadas". É isso que faz o melhor caso do bubble com flag ser O(n): uma única varredura. Sem a flag, seria O(n²) mesmo com tudo ordenado.
✘ ERRADO — resposta certa: b) 1 0 é impossível: trocou inicia em 1, então o while SEMPRE executa ao menos uma vez. Nessa primeira passada o vetor já está ordenado → zero trocas → trocou fica 0 → para. Total: 1 passada. n-1 passadas é o PIOR caso (vetor invertido), não o melhor. A flag "trocou" é justamente a otimização que detecta vetor pronto em UMA passada → melhor caso O(n).
// questão 07

O selection sort abaixo (troca só quando necessário) ordena os dígitos da sua matrícula [2,3,2,0,3,7,9,3,7]. Quantas trocas efetivas ele faz?

int Q7(int v[], int n) {
    int trocas = 0, min, aux;
    for (int i = 0; i < n-1; i++) {
        min = i;
        for (int j = i+1; j < n; j++)
            if (v[j] < v[min]) min = j;
        if (min != i) {
            aux = v[i]; v[i] = v[min]; v[min] = aux;
            trocas++;
        }
    }
    return trocas;
}
parâmetros
  • v = [2,3,2,0,3,7,9,3,7] · n = 9
✔ CORRETO — resposta: 6 Selection: acha o MENOR do trecho [i..n-1] e troca com v[i] — no máximo 1 troca por i. O if(min!=i) PULA a troca quando o menor já está no lugar. Trace ([2,3,2,0,3,7,9,3,7]): i=0: menor=0 (idx 3) ≠ 0 → troca → [0,3,2,2,3,7,9,3,7] (1) i=1: menor=2 (idx 2) ≠ 1 → troca → [0,2,3,2,3,7,9,3,7] (2) i=2: menor=2 (idx 3) ≠ 2 → troca → [0,2,2,3,3,7,9,3,7] (3) i=3: menor=3 (idx 3) = i → NÃO troca i=4: menor=3 (idx 4) = i → NÃO troca i=5: menor=3 (idx 7) ≠ 5 → troca → [0,2,2,3,3,3,9,7,7] (4) i=6: menor=7 (idx 7) ≠ 6 → troca → [0,2,2,3,3,3,7,9,7] (5) i=7: menor=7 (idx 8) ≠ 7 → troca → [0,2,2,3,3,3,7,7,9] (6) 6 trocas. Selection faz POUCAS trocas (≤ n-1), mas SEMPRE n(n-1)/2 = 36 comparações.
✘ ERRADO — resposta certa: b) 6 O if(min != i) evita trocas desnecessárias: quando o menor do trecho já está na posição i, não conta troca. Isso acontece 2 vezes (i=3 e i=4, onde o 3 já estava no lugar) → 8 possíveis − 2 puladas = 6 trocas. 36 é o nº de COMPARAÇÕES (n(n-1)/2) — o enunciado pede TROCAS. Diferencie sempre: selection = muitas comparações, poucas trocas.

// questão 10

O insertion sort da Q4 recebe um vetor já ordenado de tamanho n. Quantos deslocamentos (trocas) ele faz, e quantas comparações vetor[j] > chave?

✔ CORRETO — 0 deslocamentos, n−1 comparações Vetor ordenado: para cada i (de 1 a n−1), a chave já é ≥ vetor[i−1]. O while testa vetor[j] > chave UMA vez, dá falso, e nem entra no corpo: • comparações: 1 por i → n−1 no total • deslocamentos: 0 Por isso o melhor caso do insertion é O(n) — ele é o algoritmo ideal pra vetor "quase ordenado". É também o motivo de trocas=0 não significar "não rodou": ele PERCORREU o vetor todo verificando.
✘ ERRADO — resposta certa: b) Com vetor ordenado, a condição vetor[j] > chave é FALSA logo na primeira verificação de cada i → o while não executa o corpo → 0 deslocamentos. Mas a COMPARAÇÃO acontece: uma por iteração do for (n−1 vezes). Não é 0 comparações — o algoritmo precisa checar pra saber que não desloca. n(n−1)/2 seria o PIOR caso (vetor invertido), onde cada chave atravessa todo o trecho ordenado.
