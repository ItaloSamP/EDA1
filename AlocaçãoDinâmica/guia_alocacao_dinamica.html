// 01

Por que alocar memória dinamicamente?

analogia do dia a dia

Imagine que você vai fazer uma festa e precisa reservar mesas. Se você reservar sempre 100 mesas, vai desperdiçar espaço quando só vier 10 pessoas. Se reservar só 10, vai faltar espaço quando vierem 200. A solução ideal é reservar mesas conforme as pessoas chegam. Isso é alocação dinâmica.

Quando você escreve int vetor[100];, está reservando espaço para exatamente 100 inteiros em tempo de compilação. O problema é que às vezes o tamanho necessário só é conhecido quando o programa já está rodando.

📌 Alocação estática: tamanho definido no código, em tempo de compilação. Simples, mas inflexível.

📌 Alocação dinâmica: tamanho definido em tempo de execução. Flexível, mas exige cuidado com o gerenciamento da memória.

Exemplos práticos onde o tamanho só é conhecido em tempo de execução:

✔ Carregar todos os registros de um arquivo (quantos tem? depende do arquivo)

✔ Criar uma matriz cujas dimensões o usuário digita

✔ Construir uma lista que cresce conforme dados são inseridos

// 02

Mapa da memória de um programa

Todo programa em execução divide a memória RAM em regiões com funções bem definidas. Entender isso é essencial para compreender onde a alocação dinâmica acontece.

Endereços altos ┌──────────────────────────────────────────┐ │ │ │ HEAP (Montículo) │ alocação dinâmica │ malloc / calloc / realloc atuam AQUI │ cresce para baixo │ Você controla manualmente │ │ │ ├──────────────────────────────────────────┤ │ (espaço livre entre heap e pilha) │ ├──────────────────────────────────────────┤ │ │ │ PILHA (Stack) │ variáveis locais e │ Variáveis locais e parâmetros │ frames de funções │ Gerenciada automaticamente pelo C │ cresce para cima │ │ ├──────────────────────────────────────────┤ │ Segmento de Dados │ variáveis globais ├──────────────────────────────────────────┤ │ Segmento de Código (código compilado) │ instruções do programa └──────────────────────────────────────────┘ Endereços baixos

A Pilha (Stack) é automática: o C cria e destrói os frames sozinho. O Heap é manual: você pede a memória com malloc e deve devolvê-la com free. Esquecer de devolver é um memory leak (vazamento de memória).

// 03

Ponteiros — o controle remoto da memória

Para usar alocação dinâmica, você precisa de ponteiros. Um ponteiro é uma variável que armazena um endereço de memória. Ele não guarda o dado em si, mas sim a localização de onde o dado está.

analogia

Um ponteiro é como o endereço de uma casa. Você não carrega a casa no bolso. Você carrega o endereço que te diz onde ela está. Com o endereço em mãos, você consegue ir lá e modificar o que está dentro.

declaração e uso básico de ponteiros
int  x = 42;         /* variável comum: guarda o valor 42           */
int *p = &x;         /* ponteiro: guarda o endereço de x            */

printf("%d\n", x);   /* imprime 42  (o valor direto)                */
printf("%p\n", p);   /* imprime 0x7fff... (o endereço)              */
printf("%d\n", *p);  /* imprime 42  (desreferência: vai ao endereço)*/

*p = 100;            /* muda o valor em x através do ponteiro       */
printf("%d\n", x);   /* imprime 100 (x foi modificado!)             */
Memória RAM: Endereço Conteúdo Variável ────────────────────────────────── 0x1000 | 42 | x (o inteiro) 0x1004 | 0x1000 | p (guarda o endereço de x) p ──────────────────────► x (42) "p aponta para x"

* na declaração: cria um ponteiro. Exemplo: int *p;

* em uso: acessa o valor apontado (desreferência). Exemplo: *p = 100;

& em uso: obtém o endereço de uma variável. Exemplo: &x

Ponteiros e vetores em C

Em C, o nome de um vetor é um ponteiro para o primeiro elemento. Por isso vetores dinâmicos funcionam com ponteiros.

int vet[5] = {10, 20, 30, 40, 50};
int *p = vet;           /* p aponta para vet[0]                       */

printf("%d\n", vet[2]); /* 30 — notação de índice                     */
printf("%d\n", *(p+2)); /* 30 — aritmética de ponteiro (equivalente!) */

Passar por referência usando ponteiro permite que uma função modifique o valor original de uma variável, em vez de trabalhar com uma cópia.

passagem por referência — modificando struct dentro de uma função
void dobrarIdade(Aluno *a) {
    a->idade = a->idade * 2;  /* modifica o original, não uma cópia */
}

int main() {
    Aluno al = {"Ana", 20};
    dobrarIdade(&al);          /* passa o endereço de al             */
    printf("%d\n", al.idade);  /* imprime 40                         */
}
// 04

malloc() — alocando memória

malloc (Memory ALLOCation) reserva um bloco de bytes contíguos no Heap e retorna um ponteiro para o início desse bloco. A memória alocada não é inicializada e pode conter qualquer valor ("lixo").

sintaxe
void* malloc(size_t qtde_bytes);
/* Retorna ponteiro para o bloco, ou NULL se falhar */
padrão de uso
tipo *nome = (tipo *) malloc(sizeof(tipo) * quantidade);
exemplo completo com verificação de erro
#include <stdlib.h>
#include <stdio.h>

int main() {
    int  n;
    int *vetor;

    printf("Quantos elementos? ");
    scanf("%d", &n);

    vetor = (int *) malloc(sizeof(int) * n);

    if (vetor == NULL) {          /* SEMPRE verifique! */
        printf("Sem memoria!\n");
        return 1;
    }

    for (int i = 0; i < n; i++)
        vetor[i] = i * 10;         /* usa igual a um vetor normal */

    free(vetor);
    vetor = NULL;
    return 0;
}
Depois de malloc(sizeof(int) * 4): Heap: [ bloco alocado ....... livre ....... ] ↑ vetor aponta aqui vetor[0] vetor[1] vetor[2] vetor[3] [ ??? ] [ ??? ] [ ??? ] [ ??? ] conteúdo indefinido (lixo) — não inicializado!
O cast (int *) antes do malloc não é obrigatório em C, mas é boa prática incluí-lo para deixar o código mais legível e explícito.
// 05

calloc() — alocando e zerando

calloc (Contiguous ALLOCation) funciona como malloc, mas recebe dois argumentos separados (quantidade e tamanho de cada elemento) e inicializa toda a memória com zero.

sintaxe
void* calloc(size_t qtde_elementos, size_t tamanho_cada);
/* Retorna ponteiro para o bloco zerado, ou NULL se falhar */
malloc — memória com lixo
int *v = (int*)
  malloc(4 * sizeof(int));

/* v[0..3] = ??? (lixo) */
calloc — tudo zero
int *v = (int*)
  calloc(4, sizeof(int));

/* v[0..3] = 0  garantido */
FunçãoArgumentosInicializa?Quando usar
malloctotal de bytesNão (lixo)Quando vai preencher todos os valores logo em seguida
callocquantidade + tamanho unitárioSim (zeros)Quando precisa garantir que começa com tudo zerado
exemplo comparando os dois
#include <stdlib.h>

int main() {
    int *Vet1, *Vet2;

    Vet1 = (int*) malloc(100 * sizeof(int));  /* 100 ints com lixo */
    Vet2 = (int*) calloc(100, sizeof(int));   /* 100 ints zerados  */

    free(Vet1);  Vet1 = NULL;
    free(Vet2);  Vet2 = NULL;
    return 0;
}
// 06

realloc() — redimensionando o bloco

E quando o vetor fica cheio e você precisa de mais espaço? É para isso que existe o realloc. Ele redimensiona um bloco de memória já existente, preservando o conteúdo original.

sintaxe
void* realloc(void *ptr, size_t novo_tamanho_em_bytes);
/* ptr: ponteiro para o bloco existente
   novo_tamanho: tamanho desejado em bytes
   Retorna: ponteiro para o novo bloco (pode ser diferente do original!) */
analogia

Imagine que você alugou um apartamento de 2 quartos. Quando a família cresceu, você precisou de 4 quartos. O realloc é como o processo de mudar para um apartamento maior, carregando todos os móveis. Se houver espaço no mesmo corredor, fica no mesmo lugar. Se não houver, você se muda para outro andar e o endereço muda.

exemplo — vetor que cresce sob demanda
#include <stdlib.h>
#include <stdio.h>

int main() {
    int  tamanho = 4;
    int  ocupacao = 0;
    int *vetor = (int*) malloc(tamanho * sizeof(int));

    for (int i = 0; i < 10; i++) {

        if (ocupacao == tamanho) {       /* vetor cheio! */
            tamanho = tamanho * 2;       /* dobra o tamanho */

            int *tmp = (int*) realloc(vetor, tamanho * sizeof(int));

            if (tmp == NULL) {           /* realloc falhou */
                free(vetor);
                return 1;
            }
            vetor = tmp;                 /* atualiza o ponteiro! */
        }

        vetor[ocupacao] = i * 10;
        ocupacao++;
    }

    free(vetor);
    vetor = NULL;
    return 0;
}
Nunca faça: vetor = realloc(vetor, novo_tam); diretamente. Se o realloc falhar, ele retorna NULL e você perde o ponteiro original, causando memory leak. Sempre use uma variável temporária como no exemplo acima.
Antes do realloc (tamanho=4, cheio): Heap: [ 0 | 10 | 20 | 30 ] ↑ sem espaço para inserir Depois de realloc(vetor, 8 * sizeof(int)): Caso 1 — havia espaço contíguo: Heap: [ 0 | 10 | 20 | 30 | | | | ] mesmo endereço Caso 2 — sem espaço contíguo: Heap: [livre] [ 0 | 10 | 20 | 30 | | | | ] novo endereço — vetor aponta para cá agora
// 07

free() e memory leak — devolvendo a memória

free() libera o bloco apontado pelo ponteiro, devolvendo-o ao Heap. Sem ela, a memória continua ocupada até o programa encerrar.

sintaxe
void free(void *ptr);

Memory Leak — o que acontece quando você esquece o free

Observe o exemplo abaixo. A cada chamada da função, 1000 inteiros são alocados e nunca liberados. Em um loop de 1 milhão de iterações, isso consome aproximadamente 4 GB de RAM.

❌ Memory Leak — sem free
void processaDados() {
  int *buf = (int*)
    malloc(1000*sizeof(int));
  /* ... processa ... */
  /* esqueceu o free! */
}
/* a cada chamada, 4KB
   vaza para sempre */
✔ Correto — com free
void processaDados() {
  int *buf = (int*)
    malloc(1000*sizeof(int));
  /* ... processa ... */
  free(buf);
  buf = NULL;
}
1

Sempre libere o que alocou

Para cada malloc ou calloc deve haver um free correspondente.

2

Nunca libere duas vezes (double free)

Chamar free(p) duas vezes no mesmo ponteiro causa comportamento indefinido e pode corromper o heap silenciosamente.

3

Nunca use após liberar (use-after-free)

Após free(p), o ponteiro aponta para memória inválida. Atribua p = NULL logo após para evitar esse bug.

Structs com ponteiros — . vs ->

Structs são usados frequentemente com alocação dinâmica. Quando você tem um ponteiro para uma struct, precisa saber qual operador usar para acessar os campos.

📌 variavel.campo: acessa o campo quando você tem a variável diretamente.

📌 ponteiro->campo: acessa o campo quando você tem um ponteiro para a struct. É um atalho para (*ponteiro).campo.

definindo struct com typedef
typedef struct {
    char  nome[50];
    int   idade;
    float ira;
} Aluno;   /* typedef cria um apelido — não precisa escrever "struct Aluno" */
Variável direta — usa ponto (.)
Aluno a;
a.idade = 20;
printf("%d", a.idade);
Ponteiro — usa seta (->)
Aluno *p = &a;
p->idade = 20;
printf("%d", p->idade);

Alocando struct dinamicamente

criar e destruir struct no heap
#include <stdlib.h>
#include <string.h>

int main() {
    Aluno *p = (Aluno *) malloc(sizeof(Aluno));

    if (p == NULL) { return 1; }

    strcpy(p->nome, "Ana");   /* acessa campo pelo ponteiro */
    p->idade = 20;
    p->ira   = 3.85;

    printf("%s tem %d anos, IRA %.2f\n", p->nome, p->idade, p->ira);

    free(p);
    p = NULL;
    return 0;
}

Vetor de structs dinamicamente alocado

Aluno *turma = (Aluno *) malloc(n * sizeof(Aluno));

for (int i = 0; i < n; i++) {
    scanf("%s %d", turma[i].nome, &turma[i].idade);
    /* turma[i] já é a struct, não ponteiro — usa ponto (.) */
}

free(turma);
turma = NULL;
Use -> quando a variável for um ponteiro. Use . quando for a struct direta. A dúvida some se você perguntar: "tenho a struct ou tenho o endereço dela?"

Ponteiro para ponteiro e matrizes dinâmicas

Um ponteiro pode apontar para qualquer tipo, inclusive para outro ponteiro. Isso é declarado com dois asteriscos: int **p. Esse conceito é a base para criar matrizes dinâmicas em C.

int **mat; (ponteiro para ponteiro de int) mat ──► [ *linha0 | *linha1 | *linha2 ] (vetor de ponteiros) │ │ │ ▼ ▼ ▼ [0|1|2] [3|4|5] [6|7|8] (linhas no heap)
alocando uma matriz NxM dinamicamente
#include <stdlib.h>
#include <stdio.h>

int main() {
    int N = 3, M = 4;
    int i, j;

    /* Passo 1: aloca vetor de N ponteiros (as linhas) */
    int **mat = (int **) malloc(N * sizeof(int *));

    /* Passo 2: para cada linha, aloca M inteiros (as colunas) */
    for (i = 0; i < N; i++)
        mat[i] = (int *) malloc(M * sizeof(int));

    /* Usa a matriz normalmente com mat[linha][coluna] */
    for (i = 0; i < N; i++)
        for (j = 0; j < M; j++)
            mat[i][j] = i * M + j;

    /* Passo 3: libera em ordem inversa — primeiro as linhas */
    for (i = 0; i < N; i++) {
        free(mat[i]);
        mat[i] = NULL;
    }
    free(mat);    /* depois o vetor de ponteiros */
    mat = NULL;

    return 0;
}
A liberação deve ser feita em ordem inversa à alocação: primeiro libere cada linha com free(mat[i]), depois libere o vetor de ponteiros com free(mat). Inverter a ordem causa memory leak ou acesso a memória inválida.

A grande vantagem desta abordagem é que as linhas não precisam ser contíguas na memória, e cada linha pode ter um tamanho diferente. Isso permite matrizes triangulares e outras estruturas irregulares.

Vetores dinâmicos — operações e limitações

Um vetor dinâmico mantém dois valores separados: o tamanho (capacidade total alocada) e a ocupação (quantos elementos estão em uso de fato). O vetor não guarda essas informações sozinho. Você precisa passá-las como parâmetro para qualquer função que opere sobre o vetor.

Vetor Desordenado

Na inserção desordenada, o novo elemento vai direto na próxima posição livre. Na remoção de um elemento qualquer, o truque é sobrescrever a posição removida com o último elemento, evitando deslocar tudo.

Tamanho: 8Ocupação: 3

Inserção desordenada: O(1). Coloca direto na posição ocupacao e incrementa.

Remoção do último: O(1). Só decrementa a ocupação.

Remoção de qualquer elemento: O(1) no desordenado. Copia o último para a posição removida, sem precisar deslocar nada.

Vetor Ordenado

A inserção ordenada exige encontrar a posição correta e deslocar os elementos maiores para abrir espaço. A remoção também exige deslocar para fechar o buraco.

Inserir 15 no vetor [10, 20, 40] (ordenado): Antes: [ 10 | 20 | 40 | | | | | ] ocupacao=3 Passo 1: Encontrar a posição correta: 15 vai entre 10 e 20, posição 1 Passo 2: Deslocar os maiores para a direita: 40 vai para pos 2, 20 para pos 2 Passo 3: Inserir na posição 1 Depois: [ 10 | 15 | 20 | 40 | | | | ] ocupacao=4 E se o vetor estiver cheio? Usar realloc para expandir!

Inserção ordenada: O(n). Precisa deslocar elementos.

Remoção ordenada: O(n). Precisa deslocar para fechar o buraco.

Vetor cheio: use realloc para dobrar o tamanho e continuar inserindo.

Um vetor (estático ou dinâmico) não sabe seu próprio tamanho. Sempre passe o tamanho como parâmetro extra para funções que recebem vetores.

Fluxo padrão completo

1. Declarar ponteiro: int *v; 2. Alocar: v = malloc(n * sizeof(int)); 3. Verificar NULL: if (v == NULL) { trata erro } 4. Usar normalmente: v[0] = 10; v[1] = 20; ... 5. Realocar se precisar: tmp = realloc(v, novo_tam); if (tmp) v = tmp; 6. Liberar: free(v); 7. Anular ponteiro: v = NULL;

Exercícios de fixação

Quiz rápido

1. Qual região da memória é usada por malloc e calloc para alocar memória?

✔ Correto! malloc e calloc sempre alocam no Heap, que é a área reservada para alocações dinâmicas.
✘ A memória dinâmica fica no Heap (Montículo), não na pilha nem no segmento de código.

2. Por que nunca se deve fazer ptr = realloc(ptr, novo_tam) diretamente?

✔ Exato! Se realloc falha, retorna NULL. Ao atribuir diretamente a ptr, você perde a referência ao bloco original e causa memory leak.
✘ O problema é que realloc pode retornar NULL em caso de falha. Se você atribuir direto a ptr, o endereço original é perdido para sempre.

3. Quando você tem um ponteiro para struct, qual operador usa para acessar um campo?

✔ Correto! Para ponteiro use seta (->). Para variável direta use ponto (.). Seta é atalho para (*ptr).campo.
✘ Para ponteiro usa-se seta (->). O ponto é para variável direta. Seta equivale a (*ptr).campo.

4. Na alocação de uma matriz dinâmica com ponteiro para ponteiro, qual é a ordem correta de liberação?

✔ Correto! Libere as linhas primeiro. Se liberar o vetor de ponteiros antes, você perde as referências para as linhas e causa memory leak.
✘ Libere as linhas individualmente primeiro, depois o vetor de ponteiros. Inverter a ordem provoca memory leak.

5. Qual é a diferença entre calloc e malloc para alocar 10 inteiros?

✔ Correto! calloc zera a memória alocada. malloc deixa o conteúdo anterior. calloc também recebe dois parâmetros separados: quantidade e tamanho.
✘ A diferença principal é que calloc inicializa a memória com zeros. malloc deixa lixo na memória.

Desafios para programar

Desafio 1 — Leitura dinâmica
Peça ao usuário um número N, aloque dinamicamente um vetor de N floats com malloc, leia N valores do teclado, calcule a média e libere a memória.

Desafio 2 — Crescimento sob demanda
Crie um programa que começa com um vetor de 4 posições. Quando o vetor encher, use realloc para dobrar o tamanho. Continue inserindo até o usuário parar. Exiba o tamanho atual a cada realocação.

Desafio 3 — Vetor de structs
Crie uma struct Aluno com nome e IRA. Aloque dinamicamente um vetor de N alunos com malloc. Leia os dados, encontre o aluno com maior IRA e libere a memória ao final.

Desafio 4 — Matriz dinâmica
Aloque dinamicamente uma matriz NxM onde N e M são lidos em tempo de execução usando ponteiro para ponteiro. Preencha com valores, imprima e libere corretamente em ordem inversa.
