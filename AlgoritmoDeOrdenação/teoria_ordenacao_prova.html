Conceitos fundamentais — estabilidade e in-place

Estabilidade: um algoritmo é estável se elementos com chaves iguais mantêm a mesma ordem relativa que tinham antes de ordenar.

Exemplo: vetor [(3,A), (1,B), (3,C)] ordenado por número. Estável → [(1,B), (3,A), (3,C)] — A veio antes de C e continua antes. Instável → pode resultar [(1,B), (3,C), (3,A)].

In-place: o algoritmo ordena sem usar memória extra proporcional a n. Usa no máximo algumas variáveis auxiliares (O(1) de espaço extra). Bubble, Selection e Insertion são in-place. Merge Sort não é — precisa de um vetor auxiliar de tamanho O(n).

Cuidado com Selection Sort e estabilidade

Na implementação padrão, o Selection Sort não é estável. A troca pode pular elementos iguais fora de ordem. Porém, algumas referências classificam como estável — verifique o contexto da sua aula. Para a prova, o importante é entender o comportamento, não apenas memorizar o rótulo.

Selection Sort — análise profunda

Divide o vetor em duas partes: a parte já ordenada (à esquerda, cresce a cada passo) e a parte não ordenada. A cada passo, encontra o menor elemento da parte não ordenada e o troca com o primeiro da parte não ordenada.

implementação completa
int smallerIndex(int vet[], int tam, int ini) {
    int min = ini;
    for (int j = ini + 1; j < tam; j++)
        if (vet[j] < vet[min])   // < não <=: mantém o primeiro
            min = j;
    return min;              // retorna ÍNDICE do menor
}

void selectionSort(int vet[], int tam) {
    for (int i = 0; i < tam; i++) {  // i vai de 0 até tam-1
        int min = smallerIndex(vet, tam, i);
        int aux = vet[i];               // troca vet[i] com vet[min]
        vet[i]  = vet[min];
        vet[min] = aux;
    }
}

smallerIndex retorna índice: a função percorre de ini+1 até tam-1 e mantém em min o índice do menor valor encontrado até agora. Começa com min = ini (assume que o primeiro é o menor). Retorna um número entre 0 e tam-1 — não um valor do vetor.

Número exato de trocas: O Selection Sort sempre realiza exatamente n trocas (uma por iteração do loop externo), mesmo quando o elemento já está na posição certa. Trocas de elemento consigo mesmo (quando min == i) também acontecem.

Número de comparações: o loop interno de smallerIndex faz (n-1) + (n-2) + ... + 1 = n(n-1)/2 comparações no total. Isso vale sempre — melhor e pior caso são O(n²). O Selection Sort nunca para antes.

Insertion Sort — análise profunda

Para cada elemento list[i] (começando do i=1), guarda o valor em next e faz um scan para trás deslocando os elementos maiores que next uma posição à direita, até achar onde inserir.

implementação completa
void insertionSort(int list[], int n) {
    int i, j, next;
    for (i = 1; i < n; i++) {
        next = list[i];              // salva o elemento atual
        for (j = i - 1; j >= 0 && next < list[j]; j--)
            list[j + 1] = list[j];  // desloca j para j+1
        list[j + 1] = next;         // insere na posição j+1
    }
}

Por que list[j+1] = next e não list[j] = next? O loop for decrementa j antes de sair. Quando a condição j >= 0 && next < list[j] falha, j já foi decrementado um a mais. A posição correta é j+1, não j.

Exemplo: se j chegou a -1 (elemento vai para o início), list[-1+1] = list[0] = next — correto.

Melhor caso O(n): quando o vetor já está ordenado, para cada i, a condição next < list[j] é falsa imediatamente (next >= list[j]). O loop interno não executa nenhuma vez. Apenas n-1 comparações no total.

Pior caso O(n²): quando o vetor está em ordem decrescente, cada elemento i precisa ser deslocado até a posição 0. O loop interno executa i vezes para cada i → 1+2+...+(n-1) = n(n-1)/2 operações.

Bubble Sort — análise profunda

Percorre o vetor comparando pares adjacentes e trocando quando estão fora de ordem. Após cada passagem completa, o maior elemento ainda não fixado "flutua" até sua posição final.

implementação com loop externo decrescente
void bubbleSort(int vet[], int tam) {
    int i, j, temp;
    for (i = tam - 1; i > 0; i--) {    // i de tam-1 até 1
        for (j = 0; j < i; j++) {         // j de 0 até i-1
            if (vet[j] > vet[j + 1]) {
                temp      = vet[j];
                vet[j]    = vet[j + 1];
                vet[j + 1] = temp;
            }
        }
    }
}

Entendendo os loops:

  • Loop externo (i): começa em tam-1 e decrementa. Representa o limite superior das comparações — a partir da posição i+1, os elementos já estão na posição final.
  • Loop interno (j): vai de 0 a i-1. Compara pares adjacentes: j e j+1. Nunca chega a i porque compara j e j+1 (o máximo é j=i-1 comparando v[i-1] com v[i]).

Número de passagens: O loop externo executa exatamente tam-1 vezes (i de tam-1 até 1 inclusive). Para tam=4: 3 passagens. Para tam=n: n-1 passagens. Isso vale sempre, mesmo que o vetor fique ordenado antes — sem a otimização de flag.

Versão otimizada com flag (importante para prova)

Essa variante para mais cedo quando nenhuma troca ocorreu:

bubble sort com flag de troca
void bubbleSortOtimizado(int vet[], int tam) {
    int i, j, temp, trocou;
    for (i = tam - 1; i > 0; i--) {
        trocou = 0;                        // reseta flag a cada passagem
        for (j = 0; j < i; j++) {
            if (vet[j] > vet[j + 1]) {
                temp = vet[j]; vet[j] = vet[j+1]; vet[j+1] = temp;
                trocou = 1;                   // marcou troca
            }
        }
        if (!trocou) break;              // nenhuma troca → já ordenado
    }
}

Com flag: melhor caso O(n) — uma única passagem sem trocas e o algoritmo para. Pior caso permanece O(n²). A versão sem flag é sempre O(n²).

QuickSort — partição linha a linha

Divide e conquista: escolhe um pivô, particiona o vetor de modo que os elementos menores que o pivô fiquem à esquerda e os maiores à direita (o pivô fica em sua posição final), depois ordena recursivamente cada metade.

funções separa e quicksort
// Pivô = último elemento v[r].
// Após execução: v[p..j-1] <= v[j] < v[j+1..r]
int separa(int v[], int p, int r) {
    int c = v[r];    // pivô
    int t, j = p;
    for (int k = p; k < r; ++k)   // k percorre p até r-1
        if (v[k] <= c) {
            t = v[j]; v[j] = v[k]; v[k] = t;  // troca v[j] com v[k]
            ++j;
        }
    t = v[j]; v[j] = v[r]; v[r] = t;  // coloca pivô na posição j
    return j;
}

void quicksort(int v[], int p, int r) {
    if (p < r) {
        int j = separa(v, p, r);
        quicksort(v, p, j - 1);
        quicksort(v, j + 1, r);
    }
}

Entendendo a função separa:

  • c = v[r]: o pivô é sempre o último elemento do intervalo [p..r]
  • j: aponta para a próxima posição disponível na partição "menores que o pivô". Começa em p.
  • k: percorre todos os elementos exceto o pivô. Se v[k] <= c, troca com v[j] e incrementa j.
  • Ao final: coloca o pivô em v[j] (trocando com v[r]). Agora v[j] é o pivô e está na posição definitiva.
  • Retorna j — o índice do pivô. Elementos em [p..j-1] são ≤ pivô, em [j+1..r] são > pivô.

Merge Sort — intercalação linha a linha

Divide recursivamente o vetor ao meio até chegar em subvetores de 1 elemento (trivialmente ordenados), depois intercala as metades ordenadas para produzir um resultado maior e ordenado.

Convenção de intervalo [p..r[: o mergesort usa intervalos "semi-abertos" — p é inclusivo, r é exclusivo. Um vetor de n elementos: mergesort(0, n, v). O subvetor vai do índice p ao índice r-1.

intercala e mergesort
// v[p..q-1] e v[q..r-1] já ordenados. Resultado em v[p..r-1]
void intercala(int p, int q, int r, int v[]) {
    int *w = (int*) malloc((r - p) * sizeof(int));
    int i = p, j = q, k = 0;
    while (i < q && j < r)
        w[k++] = (v[i] <= v[j]) ? v[i++] : v[j++];
    while (i < q) w[k++] = v[i++];   // sobras da esquerda
    while (j < r) w[k++] = v[j++];   // sobras da direita
    for (i = p; i < r; ++i) v[i] = w[i - p];
    free(w);
}

void mergesort(int p, int r, int v[]) {
    if (p < r - 1) {               // mais de 1 elemento?
        int q = (p + r) / 2;
        mergesort(p, q, v);
        mergesort(q, r, v);
        intercala(p, q, r, v);
    }
}

Condição de parada: p < r-1: significa que o subvetor tem mais de 1 elemento. Se p = r-1, tem exatamente 1 elemento — já está ordenado por definição. Se p < r-1 é falso quando p+1 = r (1 elemento) ou p = r (0 elementos).

Merge Sort NÃO é in-place: a função intercala aloca um vetor auxiliar w de tamanho r-p. O total de memória extra é O(n). Esta é a principal desvantagem do Merge Sort frente ao QuickSort.

Pegadinhas da prova — ordenação

⚠ pegadinha #1 — smallerIndex retorna índice, não valor

No Selection Sort, smallerIndex retorna o índice do menor elemento, não o valor. Se você precisar do valor do menor, é vet[smallerIndex(...)], não o retorno direto.

int min = smallerIndex(vet, 5, 2);
// min = 4 (por exemplo)      ← índice!
// vet[min] = vet[4] = 1      ← valor
⚠ pegadinha #2 — selection sort faz n trocas sempre

O loop externo do selectionSort vai de i=0 até i < tam, executando uma troca por iteração — inclusive quando min == i (troca consigo mesmo). São sempre tam trocas, não tam-1. Confirme contando no trace.

⚠ pegadinha #3 — insertion sort: list[j+1] não list[j]

A inserção final é em list[j+1] porque o for-loop já decrementou j uma vez a mais antes de parar. Este é o erro mais comum ao analisar o Insertion Sort:

// j termina em -1 quando o elemento vai para o início
list[j+1] = next;  // list[-1+1] = list[0] = next ← correto
// Se fosse list[j] seria list[-1] ← ERRADO (acesso inválido)
⚠ pegadinha #4 — bubble sort: j < i, não j < tam

No Bubble Sort com loop externo decrescente, o loop interno é j < i, não j < tam. A cada passagem, o número de comparações diminui. Passagem 1 (i=tam-1): tam-1 comparações. Passagem 2 (i=tam-2): tam-2 comparações. Etc.

// Para tam=5:
// i=4: j=0,1,2,3 → 4 comparações
// i=3: j=0,1,2   → 3 comparações
// i=2: j=0,1     → 2 comparações
// i=1: j=0       → 1 comparação
// Total: 4+3+2+1 = 10 comparações
⚠ pegadinha #5 — mergesort: p < r-1, não p < r

A condição de parada do mergesort é p < r-1. Se fosse p < r, tentaria dividir um único elemento indefinidamente. Com p < r-1: para quando há 0 ou 1 elemento.

⚠ pegadinha #6 — quicksort pior caso é vetor ordenado

Com pivô = último elemento, se o vetor já está ordenado, cada chamada a separa resulta em uma partição vazia e outra com n-1 elementos. A recursão tem profundidade n, resultando em O(n²). Este é o pior caso do QuickSort.

⚠ pegadinha #7 — após K passes do bubble, os K maiores estão fixados

Após 1 passagem: o maior elemento está na posição final. Após 2 passagens: os 2 maiores estão nas posições finais. Após k passagens: os k maiores estão nas últimas k posições. Isso é o que a prova testa quando pergunta "qual o estado do vetor após 2 passagens?".

Questões no estilo da prova

Analise o código e responda

Q1. Após a 2ª passagem do bubbleSort (i=tam-2) no vetor [5, 1, 4, 2, 8], qual o estado do vetor?

✔ Pass1(i=4): 5>1→troca→[1,5,4,2,8]; 5>4→troca→[1,4,5,2,8]; 5>2→troca→[1,4,2,5,8]; 5>8?Não. Pass2(i=3,j<3): 1>4?Não; 4>2→troca→[1,2,4,5,8]; 4>5?Não. Estado após 2 passes: [1,2,4,5,8]? Trace novamente: Pass1→[1,4,2,5,8]. Pass2: j<3(j=0,1,2): 1>4?N; 4>2→troca→[1,2,4,5,8]; 4>5?N. Final: [1,2,4,5,8].
✘ Pass1: [1,4,2,5,8]. Pass2(j=0,1,2): 1>4?N; 4>2→troca; 4>5?N → [1,2,4,5,8]. A resposta correta é [1,2,4,5,8].

Q2. No Selection Sort com [4, 2, 6, 1, 3], qual o estado após a 1ª iteração do loop externo (i=0)?

✔ smallerIndex(vet,5,0): menor é v[3]=1, retorna índice 3. Troca v[0]=4 com v[3]=1 → [1,2,6,4,3]. Atenção: smallerIndex retorna índice 3, não o valor 1.
✘ O menor é v[3]=1 (índice 3). Troca v[0] com v[3]: v[0]←1, v[3]←4. Resultado: [1,2,6,4,3].

Q3. No Insertion Sort com [3, 1, 2], quando i=2 e next=2, qual o valor de j ao final do loop interno e onde o elemento é inserido?

✔ next=2. j=1: 2 < list[1]=1? NÃO → para (condição falsa). j fica em 0. list[j+1] = list[0+1] = list[1] = 2. Resultado: [1,2,3]. j ficou em 0 pois a 2ª condição do && falhou sem decrementar j de novo.
✘ Após pass1 o vetor está [1,3,2]. next=2. j começa em 1. list[1]=3 > 2 → desloca: [1,3,3]. j=0. list[0]=1 > 2? Não. Para com j=0. list[0+1]=2. Final: [1,2,3].

Q4. Quantas comparações de igualdade o Selection Sort faz para um vetor de 5 elementos?

✔ smallerIndex(ini=0): 4 comp. smallerIndex(ini=1): 3 comp. ini=2: 2 comp. ini=3: 1 comp. ini=4: 0 comp. Total = 4+3+2+1 = 10. Selection Sort sempre faz n(n-1)/2 = 5×4/2 = 10 comparações.
✘ Sempre (n-1)+(n-2)+...+1 = n(n-1)/2. Para n=5: 10 comparações. Independe dos valores.

Q5. O Merge Sort é in-place?

✔ A função intercala faz malloc((r-p)*sizeof(int)) — aloca um vetor auxiliar. O total de memória extra é O(n). Merge Sort NÃO é in-place. A pilha de recursão usa O(log n) a mais, mas a maior parte é o vetor auxiliar.
✘ intercala aloca w com malloc — vetor auxiliar de O(n) elementos. Merge Sort usa memória extra O(n), logo não é in-place.

Q6. Após a 1ª passagem do bubbleSort (i=tam-1=8) no vetor [2,3,2,0,3,7,9,3,7] (dígitos da matrícula 232037937), qual o estado do vetor?

✔ j=0: 2>3? Não. j=1: 3>2? Sim→[2,2,3,0,3,7,9,3,7]. j=2: 3>0? Sim→[2,2,0,3,3,7,9,3,7]. j=3: 3>3? Não. j=4: 3>7? Não. j=5: 7>9? Não. j=6: 9>3? Sim→[2,2,0,3,3,7,3,9,7]. j=7: 9>7? Sim→[2,2,0,3,3,7,3,7,9]. O maior elemento (9) "borbulhou" para a última posição. 3 trocas no total nesta passagem.
✘ Trace passo a passo: trocas em j=1 (3,2), j=2 (3,0), j=6 (9,3), j=7 (9,7). Resultado: [2,2,0,3,3,7,3,7,9].

Q7. selectionSort(vet, 9) no vetor dos 9 dígitos da matrícula 232037937. Quantas trocas (chamadas à operação de swap) são realizadas no total, independente dos valores?

✔ O loop externo do selectionSort vai de i=0 até i<tam, executando swap(vet[i], vet[min]) a cada iteração — mesmo quando min==i (troca consigo mesmo). Para tam=9: exatamente 9 trocas. Este é um fato fixo do Selection Sort: sempre n trocas, independente da entrada. As comparações é que são n(n-1)/2 = 36.
✘ O loop externo executa tam vezes (i=0..tam-1), com uma troca por iteração, mesmo que min==i. Sempre n=9 trocas.

Q8. insertionSort([7,9,3,7], 4) — últimos 4 dígitos da matrícula 232037937. Qual o estado do vetor após processar o elemento na posição i=2 (o valor 3)?

✔ Estado antes de i=2: após i=1 (next=9, 9<7? Não → sem troca) → [7,9,3,7]. Agora i=2: next=3. j=1: 3<list[1]=9? Sim→list[2]=9=[7,9,9,7]. j=0: 3<list[0]=7? Sim→list[1]=7=[7,7,9,7]. j=-1: para. list[0]=3=[3,7,9,7]. Resultado após i=2: [3,7,9,7].
✘ i=2, next=3: desloca 9 e 7 uma posição à direita, insere 3 em list[0]. Resultado: [3,7,9,7].

Q9. O vetor [0,2,3,7,9] (dígitos únicos da matrícula 232037937, já ordenado) é passado ao quicksort com pivô sempre no último elemento. Por que este é o pior caso do QuickSort?

✔ Com pivô = último elemento em vetor ordenado: todos os elementos são ≤ pivô, então j avança até n-1 e o pivô vai para a posição n-1 (a própria). Partição esquerda tem n-1 elementos, direita tem 0. Recursão: T(n)=T(n-1)+O(n) → O(n²). Para [0,2,3,7,9]: 5→4→3→2→1 chamadas = 5+4+3+2+1=15 comparações no total.
✘ Vetor ordenado + pivô=último: separa sempre produz partição vazia (esquerda) e n-1 (direita). Recursão T(n)=T(n-1)+O(n) → O(n²).

Q10. Dentre os algoritmos estudados (Selection, Insertion, Bubble, QuickSort, MergeSort), quais são estáveis — preservam a ordem relativa de elementos com chaves iguais?

✔ Insertion Sort: desloca apenas quando next < list[j] (estrito), preserva iguais. Bubble Sort: troca apenas quando v[j] > v[j+1] (estrito), preserva iguais. Merge Sort: usa v[i] <= v[j] na intercalação, preferindo o da esquerda em empate. Selection Sort: a troca pode pular elementos iguais fora de ordem. QuickSort: a partição embaralha elementos com chave igual ao pivô.
✘ Estáveis: Insertion, Bubble e Merge (todos usam comparação estrita, preservam ordem de iguais). Instáveis: Selection e QuickSort (trocas podem reordenar elementos iguais).
