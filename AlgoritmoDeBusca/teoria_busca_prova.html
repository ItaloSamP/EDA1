// 01

O que a prova pede — leia antes de tudo

A prova do professor Nilton é predominantemente de análise de código. Você recebe uma função em C e precisa dizer o que ela imprime, o que retorna ou qual o estado das variáveis num ponto específico.

Padrão recorrente das questões:

  • Função recebe como parâmetros seu nome e/ou matrícula
  • O código faz algum processamento com os dígitos da matrícula ou letras do nome
  • Pergunta: "qual a saída?" ou "qual o valor de X ao final?"
  • Existe quase sempre uma pegadinha — um detalhe que muda tudo

Para busca, os padrões mais comuns são:

  • Dado um vetor construído a partir da matrícula, qual o índice encontrado pela busca?
  • O algoritmo busca por um valor — mas o código usa índice, não valor. Muita atenção.
  • A busca retorna -1 ou o índice? E se não encontrar?
  • Contar quantas comparações/iterações o loop executa para uma entrada específica
Erro clássico — índice vs valor

Na prova anterior, o código separava dígitos pares e ímpares da matrícula. A pegadinha era: o vetor acumulava os índices (posições) dos dígitos pares/ímpares, não os valores deles. Sempre leia o código inteiro antes de assumir o que ele faz.

Método seguro para questões de código
  1. Leia a assinatura da função — parâmetros e tipo de retorno
  2. Identifique as variáveis e seus valores iniciais
  3. Execute o loop mentalmente linha por linha, anotando os valores
  4. Não assuma — confirme com o código o que é índice e o que é valor
  5. Verifique a condição de parada com cuidado (< vs <=)
// 02

Busca sequencial — vetor desordenado

Percorre o vetor do índice 0 ao índice n-1, comparando cada elemento com o valor buscado. Para assim que encontra ou chega ao fim.

implementação canônica
int buscaSeq(int v[], int n, int valor) {
    for (int i = 0; i < n; i++)
        if (v[i] == valor)
            return i;       // retorna o ÍNDICE, não o valor
    return -1;               // não encontrado
}

O que a função retorna: o índice da primeira ocorrência do valor. Se houver elementos repetidos, retorna o índice do primeiro encontrado (menor índice). Se não encontrar, retorna -1.

Análise linha por linha — matrícula 232037937

Construindo um vetor a partir dos dígitos da matrícula e buscando por 3:

trace — buscaSeq([2,3,2,0,3,7,9,3,7], 9, 3)
i=0: v[0]=2 == 3? Não → continua i=1: v[1]=3 == 3? SIM → return 1 Resultado: 1 ← ÍNDICE, não o valor 3!
trace — buscaSeq([2,3,2,0,3,7,9,3,7], 9, 5)
i=0: v[0]=2 == 5? Não i=1: v[1]=3 == 5? Não i=2: v[2]=2 == 5? Não i=3: v[3]=0 == 5? Não i=4: v[4]=3 == 5? Não i=5: v[5]=7 == 5? Não i=6: v[6]=9 == 5? Não i=7: v[7]=3 == 5? Não i=8: v[8]=7 == 5? Não i=9: i < 9? Não → sai do loop Resultado: -1 ← elemento não existe

Complexidade:

  • Melhor caso: O(1) — elemento na posição 0
  • Pior caso: O(n) — elemento não existe ou está na última posição
  • Caso médio: O(n) — em média, percorre n/2 elementos

Contando iterações — o que a prova pede

Para responder "quantas comparações foram feitas?", conte cada execução do if dentro do loop:

  • Se encontrou na posição k: fez exatamente k+1 comparações
  • Se não encontrou: fez exatamente n comparações
Pegadinha — retorno de índice

A função retorna o índice onde achou o elemento. Se buscaSeq encontrou o elemento 3 na posição 1 do vetor, ela retorna 1, não 3. A questão pode perguntar "qual o retorno da função?" — a resposta é o índice.

// 03

Busca sequencial — vetor ordenado

Igual à busca sequencial desordenada, mas com um break antecipado: se o elemento atual for maior que o buscado, o elemento não existe no restante (pois o vetor é crescente). Economiza iterações quando o elemento não está no vetor.

implementação com parada antecipada
int buscaSeqOrdenado(int v[], int n, int valor) {
    for (int i = 0; i < n; i++) {
        if (v[i] == valor) return i;
        if (v[i] > valor)  break;  // não pode estar à frente
    }
    return -1;
}

Por que o break funciona: Se v[i] > valor, como o vetor está em ordem crescente, todos os elementos a partir de i também são maiores que valor. Logo, o elemento buscado definitivamente não existe no vetor.

Comparação de traces: elemento não existe

trace — busca de 15 em [3, 7, 12, 21, 34, 98] (n=6)
Desordenada: percorre TODOS os 6 elementos → 6 comparações i=0: 3, i=1: 7, i=2: 12, i=3: 21, i=4: 34, i=5: 98 → return -1 Ordenada com break: i=0: v[0]=3 ==15? Não. 3 > 15? Não. i=1: v[1]=7 ==15? Não. 7 > 15? Não. i=2: v[2]=12 ==15? Não. 12 > 15? Não. i=3: v[3]=21 ==15? Não. 21 > 15? SIM → break → return -1 Apenas 4 comparações de igualdade + 4 comparações de "maior"
Complexidade — não confunda

A busca sequencial ordenada tem pior caso O(n) — igual à desordenada. O break só ajuda quando o elemento não está no vetor. Se o elemento procurado for o maior de todos, ainda percorre o vetor inteiro antes de encontrar (ou não encontrar). A melhoria é no caso médio de ausência, não na complexidade assintótica.

Complexidade:

  • Melhor caso: O(1)
  • Pior caso: O(n) — elemento no final ou maior que todos
  • Elemento ausente (médio): O(n/2) — break no meio, em média
// 04

Busca binária — teoria completa

A busca binária usa o fato de o vetor estar ordenado para eliminar metade do espaço de busca a cada passo. Em vez de checar um por um, vai direto ao elemento do meio e decide em qual metade continuar.

Pré-requisito obrigatório: o vetor deve estar ordenado. Se o vetor não estiver ordenado, a busca binária pode retornar resultados errados silenciosamente — não dá erro, apenas retorna o índice errado ou -1 incorretamente.

Variáveis fundamentais — memorize

  • esq (esquerda): índice do início do intervalo atual de busca. Começa em 0.
  • dir (direita): índice do fim do intervalo atual de busca. Começa em n-1 (não n!).
  • meio: índice calculado como (esq + dir) / 2 — divisão inteira.
busca binária iterativa — versão canônica
int buscaBinaria(int v[], int n, int valor) {
    int esq = 0, dir = n - 1, meio;
    while (esq <= dir) {                        // <= é crucial
        meio = (esq + dir) / 2;               // divisão inteira
        if      (valor == v[meio]) return meio; // encontrou
        else if (valor <  v[meio]) dir  = meio - 1; // vai p/ esquerda
        else                       esq = meio + 1; // vai p/ direita
    }
    return -1;
}

Lógica de cada linha — detalhe a detalhe

dir = n - 1, não n: o índice do último elemento de um vetor de tamanho n é n-1. Usar n como dir causaria acesso a v[n] que está fora do vetor.

while (esq <= dir), não <: o <= garante que um único elemento restante ainda seja checado. Se fosse apenas <, quando esq == dir (1 elemento restante), o loop não executaria e o elemento seria perdido — o algoritmo retornaria -1 mesmo que o elemento exista.

meio = (esq + dir) / 2: sempre recalculado a cada iteração. É divisão inteira — com esq=0 e dir=5, meio = (0+5)/2 = 2 (não 2.5).

dir = meio - 1 e esq = meio + 1: após checar que o elemento no meio não é o buscado, o meio em si é excluído da próxima busca. Por isso meio±1 e não meio. Se fosse dir = meio, o loop poderia ser infinito quando esq == dir == meio.

Versão recursiva

busca binária recursiva
int buscaBinRec(int v[], int esq, int dir, int valor) {
    if (esq > dir) return -1;          // caso base: não encontrou
    int meio = (esq + dir) / 2;
    if      (valor == v[meio]) return meio;
    else if (valor <  v[meio]) return buscaBinRec(v, esq,    meio-1, valor);
    else                       return buscaBinRec(v, meio+1, dir,    valor);
}
// Chamada inicial: buscaBinRec(v, 0, n-1, valor)

Diferença da recursiva: o caso base é esq > dir — quando o intervalo ficou vazio. A lógica interna é idêntica à iterativa, apenas expressa com chamadas recursivas em vez de loop.

// 05

Busca binária — trace passo a passo

Trace completo e metódico. Para a prova, anote sempre os três valores: esq, dir, meio e o que ocorre em cada iteração.

Exemplo 1: elemento encontrado

Vetor: [0, 2, 3, 7, 9, 37] (dígitos da matrícula 232037937 ordenados e únicos), n=6, busca por 7.

buscaBinaria([0,2,3,7,9,37], 6, 7)
Estado inicial: esq=0, dir=5 Iteração 1: meio = (0+5)/2 = 2 ← divisão inteira, não arredonda v[2] = 3 7 == 3? Não 7 < 3? Não 7 > 3? Sim → esq = meio+1 = 3 esq=3, dir=5 Iteração 2: meio = (3+5)/2 = 4 v[4] = 9 7 == 9? Não 7 < 9? Sim → dir = meio-1 = 3 esq=3, dir=3 Iteração 3: meio = (3+3)/2 = 3 v[3] = 7 7 == 7? SIM → return 3 Retorno: 3 ← índice onde está o 7

Exemplo 2: elemento não existe

Mesmo vetor, busca por 5.

buscaBinaria([0,2,3,7,9,37], 6, 5)
esq=0, dir=5 Iteração 1: meio = (0+5)/2 = 2 → v[2]=3 5 == 3? Não | 5 < 3? Não | 5 > 3 → esq = 3 Iteração 2: esq=3, dir=5 → meio = (3+5)/2 = 4 → v[4]=9 5 == 9? Não | 5 < 9? Sim → dir = 3 Iteração 3: esq=3, dir=3 → meio = (3+3)/2 = 3 → v[3]=7 5 == 7? Não | 5 < 7? Sim → dir = 2 Verificação do while: esq=3, dir=2 → 3 <= 2? NÃO → sai do loop Retorno: -1 ← elemento não existe

Exemplo 3: único elemento — o caso crítico

buscaBinaria([42], 1, 42) — n=1, 1 único elemento
esq=0, dir=0 Iteração 1: while (0 <= 0): Sim ← se fosse '<' ao invés de '<=', não entraria! meio = (0+0)/2 = 0 → v[0]=42 42 == 42? SIM → return 0 Retorno: 0 ✓ Se a condição fosse 'esq < dir': while (0 < 0): Não → loop nunca executa → return -1 ← BUG!
Por que esq <= dir e não esq < dir

Com <, quando resta apenas 1 elemento (esq == dir), o loop não executa e o algoritmo retorna -1 mesmo que o elemento exista. O <= garante que o último elemento restante seja verificado.

Calculando meio — exercício mental obrigatório

Pratique calcular meio para não errar na prova:

esq=0, dir=7 → meio = (0+7)/2 = 3 (não 3.5!) esq=3, dir=7 → meio = (3+7)/2 = 5 esq=0, dir=6 → meio = (0+6)/2 = 3 esq=2, dir=5 → meio = (2+5)/2 = 3 (7/2 = 3, descarta .5) esq=4, dir=5 → meio = (4+5)/2 = 4 (9/2 = 4, descarta .5) esq=5, dir=5 → meio = (5+5)/2 = 5
Contando iterações da busca binária

Para um vetor de tamanho n, a busca binária faz no máximo ⌊log₂(n)⌋ + 1 iterações. Para n=8: log₂(8)=3, no máximo 4 iterações. Para n=1024: log₂(1024)=10, no máximo 11 iterações. Se a prova pedir o número de iterações para uma entrada específica, faça o trace — não confie só no log₂.

// 06

Pegadinhas da prova — busca

⚠ pegadinha #1 — retorno é índice, não valor

Todas as buscas retornam o índice do elemento no vetor, não o valor encontrado.

int v[] = {10, 30, 50, 70};
int r = buscaBinaria(v, 4, 50);
// r = 2, não 50!

Se a questão perguntar "qual o retorno?", a resposta é 2.

⚠ pegadinha #2 — dir começa em n-1, não n

Para um vetor de 5 elementos: dir = 5 - 1 = 4. O índice válido vai de 0 a 4. Se o código inicializar dir = n (errado), acessaria v[5] que está fora do vetor — comportamento indefinido.

⚠ pegadinha #3 — elementos repetidos

Com elementos repetidos no vetor, a busca binária não garante qual ocorrência será retornada. Depende de onde o meio cai:

int v[] = {1, 3, 3, 3, 5};
// buscaBinaria de 3:
// meio=2, v[2]=3 → retorna 2 (a do meio)
// Não garante o primeiro (índice 1) nem o último (índice 3)
⚠ pegadinha #4 — busca sequencial em vetor vazio

Se n = 0: o loop for (i=0; i<0; i++) não executa. A função retorna imediatamente -1. Zero iterações, zero comparações.

⚠ pegadinha #5 — a busca sequencial "ordenada" em vetor desordenado

Se o professor passar um vetor desordenado para a busca sequencial "ordenada" (com break), ela pode retornar -1 erroneamente: o break sai do loop antes de encontrar o elemento.

int v[] = {9, 3, 1, 7, 5};
buscaSeqOrdenado(v, 5, 5);
// i=0: v[0]=9 > 5? SIM → break → return -1
// Mas 5 existe no índice 4! Resultado ERRADO porque vetor não está ordenado.
⚠ pegadinha #6 — meio calculado com divisão inteira

O meio é sempre divisão inteira. Para esq=1 e dir=4: meio = (1+4)/2 = 5/2 = 2, não 2.5. Em C, divisão entre inteiros trunca para baixo.

⚠ pegadinha #7 — código com variação sutil no loop

Se o professor mostrar este código com a condição modificada:

while (esq < dir) {  // ATENÇÃO: < em vez de <=
    meio = (esq + dir) / 2;
    if      (valor == v[meio]) return meio;
    else if (valor <  v[meio]) dir  = meio;  // não é meio-1
    else                       esq = meio + 1;
}

Esta é outra variante válida (half-open interval). O comportamento é diferente — trace cuidadosamente cada questão. Não assuma que todo código de busca binária tem o mesmo comportamento.

Tabela de complexidades — busca

AlgoritmoPré-reqMelhorPiorMédioRetorno
Seq. desordenadaNenhumO(1)O(n)O(n)Índice ou -1
Seq. ordenadaOrdenadoO(1)O(n)O(n/2)*Índice ou -1
BináriaOrdenadoO(1)O(log n)O(log n)Índice ou -1

O melhor caso O(1): ocorre quando o elemento buscado está exatamente na primeira posição comparada — índice 0 na busca sequencial, ou exatamente no meio na busca binária (na primeira iteração).

// 08

Questões no estilo da prova

Analise o código e responda

Q1. Dado o código abaixo com matrícula 232037937, qual o retorno de f(v, 9, 9)?

int v[] = {2,3,2,0,3,7,9,3,7};  // dígitos da matrícula
int f(int v[], int n, int x) {
    for (int i = 0; i < n; i++)
        if (v[i] == x) return i;
    return -1;
}
✔ v[6] = 9. A função retorna o ÍNDICE 6, não o valor 9. Traçando: i=0→2, i=1→3, i=2→2, i=3→0, i=4→3, i=5→7, i=6→9 == 9 → return 6.
✘ A função retorna o ÍNDICE, não o valor. v[6]=9, então retorna 6.

Q2. No trace da busca binária em [0,2,3,7,9,37] (n=6) buscando por 0, quantas iterações o loop executa?

✔ Iter.1: esq=0,dir=5,meio=2,v[2]=3 → 0<3 → dir=1. Iter.2: esq=0,dir=1,meio=0,v[0]=0 → encontrou → return 0. Na verdade 2 iterações!
✘ Trace: iter1 meio=2 v[2]=3 → 0<3 → dir=1. Iter2: esq=0,dir=1,meio=0 → v[0]=0 == 0 → return 0. São 2 iterações.

Q3. A busca sequencial "ordenada" (com break quando v[i]>valor) é executada no vetor [5, 3, 8, 1, 9] buscando por 3. Qual o retorno?

✔ i=0: v[0]=5. 5==3? Não. 5>3? Sim → break → return -1. O vetor não está ordenado! O break saiu antes de achar o 3 que está em v[1]. Esta é a pegadinha: busca ordenada em vetor desordenado dá resultado errado.
✘ v[0]=5 > 3 → break imediato → return -1. Vetor não está ordenado, então o break corta prematuramente. Resultado incorreto.

Q4. Qual o valor de meio na primeira iteração de buscaBinaria(v, 9, 7) num vetor de 9 elementos?

✔ esq=0, dir=n-1=8. meio = (0+8)/2 = 4. Divisão inteira em C trunca para baixo. 8/2=4 exato neste caso.
✘ esq=0, dir=8. meio = (0+8)/2 = 4. Divisão inteira — não existe 4.5 em variável int.

Q5. Na busca binária com o vetor [2, 3, 7, 9] (n=4), buscando por 9, qual índice é retornado e quantas iterações ocorrem?

✔ Iter1: esq=0,dir=3,meio=1,v[1]=3. 9>3 → esq=2. Iter2: esq=2,dir=3,meio=2,v[2]=7. 9>7 → esq=3. Iter3: esq=3,dir=3,meio=3,v[3]=9 == 9 → return 3. São 3 iterações! Retorna o índice 3.
✘ Trace: iter1 meio=1 v[1]=3 →esq=2. Iter2 meio=2 v[2]=7 →esq=3. Iter3 meio=3 v[3]=9 →return 3. São 3 iterações, retorna índice 3.

Q6. buscaSeq([2,3,2,0,3,7,9,3,7], 9, 7) — vetor com os dígitos da matrícula 232037937, buscando pelo último dígito (7). Qual o índice retornado?

✔ Trace: i=0→v[0]=2, i=1→3, i=2→2, i=3→0, i=4→3, i=5→7 == 7 → return 5. A função retorna o ÍNDICE 5, não o valor 7. O outro 7 em v[8] nunca é verificado — a função para na primeira ocorrência.
✘ v[5]=7 é a primeira ocorrência. Retorna índice 5, não o valor 7. Não retorna -1 pois 7 existe no vetor.

Q7. buscaSeqOrdenado([2,3,2,0,3,7,9,3,7], 9, 0) — busca pelo 4º dígito da matrícula 232037937 (o zero) num vetor não ordenado. Qual o retorno e por quê?

✔ i=0: v[0]=2. 2==0? Não. 2>0? SIM → break → return -1. O valor 0 existe em v[3], mas o break saiu antes de chegar lá porque v[0]=2 > 0. O vetor não está ordenado — a condição de parada antecipada é inválida aqui. Este é exatamente o cenário da pegadinha #5 desta apostila.
✘ v[0]=2 > 0 → break imediato → return -1. Mesmo que 0 exista em v[3], nunca chegamos lá. Vetor não ordenado invalida a busca sequencial com parada antecipada.

Q8. buscaBinaria([0,2,3,7,9], 5, 3) — dígitos únicos da matrícula 232037937 em ordem crescente, buscando pelo penúltimo dígito (3). Quantas iterações o while executa?

✔ esq=0, dir=4. meio=(0+4)/2=2. v[2]=3. 3==3? SIM → return 2. Uma única iteração! Este é o melhor caso da busca binária O(1): o elemento está exatamente no meio na primeira tentativa. Retorna o índice 2.
✘ meio=(0+4)/2=2, v[2]=3 == 3 → encontrou na 1ª iteração. Melhor caso da busca binária. Retorna índice 2.

Q9. A matrícula 232037937 tem 9 dígitos. Para um vetor de n=9 elementos, qual o número máximo de iterações que a busca binária pode executar (pior caso)?

✔ Fórmula: ⌊log₂(n)⌋ + 1. Para n=9: log₂(9)≈3.17, ⌊3.17⌋=3, +1=4. Trace de pior caso (buscando elemento ausente): [0..8]→meio=4→[5..8]→meio=6→[7..8]→meio=7→[8..8]→meio=8→esq>dir → 4 iterações. Busca binária nunca precisa de 9 iterações para n=9.
✘ Máximo = ⌊log₂(9)⌋+1 = 3+1 = 4. A busca binária é O(log n) — nunca percorre tudo como a sequencial.

Q10. Por que a busca binária usa dir = meio - 1 e esq = meio + 1 em vez de dir = meio e esq = meio? Qual o risco da segunda versão?

✔ Com dir=meio: se esq==dir==meio e v[meio]≠valor, dir ficaria igual a esq — o while(esq<=dir) seria verdadeiro para sempre → loop infinito. Com meio-1: o intervalo [esq..dir] fica estritamente menor a cada iteração, garantindo terminação. Este é o invariante de terminação da busca binária: o intervalo de busca nunca para de encolher.
✘ Com dir=meio quando esq==dir==meio: nenhum update move os ponteiros → loop infinito. meio±1 garante que o intervalo sempre diminui — invariante de terminação do algoritmo.
