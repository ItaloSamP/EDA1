O que é recursividade?

analogia do dia a dia

Imagine que você quer saber quantos andares um prédio tem, mas está no térreo sem ver o topo. Você sobe um andar, pede para a pessoa lá de cima contar os andares acima dela, e soma 1 ao resultado. Ela faz a mesma coisa, até chegar no último andar, que responde "0 andares acima de mim". Esse é o caso base. A resposta desce andar por andar até chegar em você.

Uma função recursiva resolve uma parte pequena do problema e delega o restante para ela mesma, com uma entrada menor. O conceito vem da matemática, veja a definição recursiva dos números naturais:

📌 0 é um inteiro natural  ←  caso base

📌 Se x é um inteiro natural, então x + 1 também é  ←  passo recursivo

O exemplo clássico: Fatorial

Fatorial(5) = 1 × 2 × 3 × 4 × 5 = 120 Escrito recursivamente: ┌─────────────────────────────────────────────┐ │ Se x <= 1 → Fatorial(x) = 1 (caso base) │ │ Senão → Fatorial(x) = x × Fatorial(x-1) │ └─────────────────────────────────────────────┘ Expandindo Fatorial(5): Fatorial(5) = 5 × Fatorial(4) = 5 × 4 × Fatorial(3) = 5 × 4 × 3 × Fatorial(2) = 5 × 4 × 3 × 2 × Fatorial(1) = 5 × 4 × 3 × 2 × 1 = 120 ✓

Cada chamada resolve uma multiplicação e repassa o resto para ela mesma com argumento menor (x-1). Quando x chega a 1, não há mais o que delegar, esse é o caso base.

// 02

As duas partes obrigatórias

Toda função recursiva correta precisa ter exatamente estas duas partes. Se faltar qualquer uma, o programa quebra.

1

Caso base — a condição de parada

Uma situação onde a função não chama a si mesma e retorna diretamente um valor. Sem ela, a recursão nunca termina.

2

Chamada recursiva — com argumento menor

A função chama a si mesma com um argumento que se aproxima do caso base a cada passo. Se não diminuir, nunca chega ao caso base.

fatorial em C — partes identificadas
int Fatorial(int x)
{
    if (x <= 1)                    /* ← CASO BASE: para aqui, sem chamada */
    {
        return 1;
    }
    else
    {
        return x * Fatorial(x - 1); /* ← CHAMADA RECURSIVA (x-1 é menor!) */
    }
}
Sempre que escrever uma função recursiva, pergunte: "o argumento da chamada recursiva está ficando mais próximo do caso base a cada vez?". Se a resposta for não, você tem um bug.
// 03

Como a pilha de chamadas funciona

analogia

Imagine uma pilha de pratos. Cada chamada recursiva coloca um prato novo no topo. Quando uma chamada termina com return, o prato do topo é retirado e o resultado vai para o prato abaixo. No final, sobra só um prato, com o resultado.

A cada chamada, o C reserva um frame na memória com as variáveis daquela chamada. Veja o que acontece com Fatorial(4):

── DESCIDA (empilhando) ────────────────────────────────── Fatorial(4) chamada → aguarda resultado de Fatorial(3) ┌─────────────────────────────────┐ │ frame: x=4 aguardando 4 × ... │ ← topo ├─────────────────────────────────┤ │ frame: x=3 aguardando 3 × ... │ ├─────────────────────────────────┤ │ frame: x=2 aguardando 2 × ... │ ├─────────────────────────────────┤ │ frame: x=0 ou 1 → return 1 ★ │ ← CASO BASE atinge aqui └─────────────────────────────────┘ ── SUBIDA (desempilhando) ──────────────────────────────── Fatorial(1) retorna 1 → Fatorial(2) calcula 2 × 1 = 2 Fatorial(2) retorna 2 → Fatorial(3) calcula 3 × 2 = 6 Fatorial(3) retorna 6 → Fatorial(4) calcula 4 × 6 = 24 Fatorial(4) retorna 24 → resultado final = 24 ✓

✔ Cada frame tem suas próprias variáveis — o x de Fatorial(3) é diferente do de Fatorial(4).

✔ No return, o frame é descartado e o valor vai para quem chamou.

✔ A pilha tem tamanho limitado. Recursões profundas demais causam Stack Overflow.

Recursão infinita — o erro mais comum

Há dois jeitos clássicos de criar uma recursão que nunca termina. Os dois causam Stack Overflow em tempo de execução.

❌ Erro 1 — argumento não diminui
int Fatorial(int x) {
  if (x <= 1)
    return 1;
  return x * Fatorial(x);
  /* deveria ser x-1 ! */
}
❌ Erro 2 — sem caso base
int LoopInfinito(int x) {
  return LoopInfinito(x);
  /* nunca para —
     sem condição de saída */
}
Stack Overflow não é erro de compilação! O código compila sem problemas. O erro só aparece em tempo de execução, quando a pilha enche. Sempre teste com valores pequenos antes.

Checklist antes de rodar sua função recursiva

☐  A função tem um caso base claramente definido?

☐  O argumento da chamada recursiva é menor/mais simples que o atual?

☐  O caso base é atingível para todos os valores de entrada válidos?

☐  Testei com o menor valor possível (ex: n = 1)?

// 06

Recursivo vs. Iterativo — quando usar cada um

Todo problema recursivo pode ser resolvido iterativamente (com while/for), e vice-versa. A questão é qual é mais adequado:

✦ Versão Recursiva
int Fatorial(int x) {
  if (x <= 1)
    return 1;
  return x * Fatorial(x-1);
}
◈ Versão Iterativa
int Fat(int n) {
  int f = 1;
  while (n > 0) {
    f = f * n;
    n = n - 1;
  }
  return f;
}
CritérioRecursivo ✦Iterativo ◈
Legibilidade Próximo da definição matemática — mais elegante Pode ficar verboso para problemas naturalmente recursivos
Desempenho Overhead de chamada de função; usa mais memória (pilha) Geralmente mais rápido; usa menos memória
Quando usar Árvores, grafos, divisão-e-conquista, backtracking, fractais Operações simples: soma acumulada, busca linear, fatorial
Risco Stack Overflow para entradas muito grandes Loop infinito se condição de parada errada

Regra prática: use recursividade quando a implementação iterativa precisaria de uma pilha explícita para funcionar. Nesses casos, a recursão usa a pilha do sistema de graça e o código fica muito mais simples. Exemplos: Quicksort, caminhamento em árvores, backtracking.

Mais exemplos

Potência recursiva — O(n)

Calcular base^exp: caso base é expoente 0 (qualquer número elevado a 0 é 1), e reduzimos o expoente em 1 a cada chamada.

potência recursiva
int pot(int base, int exp)
{
    if (!exp)                              /* !exp é true quando exp == 0 */
        return 1;                         /* CASO BASE: base^0 = 1       */

    return (base * pot(base, exp - 1));  /* base × base^(exp-1)         */
}

/* Trace de pot(2, 4):
   pot(2,4) = 2 × pot(2,3)
            = 2 × 2 × pot(2,2)
            = 2 × 2 × 2 × pot(2,1)
            = 2 × 2 × 2 × 2 × pot(2,0)
            = 2 × 2 × 2 × 2 × 1  =  16  ✓  */
!exp é forma compacta de exp == 0. Em C, 0 é falso, então !0 é verdadeiro. Só ativa quando expoente é zero.

Fractais — recursão gerando arte

A função estrela divide um quadrado em 4 quadrantes menores e chama a si mesma para cada um, até o tamanho r chegar a zero:

fractal quadrado (exemplo da aula)
void estrela(int x, int y, int r)
{
    if (r > 0)                      /* CASO BASE: r == 0 → para   */
    {
        estrela(x-r, y+r, r/2);  /* quadrante superior esquerdo */
        estrela(x+r, y+r, r/2);  /* quadrante superior direito  */
        estrela(x-r, y-r, r/2);  /* quadrante inferior esquerdo */
        estrela(x+r, y-r, r/2);  /* quadrante inferior direito  */
        box(x, y, r);              /* desenha o quadrado atual    */
    }
}

Aqui a função faz 4 chamadas recursivas por nível, mas r é dividido por 2 a cada vez, então chega a 0 rapidamente. Isso gera um padrão fractal com código mínimo.

Régua — trace de execução (regua(0, 8, 3))

A função divide o intervalo ao meio recursivamente, marcando traços em alturas decrescentes. Observe que o lado esquerdo é explorado completamente antes de prosseguir para o direito:

regua(0, 8, 3) ├── marca(4, 3) ← ponto central, altura 3 ├── regua(0, 4, 2) ← metade esquerda │ ├── marca(2, 2) │ ├── regua(0, 2, 1) │ │ ├── marca(1, 1) │ │ ├── regua(0,1,0) ← PARA (h=0, caso base) │ │ └── regua(1,2,0) ← PARA │ └── regua(2, 4, 1) │ ├── marca(3, 1) │ ├── regua(2,3,0) ← PARA │ └── regua(3,4,0) ← PARA └── regua(4, 8, 2) ← metade direita (espelha esquerda)

Exercícios de fixação

Quiz rápido — clique na resposta correta

1. Qual é a função do "caso base" em uma função recursiva?

✔ Correto! O caso base é a condição que encerra a recursão, retornando um valor diretamente sem realizar uma nova chamada.
✘ O caso base é a condição de parada — retorna um valor direto sem fazer nova chamada recursiva.

2. O que acontece se uma função recursiva não tiver caso base?

✔ Correto! O compilador não detecta esse erro. A pilha cresce indefinidamente até estourar em runtime.
✘ Esse erro não aparece na compilação. A pilha cresce até o Stack Overflow em tempo de execução.

3. Analise: int f(int n) { return n * f(n); }. Qual o problema?

✔ Exato! f(n) chama f(n) eternamente. Precisaria ser f(n-1) com um caso base como if(n==0) return 1.
✘ O problema: f(n) chama f(n) — o argumento não diminui, nunca atingindo o caso base.

4. Quando a recursividade é preferível à solução iterativa?

✔ Certo! Em árvores, grafos, quicksort e backtracking, a recursão é muito mais natural e limpa que a alternativa iterativa.
✘ Recursividade brilha em problemas naturalmente recursivos: árvores, grafos, divisão-e-conquista, fractais.

5. Em pot(2, 4), quantas vezes a função é chamada ao total (incluindo a inicial)?

✔ Correto! pot(2,4) → pot(2,3) → pot(2,2) → pot(2,1) → pot(2,0). São 5 chamadas: exp = 4, 3, 2, 1, 0.
✘ Trace: pot(2,4)→pot(2,3)→pot(2,2)→pot(2,1)→pot(2,0). São 5 chamadas no total (exp de 4 até 0).

Desafios para programar

Desafio 1 — Soma dos naturais
Escreva int soma(int n) recursiva que retorna 1+2+…+n. Dica: soma(n) = n + soma(n-1), com soma(0) = 0.

Desafio 2 — Fibonacci
Implemente fib(n) recursivo: fib(0)=0, fib(1)=1, fib(n)=fib(n-1)+fib(n-2). Depois teste com n=40 e observe a lentidão. Por que acontece isso?

Desafio 3 — Contagem regressiva e progressiva
Escreva void contagem(int n) que imprime de n até 0. Depois mova o printf para depois da chamada recursiva — o que muda? Por quê?

Desafio 4 — Máximo Divisor Comum (MDC)
Implemente o algoritmo de Euclides recursivo: mdc(a, 0) = a e mdc(a, b) = mdc(b, a % b). É um dos algoritmos recursivos mais elegantes da história.
